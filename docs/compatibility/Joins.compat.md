# Joins Compatibility

This is the compatibility companion to the [API reference](../api/Joins.api.md). It records Structure contracts alongside the corresponding PySpark API forms and examples for read-through. The shared baseline is the public PySpark 3.5.x/4.0.x intersection; Connect is claimed only where runtime evidence is recorded.

## Join and match helpers

| Structure API | PySpark parity | Example | PySpark 3 | PySpark 4 | Details |
| --- | --- | --- | --- | --- | --- |
| `lookup_join(...)` | `DataFrame.join` | `lookup_join(on=o.customer_id == c.id)` | yes | yes | `lookup_join(...)` enriches the current relation and defaults to `"left"`. |
| `exists(...)` | left-semi join | `where(exists(on=o.customer_id == c.id))` | yes | yes | `exists(...)` and `not_exists(...)` filter current rows without exposing right-side fields. |
| `not_exists(...)` | left-anti join | `where(not_exists(on=o.customer_id == c.id))` | yes | yes | `exists(...)` and `not_exists(...)` filter current rows without exposing right-side fields. |
| `rowset_join(...)` | `DataFrame.join` | `rowset_join(c, on=o.customer_id == c.id)` | yes | yes | `left_join(...)`, `inner_join(...)`, `right_join(...)`, `full_join(...)`, and `cross_join(...)` are shortcuts over `rowset_join(...)`. |
| `left_join(...)` | `join` | `left_join(on=o.customer_id == c.id)` | yes | yes | `left_join(...)`, `inner_join(...)`, `right_join(...)`, `full_join(...)`, and `cross_join(...)` are shortcuts over `rowset_join(...)`. Same-name key shorthand is supported: `left_join(on="customer_id")` and `inner_join(on=["tenant_id", "order_id"])`. |
| `inner_join(...)` | `join` | `inner_join(on=o.customer_id == c.id)` | yes | yes | `left_join(...)`, `inner_join(...)`, `right_join(...)`, `full_join(...)`, and `cross_join(...)` are shortcuts over `rowset_join(...)`. Same-name key shorthand is supported: `left_join(on="customer_id")` and `inner_join(on=["tenant_id", "order_id"])`. |
| `right_join(...)` | `join` | `right_join(on=o.customer_id == c.id)` | yes | yes | `left_join(...)`, `inner_join(...)`, `right_join(...)`, `full_join(...)`, and `cross_join(...)` are shortcuts over `rowset_join(...)`. |
| `full_join(...)` | `join` | `full_join(on=o.customer_id == c.id)` | yes | yes | `left_join(...)`, `inner_join(...)`, `right_join(...)`, `full_join(...)`, and `cross_join(...)` are shortcuts over `rowset_join(...)`. |
| `cross_join(...)` | `crossJoin` | `cross_join(calendar, allow_cartesian=True)` | yes | yes | `left_join(...)`, `inner_join(...)`, `right_join(...)`, `full_join(...)`, and `cross_join(...)` are shortcuts over `rowset_join(...)`. Cross joins require `allow_cartesian=True` and do not accept `on=`. `param_join(relation)` is the parameter-style shortcut for `cross_join(relation, allow_cartesian=True)`; it asserts singleton cardinality for batch steps and skips that assertion for streaming steps. Use `cross_join(...)` when multiple right-side rows are intentional. |
| `param_join(...)` | `crossJoin` | `param_join(policy)` | yes | yes | Cross joins require `allow_cartesian=True` and do not accept `on=`. `param_join(relation)` is the parameter-style shortcut for `cross_join(relation, allow_cartesian=True)`; it asserts singleton cardinality for batch steps and skips that assertion for streaming steps. Use `cross_join(...)` when multiple right-side rows are intentional. |
| `relation_alias(...)` | DataFrame alias | `historical = relation_alias(customer, name="historical_customer")` | yes | yes | `relation_alias(...)` creates a named typed occurrence of the current rowset or an unjoined relation for a self join. The name must be a unique non-empty Python identifier within the step; aliasing does not execute or duplicate data. |
| `temporal_one(...)` | Temporal join | `temporal_one(on=o.id == p.id, at=o.at, valid_from=p.from_, valid_to=p.to)` | yes | yes | `temporal_one(...)` selects one right row valid at `at`; its normal interval is closed-open. |
| `as_of_one(...)` | As-of match | `as_of_one(on=o.id == r.id, left_time=o.at, right_time=r.at)` | yes | yes | `as_of_one(...)` supports backward, forward, and nearest directions. Nearest matching ignores null time candidates, ranks by absolute distance, and fails equidistant best matches when `ties="error"`. |
| `direction=` | Direction | `as_of_one(on=o.id == r.id, left_time=o.at, right_time=r.at, direction="nearest")` | yes | yes | Chooses backward (latest prior), forward (earliest following), or nearest time matching; nearest ties follow `ties=`. |
| `overlaps=` | Overlap policy | `temporal_one(on=j, at=t, valid_from=f, valid_to=e, overlaps="error")` | yes | yes | Controls multiple valid right-side matches: reject ambiguity with `"error"` or select according to the documented deterministic policy. |
| `ties=` | Selection policy | `as_of_one(on=o.id == r.id, left_time=o.at, right_time=r.at, ties="error")` | yes | yes | For equally ranked as-of candidates, `"error"` fails rather than choosing a row arbitrarily. |
| `how=` | `how` | `rowset_join(c, on=o.customer_id == c.id, how="left")` | yes | yes | Selects the relational join type; right/full joins make fields from the opposite side nullable in the declared output schema. |
| `hint=` | DataFrame hint | `lookup_join(on=o.customer_id == c.id, hint="broadcast")` | yes | yes | Analogous to PySpark `DataFrame.hint(...)`: attaches a planner hint to the lookup relation, but does not guarantee Spark will use a particular physical plan. |
| `strategy=` | Join hint | `inner_join(on=o.id == c.id, strategy="shuffle_hash")` | yes | yes | Requests a Spark join strategy hint (for example, shuffle hash); the optimizer remains responsible for the physical plan. |
| `JoinDedupe.latest_by(...)` | `row_number` | `JoinDedupe.latest_by(c.at)` | yes | yes | Keeps the highest ordered right-side row within each join key before matching; ordering and tie handling are explicit. |
| `JoinDedupe.earliest_by(...)` | `row_number` | `JoinDedupe.earliest_by(c.at)` | yes | yes | Keeps the lowest ordered right-side row within each join key before matching; ordering and tie handling are explicit. |
