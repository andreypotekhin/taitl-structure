# Version 3

Version 3 completes Structure's PySpark parity and streaming-transformation release. The public surface remains typed,
symbolic, capability-checked, and readable when generated; it does not take ownership of a streaming query's lifecycle.

## What’s Included

- Column and SQL helpers for string matching, typed casts, null ordering, date/time work, numeric work, and predicates.
- Safer joins: using-key forms, explicit Cartesian acknowledgement, strategy directives, forward as-of matching, and
  clearer right/full join diagnostics.
- Explicit grouping sets, `having(...)`, aggregate windows, and consistent multi-key window ordering.
- Collection helpers for membership, construction, set operations, lookup, and map concatenation.
- Compiler-visible watermarks, stateful streaming dedupe, and streaming aggregation admission checks.
- Source-ordered `@raw` methods, explicit `@step(...)` bindings, and variadic `where(...)` filters.

## Streaming Boundary

Structure transforms caller-supplied streaming DataFrames but deliberately does not generate or own sources, sinks,
triggers, checkpoints, output modes, or query lifecycle. Use the normal Spark APIs for those operational choices.

## Examples And Verification

The [orders example](../examples/orders) and [v3 orders testing model](../res/testing/model/v3/Readme.md) show the
feature families in one pipeline. The model compiles without a live Spark runtime and is covered by
`tests/specifications/v3-fixtures`.

Incremental project compilation and cache diagnostics remain future work with no assigned version. The remaining
admitted API work is listed as `planned` in [API Gaps](dev/Gaps.md); each item will receive its own implementation plan.
