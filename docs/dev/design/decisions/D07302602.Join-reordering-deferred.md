# Decision: Defer Structure-Level Join Reordering

## Status

Accepted on 2026-07-30.

## Context

Structure emits an ordered logical recipe and its generated PySpark and explain report preserve that authored order.
The join surface includes lookup and temporal selected-row joins, semi and anti filters, general rowset joins, and
streaming-compatible joins. These forms are not freely interchangeable: order can affect row multiplication,
nullability, right-side scope availability, validation timing, hook behavior, and traceability.

Spark is the correct owner of physical join optimization. It has deployment-specific catalog and data-source
statistics, partitioning information, configured broadcast thresholds, and runtime statistics through Adaptive Query
Execution. A Structure cost model would duplicate incomplete, environment-dependent information while making the
logical recipe less predictable.

## Decision

Structure will not add a public `join_order(...)` API or a Structure-level cost-based join planner at this time.
It will retain source-authored join order in IR, generated PySpark, online execution, and explain output. Existing
per-join hints and strategies remain explicit local directives; they are not a cost-based reordering interface.

Performance guidance should direct users to maintain accurate Spark statistics, inspect `EXPLAIN COST`, and configure
Adaptive Query Execution and join hints in their deployment where appropriate.

## Reconsideration Boundary

Revisit this decision only with production evidence that Spark cannot adequately optimize a common Structure workload.
The first possible follow-up is an opt-in, explainable advisor rather than an automatic rewrite. It may inspect only a
contiguous batch chain of inner equi-joins with no intervening hooks, validations, dedupe, set operations, ordering,
limits, projections, or predicates that read an earlier joined scope. It must show the authored and suggested order,
and fall back to source order whenever equivalence is uncertain.

No logical rewrite should be considered until that advisor has demonstrated a useful, safe case and the compiler can
prove the required dependency and cardinality constraints.

## Consequences

Structure retains a simple, reviewable semantic and traceability contract. It avoids competing with Spark's
statistics-aware physical optimizer and keeps the current [join reordering design gate](../../specifications/V9ApiCatalogDesignGatedFeatures.md#join-reordering)
open for a deliberately narrow future exploration.
