### D06182605 Versioning and Compatibility Policy

Challenges.md point C19, "Versioning and Compatibility Policy Are Missing", is resolved by adopting a public
compatibility policy in [Compatibility.md](../../../Compatibility.md) and a development contract in
[CompatibilityPolicy.md](../../specifications/CompatibilityPolicy.md).

v.1 supports Python 3.11 and newer, targets PySpark 3.5.x and 4.0.x by default, avoids a hard Airflow dependency, and
treats Linux as the runtime target. The default execution mode is `execution_mode = "online"`, and the default PySpark
target is `target_profile = ">=3.5,<4.1"`.

Structure follows semantic versioning after 1.0. Online execution is the default runtime surface. Generated PySpark is
optional compiler output and should carry a compact version header naming the Structure generator version and configured
PySpark target when emitted. Compiler traceability metadata has versioned provenance and static dataflow schemas, and config
schema changes follow the same compatibility discipline as other public contracts.

Spark Connect was originally scheduled for v4. Sprint 09 now promotes completed batch support because it can stay
inside the existing PySpark target boundary without changing public DSL syntax, generated class construction,
`run(...)` signatures, streaming orchestration semantics, or generated-code reviewability. Streaming and storage-write
ownership remain outside that support claim.
