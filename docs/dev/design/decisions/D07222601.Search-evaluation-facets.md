### D07222601 Search Evaluation Facets

The Search example separates relevance quality from observed user behavior. Search results are useful only when they
both retrieve documents that answer a query and produce a satisfactory served experience, but those are different
claims and require different evidence.

#### Decision

Provide two document-search evaluation facets below `examples/search/transforms/evaluation/search_docs/`, with public
entry points in `examples/search/transforms/evaluate.py`:

- `EvaluateDocumentRankingQuality` is the offline quality anchor. It evaluates one ranked result batch against caller-supplied
  `DocumentRelevanceJudgment` rows.
- `EvaluateDocumentSearchBehavior` is the automated daily behavior monitor. It evaluates the actual request,
  impression, and click events emitted by the serving system.

The facets share a one-row `EvaluationBatch` containing a UTC-aligned daily `TimeWindow`, but they do not turn one
another's inputs into substitute evidence.

The implementation separates evidence models as well: `schemas/evaluation/batch.py` owns the shared batch contract,
`schemas/evaluation/judged_quality.py` owns judged-quality contracts, and `schemas/evaluation/behavior.py` owns
observed-behavior contracts. The `schemas.evaluation` package re-exports these types as the stable convenient import
surface. The judged evaluator lives in `search_docs/judged_quality/`; behavior lives in `search_docs/behavior/`.

#### Judged quality

`DocumentRelevanceJudgment` uses four grades: 0 for not relevant, 1 for related, 2 for relevant, and 3 for ideal.
Grades 2 and 3 are binary relevant for Precision, judged Recall, Success@N, and reciprocal rank. All four grades
contribute to nDCG@5, nDCG@10, and nDCG@15. Accuracy@N is intentionally absent because the previously proposed
rank-position definition is identical to Precision@N. ERR is deferred; the grade model can support it later without
changing the input contract.

The caller creates a judgment pool from the deduplicated top candidates of every ranking run under comparison and
any known-answer documents. The evaluator scores one run at a time against that common pool. A returned document
without a judgment makes the affected metric unavailable rather than implicitly nonrelevant. Short result lists retain
their missing ranks as zero gain. This avoids both hiding retrieval failures and penalizing a ranker merely because it
returned a novel, unjudged document.

Click data is not relevance truth. A click depends on what was shown, where it appeared, interface details, and the
user's current intent. Click-derived scores can support ranking feedback and behavior monitoring, but they do not
establish corpus recall, offline MRR, or judged precision.

#### Request-aware behavior

Every serving attempt emits a required `SearchRequest`, including a no-result attempt. A request has an immutable ID,
request timestamp, raw query, and caller-owned ranking version. Every `Impression` refers to the request through
`search_request_id`, while retaining its own document, displayed position, query, and examination propensity. The
query remains on the impression because the existing streaming feedback aggregation consumes impressions without a
request join.

`Click` continues to refer to an impression. Behavior attribution accepts only clicks between display time and 24 hours
after display. A long click is a click with at least ten seconds dwell. The behavior facet publishes per-request facts
and a daily summary per ranking version: zero-result, no-click, and no-long-click counts; click and long-click
outcomes; first click and first long-click rank; reciprocal first-long-click rank; and inverse-propensity-weighted
long-click and dwell-credit exposure rates. These are explicitly observed-satisfaction metrics, not relevance metrics.

The behavior data flow must use ordinary Structure lanes and step methods: select daily requests, select linked
impressions, attribute clicks, aggregate per-impression engagement, preserve zero-result requests in per-request
aggregation, aggregate exposure weights, and publish daily version summaries. Raw hooks are not an acceptable
substitute for this decomposed transform flow.

#### Deferred alternatives

Experiment comparison, interleaving, counterfactual policy evaluation, and session reformulation metrics are deferred.
They need facts not present in this contract: experiment arm and result ownership for interleaving, randomized policy
selection probabilities for counterfactual estimates, and stable session identity for reformulations. They must be
added as separate facets rather than being inferred from daily click aggregates.

The source fixtures in `examples/fixtures/search/` include requests, impressions, clicks, and judgments. They cover an
empty request, short and long clicks, a click outside the attribution interval, multiple ranking versions, and graded
judgments. They are the canonical reusable model inputs for evaluator integration tests.
