### S07132601 Mirrored Generated Transform Methods

Add an opt-in generated-code layout that makes a generated transform read like its source transform. The
`"mirror_methods"` option produces source-named generated step and hook-boundary methods while keeping the compiler's
flattened `PySparkExecutionPlan` as the sole semantic authority. The independently combinable `"embed_exprs"`,
`"embed_hooks"`, and `"embed_udfs"` options decide whether corresponding source members are represented in the
generated class. This improves code review and debugger navigation without changing DataFrame semantics.

- Extend the shared `generated_code_options` setting rather than creating a second generation-mode setting. It is a
  canonical unique set whose allowed values include `mirror_methods`, `embed_exprs`, `embed_hooks`, and `embed_udfs`.
  Default to no options for compatibility. Thread the option set through `StructureConfig`, `CompilerOptions`,
  artifact fingerprints, every renderer entry point, configuration documentation, and generated-mode stale checks. It
  belongs to rendering configuration, not the backend-neutral execution plan.
- In mirror mode, make named DataFrame inputs and intermediate frames generated-instance fields. The generated
  constructor receives `spark`, `ctx`, and every declared input DataFrame; zero-argument `run()` resets current lanes
  from those original-input fields, validates inputs, invokes source-named methods in compiler-plan order, applies final
  output rendering and validation, then returns `TransformResult`. The generated runtime runner constructs
  `Generated(spark=..., ctx=..., **inputs).run()`. Each generated object represents one batch; batch callers create a
  separate instance for every input set.
- Render compiler-visible schema-returning source methods as generated methods using their
  `StepPlan.origin.member_name`.
  A method reads and writes the lane fields required by its recipe instead of accepting a `frames` dictionary or a
  DataFrame parameter. Keep final output validation in `run()` when it is a compiler-synthesized output boundary rather
  than a source method. Mangle only compiler-created frame names that are not Python identifiers, such as pipeline
  stage frames, and retain an explicit deterministic frame-name-to-field map for traceability.
- Keep expanded `@special(type="expr")` output inline by default. Let `embed_exprs` independently render named helpers,
  preserving special-call
  identity in expression IR, capture each helper body once against symbolic parameters, and render a generated
  `@staticmethod` such as `clean_id(value)` with calls written as `self.clean_id(...)`. The static method is essential:
  source special functions such as `def clean_id(value)` do not accept `self`. Keep the expanded expression tree as
  semantic authority; the named helper is only a rendering abstraction.
- Let `embed_hooks` choose raw-hook rendering independently of the method set. Without it, generate a source-named
  mirror wrapper that delegates to the exact owner-qualified source hook, for example `remove_negative_totals()` calling
  `self._impl.remove_negative_totals(...)`. With it, copy the validated raw Python method body into the generated class
  using the agreed AST-based embedding contract. In both cases, the generated method reads and writes current or
  original-input fields according to recorded hook sources. The hook remains an opaque compiler boundary.
- Let `embed_udfs` use the corresponding source-embedding contract for `@special(type="udf")`. `embed_hooks` alone
  must still preserve the existing diagnostic for a source-backed UDF. When both embedding options apply, generated
  source can omit `_impl`; otherwise retain `_impl` exactly for the source members that require it.
- Preserve owner-qualified dispatch and unique names for inheritance. A parent and child may both contribute methods
  with the same Python name; generated parent classes or deterministic protected owner-qualified wrappers must avoid
  accidental late dispatch. The existing `TransformMemberOrigin` metadata is sufficient for steps and hooks; special
  expressions need equivalent origin metadata.
- Define instance lifecycle explicitly. A mirror-mode object represents one input batch. Its input and intermediate
  DataFrame fields are isolated from every other instance, so callers process concurrent or sequential batches with one
  generated object per input set.
- Add syntax, snapshot, and generated-vs-online parity coverage for `EnrichOrders`, including an expression helper,
  a leading and trailing hook, multi-input raw-hook access, caching, multiple outputs, inherited-owner hooks, and a
  pipeline frame name that requires mangling. Confirm that default inline output is byte-stable and that generated mode
  executes both layouts through the runtime runner.

The representative mirror output should have this shape:

    class EnrichOrdersGenerated:
        def __init__(self, *, spark, ctx=None, orders, customers):
            self.spark = spark
            self.ctx = ctx
            self._impl = EnrichOrders()
            self._input_orders = orders
            self._input_customers = customers

        @staticmethod
        def clean_id(value):
            return F.lower(F.trim(value))

        def normalize(self):
            orders = self.orders.alias("order_raw")
            self.orders = orders.select(self.clean_id(F.col("order_raw.id")).alias("id"))

        def remove_negative_totals(self):
            self.orders = self._impl.remove_negative_totals(
                orders=self.orders, spark=self.spark, ctx=self.ctx
            )

        def run(self):
            self.orders = self._input_orders
            self.customers = self._input_customers
            assert_schema(self.orders, ORDER_RAW_SCHEMA, name="OrderRaw", mode="strict")
            self.normalize()
            self.remove_negative_totals()
            return TransformResult({"published": self.published}, single=True, schema={...})

Only `embed_hooks` and `embed_udfs` copy Python source. Expression helpers are compiler-visible and need IR provenance
to render as source-named methods under `embed_exprs`; raw hooks and UDFs retain their explicit opaque-boundary
contracts even when their runtime bodies are embedded. This keeps generation deterministic and preserves
online/generated semantic parity.
