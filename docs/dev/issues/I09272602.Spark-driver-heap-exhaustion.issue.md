### I09272602 Spark Driver Heap Exhaustion From Expanded Query Plans

Status: resolved
Scope: PySpark driver memory during logical query-plan construction and analysis
Versions: Structure 0.1.0, Python 3.11/3.12, PySpark 3.5/4.0, Spark Connect 4.0

Reproduction:

Run the standalone two-row reproducer with a 1 GiB PySpark driver:

    docker compose --env-file infra/compose/.env \
      -f infra/compose/docker-compose.yaml run --rm --entrypoint bash \
      -e STRUCTURE_SPARK_DRIVER_MEMORY=1g structure-integration-pyspark35 \
      -lc "python /workspace/docs/troubleshooting/memory/spark_driver_heap_oom.py --rounds 7"

Observed output:

A tiny input can exhaust the Spark driver while Spark builds or analyzes the query plan. The baseline reverse-and-union
shape reached `java.lang.OutOfMemoryError: Java heap space` at round seven. Spark Connect and ordinary PySpark runs
also exposed long construction times when an already-expanded DataFrame was reused across joins, unions, assertions,
or reranking branches.

Expected behavior:

The library should make the difference between physical reuse and a true query-plan boundary clear, provide an explicit
way to cut an expanded plan, preserve online/generated parity, and warn before repeated reuse is likely to cause driver
time or memory problems.

Resolution:

The OOM root cause and remediation are implemented and documented:

- Added compiler-visible `persist()`, `cache()`, `unpersist()`, `checkpoint()`, and
  `local_checkpoint()` operations with generated/online parity and capability checks.
- Added a safe same-source projection-union fusion that reduces one repeated branch without claiming to bound the
  remaining plan.
- Added default-on `PYSPARK-W2701` through `PYSPARK-W2704` diagnostics with plain-language remedies and
  project/transform suppression.
- Documented that `checkpoint()` and `local_checkpoint()` cut the query plan, while aliases, temporary views,
  `cache()`, and `persist()` do not. Search-specific materialization remains conditional and is tracked separately.
- Verified the standalone checkpoint boundary, fused reduction, generated/online parity, and focused regression suite.
