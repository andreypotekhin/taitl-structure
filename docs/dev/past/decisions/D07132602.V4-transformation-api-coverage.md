### D07132602 Transformation API Coverage

Prioritize PySpark transformation API coverage over backend expansion, compile-cache work, and streaming lifecycle
ownership. The release covers caller-supplied DataFrame transformations only: typed expressions, nested values,
relational transformations, joins, aggregations, windows, and any row-expanding feature that receives an explicit
schema-and-cardinality contract.

The release's governing artifact is a checked transformation coverage catalog for the PySpark 3.5.x and 4.0.x target
intersection. Each relevant API is marked supported, scheduled, deferred, or unsupported, with its Structure spelling,
target capability, semantic differences, and test/documentation evidence. This creates an honest answer before full
parity is reached and prevents a PySpark feature from becoming an accidental gap.

Release also includes a caller-owned streaming-migration slice: session-window aggregation, bounded stream-stream
outer and semi joins, and stream-static left-semi joins. Each operation must expose its watermark, event-time-bound,
state, late-data, and caller-required output-mode semantics to the compiler. It must have live streaming parity
evidence; Structure will not infer policy or start a query. Sprint 18 and
[SparkStreaming.md](../../design/SparkStreaming.md) makes this release commitment concrete.

Loading, storage, catalog/table management, actions, streaming sources/sinks/triggers/checkpoints/output-mode
application/query lifecycle, raw SQL, raw Spark objects, UDF/UDTF execution, and alternative-backend work remain
outside this release. Structure keeps its typed symbolic boundary; it will not become a wholesale PySpark wrapper.
