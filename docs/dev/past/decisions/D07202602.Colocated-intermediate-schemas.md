# D07202602 Accept Colocated Intermediate Schemas

Dedicated model schema files remain the recommended Structure source layout.
They make schema contracts visible, reusable, and easy to navigate across
transforms.

Structure also accepts an intermediate `Schema` declared at module scope in the
same Python file as the transform that uses it. This supports projects that treat
the shape as a short-lived implementation detail. It has ordinary schema
semantics: Structure discovers it, validates it, emits its generated Spark schema,
and includes it in generated documentation and traceability.

The accepted form is module-level colocation, not a schema class nested inside a
`Transform`. Nesting has no distinct runtime benefit but would require special
discovery, annotation resolution, generated naming, and inheritance rules. It is
rejected with `DSL-E0402`; move the schema to module scope, preferably to a model
schema file when it is reusable.
