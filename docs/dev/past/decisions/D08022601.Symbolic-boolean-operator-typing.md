# Decision: Preserve Symbolic Boolean Expressions in IDE-Compatible Operators

## Status

Accepted on 2026-08-02.

## Context

Structure's PySpark DSL builds compiler-visible expression trees instead of evaluating Python booleans. Helpers such as
`event_time_between(...)` therefore return `Expression` values whose embedded Structure type is `BooleanType`.

When a step combines a schema-field comparison with such a helper, an IDE may statically view the comparison as a Python
`bool` while viewing the helper result as `Expression`. Without reflected boolean operators, the IDE reports an
unexpected `Expression` operand even though symbolic execution supplies expressions for both operands.

## Decision

Keep symbolic boolean helpers, comparisons, and predicates typed as `Expression`. Add reflected `__rand__` and `__ror__`
to `Expression`, preserving authored operand order and the existing boolean type and nullability checks.

Use `~expression` for symbolic negation. Python `not` remains unsupported because it evaluates truthiness instead of
building a symbolic expression tree.

## Consequences

IDE and type-checker analysis accepts boolean composition where a statically inferred Python boolean is on the left, while
the compiler and runtime retain the same expression IR and SQL three-valued null semantics. The public return type of
`event_time_between(...)` remains truthful and does not become Python `bool`.
