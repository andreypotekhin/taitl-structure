This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and

## Purpose / Big Picture

v2 is the release that makes Structure useful for mainstream analytical batch pipelines. After this plan is complete,
users can write typed analytical transforms with aggregations, joins, dedupe, windows, higher-order collection helpers,
explicit optimization hints, rich explain output, generated documentation, test helpers, and incremental compile
support without leaving the compiler-visible DSL. They can see it working by reading `docs/QuickRef.md`, running the
orders examples, running `structure explain` on an analytical transform, and running `make build`.

The immediate Sprint 08 wrap-up is deterministic keyed dedupe shortcuts and closeout documentation. The rest of the
plan carries v2 through Sprint 09 and Sprint 10 so the remaining designs, specifications, user stories, code examples,
public reference pages, tests, and implementation slices are not left implicit.

## Decision Log

- Decision: Keep deterministic keyed dedupe shortcuts as the final Sprint 08 implementation item, rather than moving
  them to Sprint 09.
  Rationale: They are adjacent to `distinct()`, `drop_duplicates(...)`, `latest_by(...)`, and `earliest_by(...)`; users
  expect dedupe ergonomics to close with the rest of analytical windows.
  Date/Author: 2026-07-04 / Codex.
- Decision: Treat the completed Spark Connect parity gate as the first slice, then use Sprint 09 to promote completed
  batch features only after live online/generated runtime evidence exists.
  Rationale: Static generated-shape checks are useful but insufficient for a support claim. The public DSL and generated
  class API still must not change, and streaming/storage ownership remains out of scope.
  Date/Author: 2026-07-05 / Codex.
- Decision: Model Spark Connect exclusions as backend capability requirements, not ad hoc renderer checks.
  Rationale: Classic-only internals such as SparkContext, RDD access, JVM/Py4J access, and private classic fields
  should fail through `BACKEND-E2402` before online execution or generated output claims compatibility.
  Date/Author: 2026-07-05 / Codex.
- Decision: Public `docs/reference` pages must self-refer as references, not specifications.
  Rationale: Users need stable behavior reference material, not implementation acceptance criteria. Implementation
  specs live under `docs/dev/specifications`.
  Date/Author: 2026-07-04 / Codex.
- Decision: Implement keyed dedupe shortcuts as aliases over selected-row operations.
  Rationale: Users get dedupe-shaped API names while Structure keeps one deterministic row-selection contract,
  traceability model, streaming classification, and PySpark lowering path.
  Date/Author: 2026-07-04 / Codex.
- Decision: Schedule full PySpark rowset joins into Sprint 09 instead of v3.
  Rationale: Sprint 09 already owns join strategy directives and rich explain output, which are the same cross-cutting
  surfaces needed to make right, full, cross, non-equi, and disjunctive joins reviewable.
  Date/Author: 2026-07-05 / Codex.
- Decision: Use `rowset_join(...)` for right, full, cross, non-equi, and disjunctive joins.
  Rationale: These joins produce rowsets rather than lookup enrichment. A separate primitive keeps `lookup_join(...)` and
  `inner_join(...)` narrow and preserves clear cardinality diagnostics.
  Date/Author: 2026-07-05 / Codex.

## Context and Orientation

Structure is a Python library for typed, schema-returning data transforms. End users write `Structure` schemas and
`Transform` classes, then Structure compiles those methods into an intermediate representation and lowers that plan to
online or generated PySpark DataFrame operations. A "compiler-visible" helper is a DSL function whose behavior remains
visible to Structure and Spark, instead of hiding inside a Python hook or UDF.

Important code paths:

- `src/structure/app/dsl/model/transforms/reserved_v2.py` contains v2 public helper constructors such as
  `group_by(...)`, `latest_by(...)`, `drop_duplicates(...)`, window helpers, and rolling helpers.
- `src/structure/app/compiler/frontend/commands/CompileTransform.py` turns source methods into `TransformPlan` IR.
- `src/structure/app/compiler/ir/model/OperationPlan.py` and sibling model files define ordered operations and
  operation metadata.
- `src/structure/app/target/pyspark/logic/mapping` maps IR to PySpark execution recipes.
- `src/structure/app/target/pyspark/commands` renders generated PySpark source.
- `src/structure/app/runtime/execution/online` interprets the same recipes against live PySpark DataFrames.
- `src/structure/app/compiler/compileability/streaming_compatibility` classifies transforms as streaming-compatible,
  batch-only, or unknown.
- `src/structure/app/compiler/traceability/commands/BuildCompilerTraceability.py` records provenance and dataflow.

Important documentation paths:

## Public Reference Documentation Rule

Public `docs/reference/*.md` pages are not raw implementation specifications. When copying or synchronizing from
`docs/dev/specifications`, edit every public reference page with these rules:

Do not keep a first-section heading named `Purpose`. Let the introductory paragraph sit directly under the H1. That
first paragraph should be end-user oriented: what the concept is, when to use it, and what behavior Structure provides.

Self-refer as "this reference" or "this page", not "this specification". Link to other public references with
`reference/*.md` links from aggregate pages such as `docs/Reference.md` and relative `*.md` links inside
`docs/reference`.

Drop implementation details, acceptance criteria, test placement, internal checklists, and coding instructions. Keep
behavior, public API shape, diagnostics users can act on, examples, constraints, and compatibility notes.

Drop lowering explanations when the lowering is the same or obviously similar to a PySpark concept. Keep lowering notes
only when they clarify a Structure-specific guarantee, limitation, determinism rule, or portability warning.

Avoid old version framing where possible. v2 is nearing completion, so public references should describe current
behavior in present tense. Use future tense only for explicitly deferred features.

## Plan of Work

selected-row helpers already admitted. The public API does not let users accidentally choose arbitrary rows:
`dedupe_latest_by(...)` and `dedupe_earliest_by(...)` name keyed dedupe intent while reusing selected-row ranking
semantics rather than lowering to keyed `dropDuplicates(...)`.

Milestone 2 performs the public reference cleanup pass. Use the rules above to update `docs/reference` pages. Fix
`docs/Reference.md`, `docs/QuickRef.md`, diagnostic documentation links, and any error-message docs links that still
point to deleted `docs/specifications` paths. This is not just search-and-replace: each public reference needs a short
end-user introduction and no implementation checklist.

Milestone 3 starts Sprint 09 with Spark Connect support promotion. Follow
[P07052602.Spark-connect-full-batch-support.plan.md](P07052602.Spark-connect-full-batch-support.plan.md). Add tests or
matrix cases proving completed batch features work under the `pyspark` target variant `spark-connect` against a real
Spark Connect session, or fail with explicit classic-only diagnostics. The completed batch feature list includes
projections, filters, joins, analytical joins, aggregations, exact and subset dedupe, selected-row helpers, ranking,
lag/lead, rolling metrics, array/map higher-order helpers, hooks where they are variant-compatible, and generated-code
runtime boundaries.

Milestone 4 implements full PySpark rowset joins from
[P07052603.Full-pyspark-join-support.plan.md](P07052603.Full-pyspark-join-support.plan.md). Add `rowset_join(...)`,
right/full/cross joins, non-equi and disjunctive predicates, nullable-side output checks, backend capabilities, shared
PySpark recipes, traceability, explain output, streaming classification, fixtures, and parity tests.

Milestone 5 implements explicit optimization directives. Add source helpers for cache/persist, repartition/coalesce,
checkpoint, and join strategy directives. Add IR metadata, backend capabilities, generated and online recipe behavior,
traceability, explain summaries, QuickRef docs, reference docs, v2 fixture examples, and tests proving row and schema

Milestone 6 implements rich explain. Expand `structure explain` beyond compact operation names so a user can follow
field lineage through projections, filters, joins, aggregations, window projections, selected-row dedupe, exact and
subset dedupe, higher-order helpers, hooks, and optimization boundaries. Keep compact output as the default or provide
a clear expanded mode so routine output remains readable.

Milestone 7 completes Sprint 10 adoption tooling. Implement generated schema/transform documentation artifacts,
public pytest helpers for downstream projects, generated-code freshness and snapshot helpers, expected diagnostic
helpers, online/generated parity helpers, and `compile --changed-only` with cache invalidation diagnostics.

Milestone 8 closes v2. Review M7 milestones, backlog, sprint docs, user stories, public reference docs, examples,
diagnostic docs, and generated fixtures. Move completed planning and sprint files to `done` only when the repository
build and docs agree with the milestone status.
