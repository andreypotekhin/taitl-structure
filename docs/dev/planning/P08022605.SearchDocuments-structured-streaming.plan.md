# SearchDocuments Structured Streaming

This ExecPlan is the implementation roadmap for making the Search document ranker a ready-to-start, append-only
Structured Streaming transform. Structure continues to return DataFrame transformations; the caller owns sources,
watermarks, checkpoints, triggers, sinks, snapshot refreshes, and restart policy.

## Status

Design-gated and disabled for delivery. `examples.search.adoption.SEARCH_STREAMING_CONTRACTS_ENABLED` is intentionally
`False`, so SearchDocuments remains a batch transform while integration testing and delivery proceed. The query
event-time field, caller-owned run handoff, and bounded top-K metadata boundary remain documented for later re-enablement.
The no-Spark proving fixture, compiler blocker report, and explain metadata remain available without gating ordinary
Search compilation. The finite query-completion window, bounded top-K state, and stream-safe ranking path still require
compiler and live Spark work described below.

## Contract

- `SearchQuery.requested_at` is required and immutable.
- The matching `SearchRequest.requested_at` must equal the query timestamp.
- Query and request inputs are watermarked streaming relations with a caller-selected delay and finite completion
  window.
- Indexes, score caches, feedback signals, popularity, band fallback, and ranking policy are static snapshots for one
  run.
- Results are append-only: one final result set per query after the completion window closes; late/duplicate events are
  discarded by the declared watermark contract; emitted results are never revised.
- The existing deterministic score/document-ID tie-breakers remain mandatory.
- `examples.search.adoption.SearchDocumentsRunContract` validates the caller handoff: one immutable snapshot identity
  covers index, score cache, feedback, popularity, and policy; output is append-only; `requested_at` is the event-time
  field; snapshot refresh starts a new run; and downstream materialization is explicit.
- `examples.search.adoption.SearchFiniteTopKContract` validates the candidate-admission bound of 1,000 rows and
  overlap-narrowing bound of 100 rows, query grouping, positive finite durations, deterministic score/document-ID ties,
  and same-snapshot checkpoint restart.
- Both metadata validators are inactive while `SEARCH_STREAMING_CONTRACTS_ENABLED` is `False`; they are retained as
  opt-in design records and must not block batch integration or delivery.

## Gaps preventing ready-to-start status

The current graph declares streaming lineage, but the compiler report still identifies these blockers:

| Gap | Current boundary | Required V10 work |
| --- | --- | --- |
| Global ranking state | `admit.py` and `overlap.py` use `row_number(...)`; `rerank.py` also uses analytic ranking and priority selection. | `SearchFiniteTopKContract` records the 1,000/100 bounded shape; replace the current analytic lowering and prove the runtime, or keep these stages design-gated. |
| Unbounded deduplication | Search scoring and gap-selection paths still contain ordinary `drop_duplicates(...)`, which is not watermark-bounded state. | Replace with row-local uniqueness/unique query IDs or an explicitly watermark-bounded state stage; add compiler rejection for any remaining unbounded form. |
| Unbounded aggregates | Query-term sizing and score normalization group by business keys without a finite event-time completion window. | Move immutable corpus/index computations to batch/static snapshots and implement bounded per-query aggregation with explicit retention. |
| Stream/stream joins | Query/request and cached/online branches are not all admitted as one bounded, exact-schema stream/stream plan. | Require declared watermarks, matching event-time predicates, finite retention, exact schemas, and append mode at every join/union boundary. |
| Finalization semantics | Watermarks exist in parts of the graph, but no compiler-visible state record proves when one query is complete or prevents revisions. | Add ordered state-stage metadata and a single append-finalization contract; reject missing completion windows before query start. |
| Caller run handoff | Structure deliberately does not own source, checkpoint, trigger, sink, snapshot refresh, or downstream materialization. | `SearchDocumentsRunContract` validates the V10 caller-owned checklist; end-to-end readiness diagnostics and live evidence remain separate gates. |

These are separate gates. Adding `requested_at` or propagating `streaming=True` does not make a global analytic window
bounded, and a watermark alone does not make a business-key aggregate or duplicate operation finite.

## Implementation order

1. Propagate `requested_at` through Search schemas, fixtures, generated schemas, query-label transforms, and synthetic
   similarity queries. Add compiler-visible timestamp consistency checks for query/request pairs.
2. Add a caller-configured watermark delay and finite completion-window contract. Apply watermarks before the first
   query/request stateful operation and require event-time bounds on every stream/stream join.
3. Make query token distinctness row-local with `array_distinct`; remove unbounded query-term and score-cache
   deduplication from the streaming path.
4. Split cached and online scoring into streaming branches. Join each branch to static indexes/caches, then combine
   only through exact-schema stream/stream union.
5. Add a typed bounded finite-window top-K state operation. It must retain at most the configured candidate bound,
   use deterministic ordering, expose its event-time/window/grouping metadata in IR, and require append output mode.
   Use it for the 1000-candidate admission and 100-candidate overlap boundary; do not reuse `row_number`.
6. Add a batch/static snapshot preparation boundary that resolves feedback fallback and popularity. The streaming
   reranker may only use stream/static lookups, bounded normalization, and the finite top-K state operation.
7. Emit final ranked rows after watermark completion and add generated-code explain output naming every state stage,
   retention bound, output mode, and rejected operation.

The implementation order and evidence requirements for these gaps are maintained by the V10 plans for [state and joins](P08022602.V10-streaming-state-and-join-contracts.plan.md),
[side effects and arbitrary state](P08022603.V10-streaming-side-effects-and-arbitrary-state.plan.md), and
[evidence and hardening](P08022604.V10-evidence-catalog-reconciliation-and-hardening.plan.md).

## Tests and evidence

- No-Spark compiler tests cover missing timestamps, missing watermarks, unbounded deduplication, unsupported joins,
  global analytic windows, state-stage ordering, append-mode requirements, and deterministic top-K ties.
- No-Spark contract tests cover incomplete snapshots, non-append output, mutable event-time assumptions, refresh/restart
  policy, finality, and downstream materialization declarations.
- No-Spark top-K contract tests cover the exact candidate/overlap bounds, query grouping, deterministic ties, append mode,
  positive finite durations, completion window, snapshot identity, and restart boundary.
- Generated-source scans reject `readStream`, `writeStream`, `start`, `awaitTermination`, checkpoint/trigger setup,
  actions, RDD/Pandas conversion, arbitrary-state hooks, and hidden materialization.
- Online/generated parity tests cover duplicate and late queries, empty result sets, score ties, feedback ties, and
  snapshot immutability.
- PySpark 3.5 and 4.0 live lanes cover append emission, watermark completion, checkpoint restart, late-event
  suppression, and the absence of result revisions.
- Existing batch SearchDocuments tests remain the semantic parity oracle.

## Exit and fallback

Promote the streaming ranker only after positive online/generated parity and restart evidence on both supported Spark
profiles. If bounded top-K or any other state shape cannot be proven with public Spark APIs and compiler-visible
metadata, keep that shape `design-gated` or `streaming-ineligible` with a diagnostic directing callers to a
batch/materialization boundary. Never silently retain a global analytic window in the streaming path.

Revision note (2026-08-05): Hardened the caller-owned run and finite top-K metadata guards. Completion and watermark
declarations now require positive finite Spark durations, and every top-K grouping must include `query_id`; the
analytic ranking path remains design-gated until runtime and restart evidence exists.
