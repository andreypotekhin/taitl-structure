## Purpose / Big Picture

V10 will give users an executable, caller-owned safety model for streaming side effects and an implementation-ready
typed model for arbitrary state APIs. It will make clear which guarantees Structure can verify and which guarantees must
remain in the application that owns sinks, checkpoints, retries, and deployment.

## Surprises & Discoveries

- Observation: `foreachBatch` already has a caller-owned adoption recipe and is not part of generated transform code.
  Evidence: `examples/streams/adoption.py` and the V9 streaming documentation.
- Observation: Arbitrary state APIs differ by PySpark profile and involve user-managed mutable state.
  Evidence: the V9 arbitrary-state specification and streaming coverage ledger.

- Observation: Existing `foreachBatch` guidance showed where to attach the sink but did not force the caller to state how
  retries, sink identity, and serving snapshots are related.
  Resolution: `examples.streams.adoption.ForeachBatchSafety` validates those declarations before query start while
  deliberately leaving idempotence and transactionality in caller code.
- Observation: A failed `foreachBatch` callback leaves the caller checkpoint restartable in the supported classic
  PySpark lanes; the resumed callback receives the uncommitted batch and the deterministic sink replaces/creates one
  file for its `(snapshot_id, batch_id)` identity.
  Evidence: `tests/integration/pyspark/v10/test_foreach_batch_restart.py` passed on PySpark 3.5 and 4.0.
- Observation: A V10 integration fixture must be a Python package so its qualified source module matches the generated
  project path.
  Resolution: Added `tests/integration/pyspark/v10/__init__.py` and kept generated lifecycle scans in the fixture.
- Observation: The existing arbitrary-state specification described the required dimensions but did not offer an
  executable completeness boundary for caller review.
  Resolution: Added `ArbitraryStateContract.validate()` as metadata-only guidance with explicit schema, timeout, and
  lifecycle declarations; it does not lower or start stateful PySpark code.

## Decision Log

- Decision: V10 specifies safety and adoption guidance, not a Structure-owned `foreach`, `foreachBatch`, or job API.
  Rationale: Sources, sinks, checkpointing, retries, and deployment are lifecycle responsibilities outside transforms.
  Date/Author: 2026-08-02 / Codex.
- Decision: Any future arbitrary-state interface must declare input, state, and output schemas; timeout clock and
  policy; initialization and cleanup; target profile; generated-code/hook boundary; and restart behavior before code is
  admitted.
  Rationale: These facts are necessary to reason about correctness and recovery.
  Date/Author: 2026-08-02 / Codex.
- Decision: Caller-owned recipes must make sink identity, idempotence key, retry semantics, checkpoint policy, and
  failure handling explicit.
  Rationale: A transformed DataFrame alone cannot guarantee external side-effect correctness.
  Date/Author: 2026-08-02 / Codex.
- Decision: SearchDocuments may expose readiness facts and corrective diagnostics, but it must not start or validate a
  caller's streaming query on the caller's behalf.
  Rationale: The caller owns the source, checkpoint, trigger, append sink, snapshot refresh, restart policy, and any
  materialization used to bridge a gated state operation.
  Date/Author: 2026-08-02 / Codex.
- Decision: Add safety declarations to the caller-owned adoption helper without adding a Structure-owned sink runtime.
  Rationale: A pre-start guard can make missing recovery assumptions visible without falsely claiming that Structure can
  inspect or enforce arbitrary callback behavior.
  Date/Author: 2026-08-04 / Codex.
- Decision: Keep all arbitrary state processor APIs design-gated after adding the typed metadata contract.
  Rationale: Completeness validation is not a state runtime, and no supported target has positive Structure-owned
  checkpoint/restart evidence for these APIs.
  Date/Author: 2026-08-04 / Codex.

## Outcomes & Retrospective

The completed increment gives callers a runnable recipe for applying side effects after Structure transforms, including a
validated safety declaration for `foreachBatch` and live restart/retry evidence for deterministic caller-owned sinks.
It also gives callers executable completeness checks for the typed arbitrary-state and SearchDocuments run boundaries
while retaining both runtime areas' honest design-gated status. End-to-end SearchDocuments readiness remains governed by
the separate SearchDocuments structured-streaming plan.
No generated Structure module owns a sink, callback retry loop, checkpoint, or query lifecycle.

## Context and Orientation

Structure's public streaming boundary ends at a transformed DataFrame. The relevant sources are
`docs/dev/design/SparkStreamingDeferredFeatures.md`, `docs/dev/design/V9StreamingDesignGates.md`,
`docs/dev/specifications/SparkStreamingDeferredFeatures.md`, `docs/dev/specifications/V9StreamingDesignGatedFeatures.md`,
and `examples/streams/adoption.py`.

## Plan of Work

Document the caller-owned recipe for `foreachBatch`, row-level `foreach`, custom sinks, and external effects. Require a
stable sink identity, idempotence key, retry behavior, checkpoint policy, failure diagnostic, recovery behavior, and
security review for callbacks. Add examples that show the caller applying these policies around a Structure result.

Define the arbitrary-state model as a separate typed programming boundary. It must identify input rows, state schema,
output rows, grouping key, event-time or processing-time clock, timeout behavior, initialization, updates, removal,
target-version capabilities, generated-code shape, hook ownership, and restart evidence. Until implementation and live
evidence exist, the ledger remains `design-gated`.

For SearchDocuments, add a caller-owned run contract alongside the state plan. The contract should require the caller
to bind one immutable snapshot identity to the index, score cache, feedback, popularity, and policy inputs; start the
query with the append mode named by the compiler report; place the checkpoint at a stable query identity; and create a
new run when any serving snapshot is refreshed. The contract must state that emitted results are final and must not be
revised by a later snapshot or late event. If the caller materializes an intermediate score or candidate relation to
bridge a design-gated operation, that materialization is an explicit batch boundary, not hidden Structure state.

## Validation and Acceptance

Acceptance requires executable caller-owned `foreachBatch` guidance, explicit rejection of Structure-owned side effects,
generated-source cleanliness, and a typed arbitrary-state specification with profile-specific evidence requirements.
SearchDocuments additionally requires a caller handoff checklist that makes snapshot immutability, checkpoint identity,
append-only output, restart behavior, and downstream materialization visible without adding lifecycle APIs to Structure.
Support claims must not be made for `foreach`, arbitrary state, or custom sinks without live restart and recovery proof.

## Idempotence and Recovery

Examples use temporary checkpoints and deterministic test sinks. No test may perform an uncontrolled external write. A
failed live lane is cleaned by removing only its isolated temporary paths and is recorded as unavailable or failed evidence.

## Artifacts and Notes

Expected artifacts are updated adoption examples, safety documentation, diagnostics, compatibility rows, generated-source
scans, arbitrary-state specification sections, and live restart evidence where a target supports the model.

## Interfaces and Dependencies

Use `examples.streams.adoption.start_foreach_batch_query(...)`, existing `StructureSession`/transform boundaries,
streaming compatibility diagnostics, and public PySpark writer APIs in caller code. Do not add a Structure-owned job,
sink, checkpoint, or arbitrary-state runtime in this plan.
