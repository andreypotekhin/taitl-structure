# Add the Streams Example and Preserve Caller-Owned Streaming Lifecycle

This ExecPlan is a living document and follows `docs/dev/auto/Plans.md`.

## Purpose / Big Picture

Add `examples/streams`, a white-water kayaking timing and judging model that proves Structure's admitted streaming
transformations without implying ownership of Spark query lifecycle.

## Progress

- [x] 2026-07-12 Agreed the caller-owned lifecycle boundary and streams domain.
- [x] 2026-07-12 Added the example, golden generated output, tests, and documentation correction.
- [x] 2026-07-13 Ran default verification and focused live PySpark 3.5 file-stream verification.

## Surprises & Discoveries

- The active v3 roadmap planned lifecycle ownership although several public references already described it as caller-owned.
- Spark executors need the same mounted input path as the test runner; the Compose Spark master and workers now mount the
  existing integration workspace directory.

## Decision Log

- Decision: Keep sources, sinks, triggers, checkpoints, output modes, and query control in caller code.
  Rationale: They are orchestration, not transformation, concerns.
- Decision: Keep advanced winner/ranking analytics out of `streams`.
  Rationale: Ranking a completed race is batch-only under the current streaming contract.

## Outcomes & Retrospective

Implemented `examples/streams` with generated golden output, contract tests, and a live file-stream test. `make build`
passes (662 passed, 10 skipped). The focused PySpark 3.5 Compose test passes and proves caller-owned file input and
memory-sink query control across online enrichment, generated aggregation, and generated bounded stream correlation.

## Context and Orientation

`examples/streams` is the canonical public and test model. It contains static `Race`, `Gate`, and `Paddler` reference
schemas; streaming `RawEvent` and `JudgeCall` inputs; enriched `Passage`, aggregate `GateProgress`, and joined
`Penalty` outputs. `RaceWinner` is a future batch-only contract.

## Plan of Work

Implement three streaming-compatible transforms: watermarked static enrichment plus dedupe, watermarked gate progress
aggregation, and a bounded passage/judge-call stream join. Generate and check in the public golden output. Add static,
differential, and file-stream integration tests. Update public and project-management documentation to make caller-owned
lifecycle permanent, then postpone the obsolete lifecycle plan.

## Concrete Steps

Run from the repository root:

    poetry run pytest tests/golden tests/differential tests/specifications/streaming-compatibility -q
    poetry run pytest --run-integration tests/integration/pyspark/v3/streams -q
    make build

## Validation and Acceptance

The generated transforms contain watermarks and admitted state operations but no `readStream`, `writeStream`, trigger,
checkpoint, or query-control APIs. File-stream integration starts caller-owned memory-sink queries and verifies
deduplicated online passages, generated gate progress, and generated bounded penalties.

## Idempotence and Recovery

Generated output is deterministic. Integration tests use temporary source and checkpoint directories and stop every
query. Re-run with a fresh temporary checkpoint after a failed Spark query.

## Interfaces and Dependencies

No Structure API is added. The example uses existing `StreamingMode.YES`, `watermark(...)`, `drop_duplicates(...)`,
`group_by(...)`, `inner_join(...)`, and `event_time_between(...)` APIs.
