## Context and Orientation

Structure is a Python-to-PySpark compiler and runtime. Users write typed `Transform` classes; Structure can run them
online through `StructureSession` or emit generated PySpark classes. For streaming, Structure transforms return a
DataFrame plan. The caller owns sources, sinks, checkpoints, triggers, output modes, query start/stop, deployment, and
recovery.

V9 uses five status terms. `structure-supported` means Structure owns the typed transform contract and evidence.
`caller-owned-guided` means the operation remains ordinary caller PySpark, with a runnable recipe and diagnostics.
`streaming-ineligible` means the shape cannot safely run on an unbounded stream under the current contract.
`unsupported` or `not-applicable` means the public API does not belong in Structure's model. `design-gated` means a
written design exists but a support claim still lacks a complete contract or evidence.

The authoritative ledger is `src/structure/plugin/pyspark/resources/pyspark-streaming-api-coverage.json`. The public
catalog is `docs/APICatalog.md`; streaming reference material is in `docs/api/Streaming.api.md` and the background
documents under `docs/background/`. No release status is complete until the ledger, catalog, specifications, tests,
and documentation agree.

6. Reconcile ledgers, diagnostics, explain output, generated artifacts, public docs, troubleshooting, and live evidence.

The priority order is release correctness first, then supportable typed slices, then documentation and evidence closure:

- P0: status/ledger consistency, diagnostics, generated-source safety, and hardening blockers;
- P1: selected-row and analytic-window decisions, Variant completion, and Geometry provider contract;
- P2: evidence lanes and documentation for already-decided rows;
- P3: optional polish that cannot alter the V9 support contract.

## Plan of Work

Begin each slice by updating the ledger row and its acceptance command before editing implementation code. Keep typed
source capture, IR, capability checks, online lowering, generated rendering, diagnostics, and tests in one vertical
slice. Do not use raw SQL, private JVM APIs, actions, RDDs, Pandas execution, or lifecycle calls to manufacture a
passing streaming result.

For selected-row and analytic-window work, prototype the smallest Spark plan outside Structure first. Promote it only if
both target profiles prove the same bounded semantics. If Spark rejects the shape, retain a useful finite alternative
or produce a diagnostic that directs the caller to batch materialization or caller-owned PySpark.

For Variant and Geometry, keep target-specific behavior behind capability/profile checks. Generated code must remain
portable and must not import an optional provider. Provider availability belongs at schema materialization or execution,
where the diagnostic can explain the missing runtime contract.

For every catalog closure, update the public API table and the relevant background/reference page in the same change as
the implementation or rejection test. Generated documentation and traceability are release artifacts, not optional
cleanup.

## Idempotence and Recovery

All work is additive and rerunnable. Regenerate artifacts from source rather than editing generated files manually. If a
live Spark or provider lane is unavailable, retain the last honest status and write the missing evidence path into the
plan. If a prototype fails, preserve the smallest failing fixture, record the Spark version and error, and classify the
API rather than weakening its contract. If a date slips, move the remaining sprint boundary while keeping Sprint 48
after the last feature sprint.

Use the existing Structure `Transform`, schema, capability, diagnostic, online recipe, generated renderer, and
traceability interfaces. Use only public PySpark DataFrame and SQL APIs in generated transforms. Geometry providers are
optional and late-bound; the bundled PySpark plugin must not import Sedona. Streaming lifecycle remains caller-owned.

Java/Spark runtime in the target images. A missing dependency changes the evidence status; it does not authorize a
weaker support claim.
