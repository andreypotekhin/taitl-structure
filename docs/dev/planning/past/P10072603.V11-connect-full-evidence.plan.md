## Implementation

Compose already mounts the repository read-only at /workspace, with a writable integration-artifact directory. Each
runner now invokes bash /workspace/infra/compose/images/pyspark/run-integration.sh followed by its backend name, so the
baked /usr/local/bin/run-integration cannot silently select old tests. Rebuilds explicitly build selected runner
services before their required Spark services start. Selecting Connect 4.1 alone starts no master/worker services.

Keep Iceberg and Delta in separate pytest processes and exclude their modules from the general phase. Connect 4.1
uses tests/integration and tests/concepts/live_pyspark. Ordinary 4.1 remains limited to its version check and V11 tests.
All phases report their selections, exit status, and skip reasons. Register gateway/checkpoint cleanup before setup so
failures cannot leave this run's resources behind. Retain package versions, caches, default profiles, and sequential
live execution. Do not stop shared services or alter state processor/foreachBatch interfaces or admission rules.

Unexpected failures require a concrete fix and a regression test. Existing capability limits and independently owned
streaming/state/sink interfaces can justify explicit skips; a timeout remains a failed run. New support requires
positive online/generated parity evidence for output values, schema, and generated spelling.

## Decision Log

Use the existing repository mount for the launcher rather than force image rebuilds for source changes. Rebuild
selected runner images explicitly because starting Spark master/worker services with --build does not build runners.
Keep phase orchestration in one Bash helper so all phases share status, diagnostics, and skip reporting.

## Surprises & Discoveries

The current repository general selection collected 272 tests before live execution; the count can change with other
chats. The launcher tests pass 40 cases; focused compatibility/capability/source/materialization checks pass 489 cases.
Their macOS Bash 3.2 run exposed empty-array expansion under set -u;
append optional exclusions only when present so Connect 3.5/4.0 remain usable in Spark-free runner checks. Explicit
configuration validation also avoids macOS Bash reporting success after an unset-variable setup failure.

The first full run collected all 272 general tests and reported 214 passed, 56 skipped, and two failures in 327.36s.
One callback source assertion used double quotes although the renderer emits a single-quoted cast type; the corrected
assertion was already on disk after this process collected its tests. The other failure was UNRESOLVED_ROUTINE for
ST_GeomFromWKT. The V9 geometry specification scopes its optional Sedona provider evidence to Spark 3.5/4.0; the 4.1
lane configures Delta/Iceberg and has no Sedona SQL extension. Mark just that provider test as excluded on 4.1 at
collection time, with the existing specification named in its reason. No batch capability was removed or admitted by
this exclusion. The original unfiltered full log remains v11-connect41-full.log; rerun the finished source separately.

The finished unfiltered Connect 4.1 run used launcher checksum 3047266420 (9,184 bytes), matching source. Its three
phase collections were 15, 34, and 272, exactly matching provider selections and fresh general collection. Results:
Iceberg 15 passed in 41.43s; Delta 33 passed / 1 skipped in 110.96s; general 215 passed / 57 skipped in 334.18s.
