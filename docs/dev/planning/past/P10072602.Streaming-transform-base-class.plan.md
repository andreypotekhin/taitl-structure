# Introduce an inherited streaming contract with StreamingTransform


This ExecPlan is a living document maintained under `docs/dev/auto/Plans.md`. Keep `Progress`,
`Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` current throughout implementation.

The plan was requested on 2026-10-07 before implementation. The user later authorized implementing the full plan.
This document records its design, implementation, tests, and verification limits.

## Purpose / Big Picture


Allow users to declare a streaming-compatible transform by inheriting from `StreamingTransform`, without adding
`@transform(streaming=True)`. Every descendant must preserve this compatibility requirement. Developers can build
a hierarchy whose inherited, overridden, and newly added steps are checked for streaming compatibility.

Keep the existing decorator as an alternative for a class-local declaration. A child of an ordinary `Transform`
hierarchy can opt in with `@transform(streaming=True)`, including when its parent declares `streaming=False`.
That opt-in subjects the child's effective steps to validation; it does not make incompatible code safe. It also
does not turn that class into a nominal subclass of `StreamingTransform` or propagate its decorator to grandchildren.

Success is observable by compiling equivalent decorator-based and base-class-based transforms, then extending the
latter without a decorator. Compatible descendants compile; incompatible descendants fail streaming checks. An
explicit `streaming=False` on a `StreamingTransform` descendant fails immediately with a corrective error.

## Surprises & Discoveries


Decorator options deliberately do not inherit. In `src/structure/core/dsl/model/transforms/Transform.py`,
`Transform.__init_subclass__` clears `_structure_transform_options` for each child, and
`effective_transform_options()` reads the child's own dictionary. The regression
`test_class_level_decorator_options_do_not_leak_to_undecorated_children` in
`tests/specifications/transform-inheritance/test_transform_inheritance.py` expects the child's plan options to be
empty. Adding a decorated library base alone therefore cannot implement this feature.

Composition has additional option resolution paths. `ComposeTransformGraph` and `ComposeTransformPlans` currently
pass the wrapper's raw class options to `Transform.resolve_transform_options()`. Updating only ordinary frontend
compilation would leave composed wrappers without the new inherited requirement.

Source discovery already recognizes undecorated subclasses by ancestry and declared outputs. Its module-ownership
check excludes imported classes. The library base should have no declarations or step methods and should never
become a discovered user transform or a generated user implementation class.

The referenced annotated-source guide `docs/dev/Annotation.auto.md` is absent, and a repository search found no
annotated-source files. There is no annotated mirror to update for this feature.

The compatibility classifier needs `streaming_contract=True` to analyze every operation when current inputs are batch.
Passing only `required=True` checks streaming inputs and does not request the class-wide promise. The regression tests
pass the contract flag, matching the compiler's production call.

## Decision Log


Decision: Export `StreamingTransform` as a subclass of `Transform` from the target-neutral `structure` package.
Rationale: This is a declaration of compatibility requirements, while the selected plugin continues to determine
which operations satisfy them. No new runtime, query controller, or plugin capability is introduced.
Date/Author: 2026-10-07 / User and Codex.

Decision: Every descendant of `StreamingTransform` retains the streaming requirement, with no decorator opt-out.
Rationale: The user selected a required contract. An incompatible subclass would contradict what its base promises.
Multiple inheritance and diamond hierarchies retain the requirement whenever any ancestor is `StreamingTransform`.
Date/Author: 2026-10-07 / User and Codex.

Decision: Keep decorator options class-local, including both `streaming=True` and `streaming=False`.
Rationale: This preserves current behavior and the user's explicit clarification. A decorated child can opt into
streaming below an unmarked or explicitly batch parent. Its undecorated child does not inherit the decorator's
requirement unless the hierarchy also includes `StreamingTransform`.
Date/Author: 2026-10-07 / User and Codex.

Decision: Keep input lineage, opaque-hook safety declarations, and caller-owned streaming lifecycle unchanged.
Rationale: Requiring compatible steps does not identify which inputs carry streaming data, prove arbitrary hook
code safe, or start a streaming query. Static lookup inputs and batch execution remain valid.
Date/Author: 2026-10-07 / User and Codex.

Decision: Use the existing resolved `streaming=True` option throughout compilation and generation.
Rationale: One effective option keeps diagnostics, composition, and streaming-dependent defaults consistent with
the decorator. Do not introduce a second plugin option, serialized flag, or backend-specific class hierarchy.
Date/Author: 2026-10-07 / Codex.

## Context and Orientation


Structure captures Python transform methods into a compiler plan, then executes that plan or emits equivalent
generated Python. Streaming compatibility means those operations are permitted for streaming DataFrames. Streaming
lineage records which input relations and derived relations can contain streaming data. These are distinct concerns:
the class option requires every concrete step to satisfy streaming compatibility even with batch inputs, whereas
`input(..., streaming=True)` identifies a streaming-capable relation. Runtime DataFrames still determine whether
execution produces a stream.

The public exports are in `src/structure/__init__.py`. Transform declarations and option resolution live in
`src/structure/core/dsl/model/transforms/Transform.py`; the decorator and option normalization live in the adjacent
`transform_api.py`. `_decorate_transform_class()` validates options and stores them on the declaring class.

The frontend entrypoints `AnalyzeTransform.py` and `CompileTransform.py`, under
`src/structure/core/compiler/frontend/commands/`, use effective class options. The composition helpers
`src/structure/core/compiler/frontend/logic/ComposeTransformGraph.py` and
`src/structure/core/compiler/frontend/logic/ComposeTransformPlans.py` assemble plans for named stages and `.to(...)`
pipelines. Their composed input lists must continue to participate in existing input-option validation.

`src/structure/core/compiler/frontend/logic/CompilerTransformMemberCollector.py` gathers inherited user methods.
`src/structure/core/sources/commands/DiscoverStructureSources.py` discovers transforms in loaded source modules.
`src/structure/core/compiler/artifacts/commands/BuildArtifactManifest.py` records source dependencies for artifact
reuse. These paths currently special-case `Transform` as library infrastructure; the new base needs equivalent
treatment where traversing it would otherwise treat library source as user source.

Behavioral coverage already exists under `tests/specifications/transform-inheritance/`,
`tests/specifications/transform-composition/`, and `tests/specifications/streaming-compatibility/`. User stories live
in `docs/dev/specifications/UserStories.spec.md`, with streaming tests under
`tests/user_stories/17_streaming_compatibility/compatibility_checks/`. The public API snapshot is
`res/testing/snapshots/api/public_structure.v1.json`, checked by `tests/app/test_public_api_snapshot.py`.

preserve those edits and keep implementation changes limited to this feature.

## Public Behavior


The new declaration is available through named and wildcard imports:

    from structure import *
    from structure.plugin.pyspark import *

    class Event(Schema):
        id = string(nullable=False)

    class CleanEvents(StreamingTransform):
        events = input(Event, streaming=True)
        clean = output(Event)

        def clean_event(self, event: Event) -> Event:
            where(event.id.is_not_null())
            return Event.project(event)(id=event.id)

    class SpecializedEvents(CleanEvents):
        pass

Both classes require streaming-compatible steps. Any decorator on `SpecializedEvents` that sets unrelated options,
such as `target="pyspark"`, preserves that requirement. Explicit `streaming=True` is accepted and redundant.
Explicit `streaming=False` is an error at decorator application, before compilation or runtime work.

For an ordinary hierarchy, the existing opt-in remains valid:

    @transform(streaming=False)
    class BatchDefault(Transform):
        pass

    @transform(streaming=True)
    class StreamingUse(BatchDefault):
        pass

This example illustrates option resolution; concrete compilable transforms must also declare inputs, outputs,
and compatible steps. `StreamingUse` has a streaming requirement despite its parent's class option. Its own
undecorated descendant has no class-level streaming option. Inherited streaming input declarations still trigger
lineage analysis independently, exactly as they do today.

Every effective step of a `StreamingTransform` descendant is checked, including inherited methods and overrides.
Neither method options nor global disabling of optional compatibility checks may weaken the existing mandatory
`streaming=True` behavior. Opaque hooks retain their existing explicit streaming-safe declaration requirements.
An `input(..., streaming=False)` remains explicitly batch-only; the new class must not rewrite input declarations.

Multiple inheritance retains the requirement in either valid Python base order. An unrelated parent's class-local
`streaming=False` does not itself conflict: it is not inherited. A `streaming=False` decorator on the resulting
`StreamingTransform` descendant does conflict. Shared batch and streaming behavior can be factored into an ordinary
base, with the streaming branch also inheriting `StreamingTransform`.

### Milestone 2: Add the base class and resolve its contract once

Make `Transform.resolve_transform_options()` a classmethod with the same caller-visible arguments and return type.
Use a function-local import of `StreamingTransform` to avoid a module import cycle. Detect the contract using
`issubclass(cls, StreamingTransform)`, so it depends on actual ancestry and cannot disappear because of class option
resetting or base ordering. Copy supplied options, reject explicit `False` for that ancestry, set effective
`streaming=True`, and then perform the existing input validation. Calls bound to `Transform` retain current behavior.
`effective_transform_options()` already dispatches through `cls.resolve_transform_options()`; retain its existing
handling of other options.

In `_decorate_transform_class()`, check the proposed normalized streaming option against this class-aware resolver
before assigning class metadata. For this early check, omit input validation so existing unrelated invalid-input
errors keep their current timing. Keep stored decorator metadata class-local, and do not copy other ancestor options
or turn the decorator into an inheritance mechanism. Effective option resolution remains the authoritative check
at compilation as well.

The new `TypeError` must name the offending class, state that descendants of `StreamingTransform` cannot declare

### Milestone 3: Preserve the requirement through composition and artifacts

## Validation and Acceptance


Public API tests prove `StreamingTransform` is exported, and wildcard-import-based inheritance tests compile without
a Spark installation. A compatible transform using the new base compiles with the existing streaming option; generated
code does not include a generated class for the library base. Undecorated children and grandchildren retain the
requirement. A child adding a known batch-only operation receives the existing `STREAM-E0801` finding through the
streaming classifier when the class-wide contract is requested.

Inheritance tests cover valid multiple-inheritance orders and a diamond, unrelated transform options, redundant
`streaming=True`, and the actionable immediate error for explicit `False`. They also cover `@transform(streaming=True)`
on children of both unmarked and explicitly `streaming=False` ordinary parents. Such children enforce streaming checks
on their effective steps, while an undecorated grandchild does not inherit decorator options.

Input tests show that static lookup inputs remain static, explicit batch-only inputs retain their restrictions,
and streaming input declarations retain their separate lineage semantics. Batch input fixtures remain executable;
neither the class nor its descendants start a query or add read/write-stream lifecycle calls to generated code.

Composition tests verify the requirement on a named-stage wrapper with batch-declared inputs and show its incompatible
inner step receives `STREAM-E0801`. A wrapper without the new ancestry preserves its previous behavior. Generation,
source discovery, and artifact tests prove that concrete descendants remain usable and that the empty library base
contributes no user steps, generated base implementation, or application-source dependency. Existing class-local
decorator and inheritance regressions pass.

## Interfaces and Dependencies


The sole new public type is `structure.StreamingTransform`, implemented as a subclass of `structure.Transform`.
Existing invocation, compilation, generation, and execution interfaces remain available through inheritance.
`@transform(...)` retains its existing signature and class-local option semantics.

`Transform.resolve_transform_options(options=None, *, inputs=(), transform_name=...) -> dict[str, object]` becomes
class-aware while preserving its existing call shape. The effective options dictionary continues to represent the
requirement with the existing `streaming: True` entry. No new serialized field, configuration switch, plugin interface,
runtime package, or streaming capability claim is required.
