# Extend Delta parity with inspection, column metadata, and maintenance

## Purpose / Big Picture

A Structure user can already pass a native Delta table into a transform, mutate rows, read snapshots and batch change data feed (CDF), and evolve a schema explicitly. After this plan is implemented, a transform can also inspect table history and details as typed relations; write to tables with declared generated, identity, or default columns without falsely requiring values Delta supplies; and perform explicit restore, optimize, and vacuum maintenance operations. A caller can see each effect in generated code and observe the same table state after online and generated execution.

The visible proof uses disposable Delta tables. A history transform returns recent commits with a runtime limit. A merge inserts rows while Delta generates an identity value. A restore returns a previously declared schema and commit. Optimize rewrites files without changing rows. Vacuum removes old, unreferenced files only after its retention checks pass. These operations remain scoped to the caller-supplied table; Structure does not create a table, change protocol features, install constraints, or own streaming query lifecycle.

## Surprises & Discoveries

- Observation: The existing `delta_snapshot` and `delta_changes` helpers encode reads in the Delta operation record, and `validate_delta_relation` accepts a declared subset of a native read DataFrame's columns. This provides a route for history/detail results, whose metadata columns may vary by Delta version. Evidence: `src/structure/plugin/pyspark/delta/operations.py`, `model.py`, and `runtime.py`.
- Observation: `Schema.constraints` already demonstrates target-specific declarations without adding Delta options to ordinary DataFrame fields. `Schema` currently has no declaration for generated, identity, or default columns, and `_assignments` requires every non-nullable insert field. Evidence: `src/structure/core/dsl/model/schemas/Schema.py`, `src/structure/plugin/pyspark/delta/checks.py`, and `operations.py`.
- Observation: Native `history()` and `detail()` return DataFrames; native restore and optimize return metrics DataFrames; native vacuum returns an empty DataFrame after deleting eligible files. A restore is a data-changing Delta commit, while optimize changes file layout. Vacuum can make older snapshots unreadable because it removes unreferenced data files. Evidence: Delta's Python API and table-utility documentation linked under `Artifacts and Notes`.
- Observation: Delta-generated columns can be omitted from writes. Identity columns can be `GENERATED ALWAYS` or `GENERATED BY DEFAULT`; an identity table restricts concurrent writes. Generated-column merge behavior needs a pinned runtime proof before Structure promises omission in every merge clause. Evidence: Delta table batch-read/write documentation linked under `Artifacts and Notes`.
- Observation: In Delta 4.1.0, generated expressions and identity settings are in the Delta log schema metadata (`delta.generationExpression`, `delta.identity.*`), while `StructField.metadata` is empty for those columns. Literal defaults appear as `CURRENT_DEFAULT` in Spark's current schema. Delta 4.1 merge insert clauses successfully omit all three declared field kinds; identity sequence values may have gaps and should not be assumed contiguous.
- Observation: The first full V11 process had already initialized Spark before the Delta fixture attempted Ivy package resolution. Delta must run in a separate runner process before the ordinary V11 process so its jars enter the driver classpath before JVM startup. Evidence: `make integration BACKEND=pyspark41`.

## Decision Log

- Decision: Deliver this as vertical slices in the order inspection, column metadata, restore, optimize, then vacuum.
  Rationale: read-only inspection exercises the existing typed read path first; metadata fixes write typing before more effects; vacuum's irreversible file deletion receives an isolated final milestone.
  Date/Author: 2026-10-06 / Codex, implementing the user-approved parity queue.
- Decision: Keep `delta_history` and `delta_detail` as direct-return relations selected by the step return annotation, and allow a declared subset of native metadata columns.
  Rationale: this matches snapshot/CDF authoring and avoids freezing every vendor metadata field into Structure.
  Date/Author: 2026-10-06 / Codex.
- Decision: Declare expected generated, identity, and default behavior in `Schema.delta_columns` through Delta-specific helpers; verify native metadata before relaxing insert requirements.
  Rationale: the compiler must never infer auto-population from nullability alone, and a plain Schema remains usable for ordinary DataFrames.
  Date/Author: 2026-10-06 / Codex.
- Decision: Restore returns the table-result marker directly. Its result annotation names the expected post-restore Schema, while vendor metrics remain available through caller-owned native code or later history inspection.
  Rationale: a restore can change the table shape and must use the same explicit result discipline as schema evolution; exposing a second metrics result would require a separate multi-result effect design.
  Date/Author: 2026-10-06 / Codex.
- Decision: Optimize and vacuum are dedicated maintenance steps with explicit `.execute_*()` / `.execute()` calls and may not be mixed with row mutations in one step.
  Rationale: file-layout and retention effects need distinct preflight and failure reporting.
  Date/Author: 2026-10-06 / Codex.
- Decision: Vacuum defaults to 168 hours. A shorter interval requires `allow_short_retention=True` in source and must still pass Delta's own retention safety check; Structure never disables that Spark setting.
  Rationale: a short retention can remove files needed by lagging streams or concurrent readers, and an explicit helper argument cannot prove those consumers have stopped.
  Date/Author: 2026-10-06 / Codex.
- Decision: Run the Delta live module in a fresh Python process before the remaining V11 suite.
  Rationale: the test fixture uses Delta's supported PySpark integration to resolve jars through Ivy, and a previously initialized driver JVM cannot add those jars safely.
  Date/Author: 2026-10-06 / Codex.
- Decision: Accept `delta_generated(..., as_="...")` as a SQL expression string in this increment and compare it exactly (ignoring whitespace) with Delta's stored generation expression.
  Rationale: schema declarations are static class values, so row-scope expression objects are unavailable there. The native metadata check prevents a declaration from relaxing insert checks unless the bound table records the same expression. A typed expression builder remains a future ergonomics improvement.
  Date/Author: 2026-10-06 / Codex.

## Context and Orientation

The PySpark plugin compiles method calls symbolically, records immutable operation data, then runs that data online or renders equivalent generated Python. `delta_input(Schema)` is a read-only native `delta.tables.DeltaTable` binding. `delta_table(Schema)` is a caller-bound same-schema read/write binding. `delta_output(Schema)` declares the result of an explicit schema transition and is not supplied separately by the caller. ## Interfaces and Dependencies

Export `delta_history(table, *, limit=None)` and `delta_detail(table)` from `structure.plugin.pyspark`. They accept a `delta_input` or `delta_table` relation parameter and are the direct result of a single-output step whose return annotation selects an ordinary `output(ResultSchema)`. `limit` accepts a positive non-Boolean integer or `variable(int)`; `None` requests full history. The native calls are `DeltaTable.history(limit)` and `DeltaTable.detail()`. Validate the returned DataFrame against declared physical names, types, and nullability. Ignore additional native metadata columns without silently coercing an incompatible declared field.

Add `Schema.delta_columns = (...)` declarations using `delta_generated(field, as_=expression)`, `delta_identity(field, mode="always" | "by_default", start=1, step=1)`, and `delta_default(field, value=literal)`. The field argument is a field token from the same Schema class. Generated expressions use the existing deterministic typed-expression subset; a default is a typed literal in this increment. Identity fields require Structure `long` and nonzero integral step. The declarations validate expectations against native Delta field metadata at binding. The exact metadata keys and supported native merge behavior must be captured by the pinned prototype before coding; do not treat metadata embedded in an ordinary DataFrame Schema as an instruction to create a Delta feature. Only a verified auto-populated field may be omitted from required insert values. An always-identity field may not receive an explicit assignment; a by-default identity field may. Native Delta remains the authority for explicitly supplied generated values and expression equality.

Export `delta_restore(table, *, version=None, timestamp=None).execute()`. Exactly one selector is required and may be a runtime variable. A same-schema restore uses `delta_table(Current)` and may return the direct result with `-> Current`. A shape-changing restore uses `delta_input(Current)` plus `delta_output(Restored)` and a direct `-> Restored` return; the old table is checked before the commit and the result schema and CHECK metadata afterward. The returned table object is the caller's original handle. Native restore metrics are not exposed as a Structure result in this increment, and the compatibility ledger must state that limit.

Export `delta_optimize(table, *, where=None)` as a builder on `delta_table`. It ends with `.execute_compaction()` or `.execute_zorder(by=(table.field, ...))`. `where` is an optional typed Boolean predicate referring only to the bound table's partition fields; check this against native `detail().partitionColumns` before execution. Z-order columns must be distinct, present in the declared schema, and accepted by the pinned Delta runtime. Optimize is one explicit effect in a dedicated `-> None` maintenance step. Check row equality before and after, keep the bound table object, and expose no metrics result yet; document that native metrics remain caller-owned.

Export `delta_vacuum(table, *, retention_hours=168, allow_short_retention=False).execute()` as one explicit effect in a dedicated `-> None` maintenance step on `delta_table`. `retention_hours` is a finite nonnegative number or a runtime variable of a declared numeric type, with Boolean rejected. Zero is permitted only with the explicit short-retention opt-in. A value below 168 requires literal `allow_short_retention=True`; runtime values are checked before invoking native Delta. Do not set `spark.databricks.delta.retentionDurationCheck.enabled` inside Structure. Delta's own refusal remains visible when its safety check is enabled. Vacuum does not return a useful data relation; the step returns the same table handle through the `delta_table` output. After vacuum, recheck the current table shape and native CHECK metadata but do not promise historical snapshots still exist.

Keep Delta imports late in `runtime.py`; compilation, documentation generation, and package import must work without `pyspark` or `delta-spark` installed. The pinned evidence pair is classic PySpark 4.1.0 and `delta-spark` 4.1.0. Do not claim Spark Connect for these helpers without separate evidence.

## Validation and Acceptance

The history/detail examples must be usable as normal typed transform steps. A mismatched declared history/detail field reports the field and expected schema. `limit=True`, `limit=0`, and `limit=-1` fail before native execution, while two positive runtime limits produce different row counts through one compiled artifact. A detail read returns one row. Compilation and generated-source inspection must work without installed PySpark or Delta.

Column metadata acceptance requires both positive writes and negative preflight. The same `Schema` still materializes as an ordinary DataFrame row shape; Delta-only declarations do not install table metadata. A verified generated, identity, or literal-default column may be omitted where the pinned Delta API supports it. An unverified or mismatched declaration never suppresses a required-field error. No compiler path silently sets session-wide `spark.databricks.delta.schema.autoMerge.enabled`.

Restore acceptance checks current and result schemas, table object identity, a fresh commit in `delta_history`, and CDF visibility for changed rows. Optimize acceptance checks both compaction and Z-order, unchanged logical rows, and an OPTIMIZE history entry. Vacuum acceptance checks default 168-hour behavior, explicit short-retention opt-in, native retention safety, actual deletion of eligible files on a disposable table, current-table validity after deletion, and expected loss of old time travel. Native failures retain their exception types and gain transform/step context. Earlier committed effects are not rolled back after a later failure.

The API compatibility ledger must describe each helper's subset and metrics limitation. Live PySpark 4.1.0/Delta 4.1.0 evidence is required for a supported row; until then retain `implemented; release-gated` or a narrower status. The final `make build` and `git diff --check` must pass. Do not count skipped integration tests as successful live parity.

## Idempotence and Recovery

Compilation and history/detail reads do not change table state. Repeating restore, optimize, or vacuum can create a new commit or delete more files, so never retry an uncertain native result automatically. Each live test creates its own temporary table path; the vacuum test verifies that path before disabling Delta's native retention guard in its private session and restores the configuration afterward. If a live test fails after a commit, discard that disposable path and rerun with a new one rather than attempting an inverse write. Preserve user and shared table paths. If the pinned environment cannot run, complete Spark-free code and documentation, leave affected compatibility rows gated, and record the missing evidence in this plan.

## Artifacts and Notes

The intended typed inspection shape is:

    class OrderCommit(Schema):
        version = long(nullable=False)
        operation = string()

    class RecentOrderCommits(Transform):
        orders = delta_input(Order)
        limit = variable(int, default=10)
        commits = output(OrderCommit)

        def read(self, order: Order) -> OrderCommit:
            return delta_history(order, limit=self.limit)

The intended maintenance shape is:

    class RestoreOrders(Transform):
        current = delta_input(OrderV2)
        restored = delta_output(OrderV1)
        version = variable(int)

        def restore(self, order: OrderV2) -> OrderV1:
            return delta_restore(order, version=self.version).execute()

    class CompactOrders(Transform):
        orders = delta_table(Order)

        def compact(self, order: Order) -> None:
            delta_optimize(order).execute_compaction()

    class VacuumOrders(Transform):
        orders = delta_table(Order)

        def vacuum(self, order: Order) -> None:
            delta_vacuum(order, retention_hours=168).execute()

These examples omit imports and caller-created tables for brevity. The implementation must put complete runnable examples in public docs and tests. A short-retention example belongs only in a clearly isolated test with `allow_short_retention=True` and Delta's native safety override explicitly set by that test.
