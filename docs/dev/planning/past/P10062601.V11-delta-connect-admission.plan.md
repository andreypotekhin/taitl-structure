# Admit Delta Connect without a metadata bridge

This completed ExecPlan follows `docs/dev/auto/Plans.md`. Its acceptance evidence is recorded below.

## Purpose

Admit the existing Delta table API for the exact PySpark `>=4.1,<4.2`, `spark-connect` target. Online and generated transforms should use the same native Delta Connect semantics as direct writes. Structure uses `Schema.delta_columns` for typing and omitted writer fields; Delta computes generated, identity, and default values or rejects invalid writes. Connect does not promise an exact pre-write comparison between declarations and table feature metadata. Ordinary PySpark retains that comparison.

## Surprises & Discoveries

- The ordinary validator reads generated and identity metadata from the client JVM's Delta log because their `toDF().schema` metadata is empty in the pinned classic test. Connect has no client JVM.
- Before the change, binding called `fresh_delta_frame` once per validation mode and again for execution. The shared frame now serves validation and execution.
- Delta's native [generated and identity rules](https://docs.delta.io/delta-batch/) and [default rules](https://docs.delta.io/delta-default-columns/) already govern omitted columns.
- The first live server loaded Delta Connect's older transitive Protobuf Java and failed its first `detail()` response with `MapFieldReflectionAccessor` missing. Pinning Protobuf Java 4.33.0 alongside the 4.1 server artifact fixed it.
- Expanded live runs lost the server after Docker's 6 GiB host filled its swap while other integration lanes ran concurrently; the shell reported `spark-submit ... Killed`. A nonconcurrent run with a 2 GiB driver override passed. The lane retains the existing 3 GiB default.
- An ordinary 4.1 run's general V11 process first stopped with Docker `unexpected EOF` after its Delta module passed. A later full rerun passed both processes without changing application code.

## Context

The DSL lives in `src/structure/plugin/pyspark/delta/`; `PySparkCapabilities.py` grants target-profile capabilities. `LowerPySparkPlan.py` and `MapPySparkStep.py` enforce them before execution or rendering. Online and generated execution share `delta/runtime.py`. The ordinary validator uses `_delta_log_field_metadata` and client JVM internals. Before this work, the integration matrix had ordinary PySpark 4.1 and Connect 3.5/4.0, but no Connect 4.1.

## Validation and Acceptance

The Connect lane must report the pinned 4.1 pair and execute, without feature skips, binding, CHECKs, declared generated/identity/default fields, delete, update, merge clauses, append, selective overwrite, schema evolution, snapshot, CDF, history, detail, restore, optimize, and vacuum. Online and generated results should match native direct Delta outcomes. Wrong declarations are allowed through Structure's Connect preflight; native Delta may reject the write, or may write values different from the declaration. Tests must record both outcomes. Unsupported Connect 3.5, 4.0, broad default, and 4.2 targets must fail during compilation. Ordinary PySpark regression tests must still reject declaration drift.

Connect must issue no feature-metadata bridge request and refresh only once at binding. Record remote-call counts and elapsed times against direct Delta writes. `make build` is required at the end of this coding task. Do not claim live admission if its lane is unavailable or skipped; record the infrastructure limit and leave this plan active.

## Idempotence and Recovery

Use uniquely named disposable Delta tables. Keep native vacuum retention safeguards. A post-commit error does not roll back Delta, so failure cases use separate tables. Do not delete user changes or a warm Ivy cache for recovery.

## Interfaces and Dependencies

Public helper signatures stay unchanged. `validate_delta_table(table, schema, *, mode="expression")` keeps returning the caller's handle. Internal binding may use a helper that returns the refreshed DataFrame. The Connect server needs Spark 4.1/Delta 4.1 packages and extensions; no Structure metadata transport or client filesystem access is required.

## Outcomes & Retrospective

The exact `>=4.1,<4.2` Connect capability admits every Delta helper. Binding accepts native Delta Connect handles,
validates table shape and declared CHECKs, refreshes once, and reuses that frame in online and generated execution.
Connect never requests `_delta_log_field_metadata`; ordinary PySpark retains the exact feature comparison.

`STRUCTURE_SPARK_CONNECT_DRIVER_MEMORY=2g make integration BACKEND=spark-connect41` passed on pinned PySpark 4.1.0 /
Delta 4.1.0: 33 Delta tests passed, one ordinary-only JVM inspection test skipped; the V11 selection passed five and
skipped nine unrelated Connect exclusions. The Delta suite covered online/generated operations, direct native writes,
deliberately wrong generated/identity/default declarations, and native CHECK failures. The ordinary PySpark 4.1 Delta
module passed 31 tests with three Connect-only skips, including exact generated, identity, and default metadata drift
regressions. Its general V11 selection passed 14 tests on a full rerun.

One instrumented Connect binding on a generated-column table made one execution request, two analysis requests, and
one table refresh in 2.171 seconds. A direct Delta append made one execution request, no analysis requests, and no
Structure refresh in 0.474 seconds. These are single local observations of different operations, not a speed
comparison. The instrumented binding also asserted that no feature-metadata bridge request occurred. The focused test
passed; its wrapper exited 5 because the same `-k` selection deselected every test in the runner's subsequent V11
process. The complete lane above exited successfully.

`make build` completed successfully: the primary suite passed 2,258 tests with 288 skips, the additional golden and
compatibility suite passed 110 with seven skips, and the source distribution and wheel built. The skips belong to
optional live environments and unrelated feature lanes. No speedup is claimed from the request-count observation.
The annotated-source guidance points to an absent `docs/dev/Annotation.auto.md`, and this checkout has no annotated
source tree to update.
