# Allow string addition in the PySpark DSL

This ExecPlan is maintained according to `docs/dev/auto/Plans.md`. Keep Progress, Surprises & Discoveries,
Decision Log, and Outcomes & Retrospective current as work proceeds.

## Purpose / Big Picture


Users can write `"order:" + row.order_id` and `row.first + " " + row.last` in compiled transforms. String addition
uses the existing typed concatenation operation and produces native Spark expressions in both direct execution and
generated Python. Numeric addition retains its existing behavior. No Python user-defined function is introduced.

This follows Python's string concatenation and rejection of mixed string/numeric operands, with Spark's propagation
of null values. Raw PySpark Column addition is arithmetic, not concatenation. Raw PySpark `concat` accepts numeric
columns too; Structure deliberately requires explicit conversion. Python also concatenates lists and bytes with `+`;
Structure continues to require `concat(...)` for arrays and binary expressions.

## Surprises & Discoveries


The existing `concat` helper already validates string types, computes nullability, records backend capability use,
and has execution and generated-code consumers. Reusing it avoids adding a second concatenation contract.
The annotation instructions moved from the AGENTS.md reference to `docs/dev/auto/prose/Annotation.prose.md`;
its selected source roots do not include the PySpark DSL or the tests changed here.

The new Expression-to-operations_api dependency changes mypy's circular-import resolution. Nine errors treated
package-exported classes as modules in body.py, InputScope.py, PySparkOperationRecipe.py, and one downstream consumer.
A clean mypy run with `--shadow-file` substituting the original Expression.py passed all 1248 files, confirming the
dependency change caused the errors. Import those classes from their defining modules to remove the ambiguity.
The next check exposed the same ambiguity for StreamingSupport in ClassifyStreamingCompatibility.py. Applying the
same defining-module import there made a clean full mypy run pass all 1248 files.
The sandboxed full build hit the existing Windows pytest temporary-directory permission issue documented in
`docs/dev/Troubleshooting.md`. The affected source-discovery test reproduced that setup error. The build process was
stopped and restarted with approved elevated access; no unrelated source changes were needed.
The first complete pytest pass found one existing assertion expecting the former generic numeric error for an
integer-plus-string expression. Its behavior remains rejection; the test now checks the new actionable String-typing
error. The next full run passed 1,837 tests with 69 skips in 718.49s. The rigidity run passed 73 with 7 skips in
361.60s. Mypy passed for all 1,248 source files, lint passed, and Poetry built both sdist and wheel.

## Decision Log


Decision (2026-09-16, Codex): Add string-only operator syntax without implicit casts or special handling of bare
`None`. Both operands must have String type; literals are converted using the existing `literal` helper. Typed null
strings, including `literal(None).cast(types.string())`, are accepted. A result is nullable if either operand is
nullable, and null at runtime if either value is null. This preserves the existing concat contract.

Decision (2026-09-16, Codex): Dispatch in Expression's addition methods and reuse `concat`; leave numeric arithmetic
and backend consumers unchanged. Preserve authored left/right order and nested chains without a new flattening pass.
This limits the change and retains existing capability checking and optimizer-visible expressions.

Decision (2026-09-16, Codex): Use defining-module imports for OperationPlan, WatermarkPlan, ExactlyOnePlan,
StreamingOutputMode, and StreamingSupport at the affected internal sites. This fixes the type-checker ambiguity without
changing public exports or introducing another concat implementation.

## Context and Orientation


Work from the repository root. The PySpark DSL is the Python interface for authoring expressions.
`src/structure/plugin/pyspark/dsl/Expression.py` implements `__add__` and `__radd__` using numeric `_arithmetic`.
`src/structure/plugin/pyspark/dsl/operations_api.py` defines `concat`, which creates a typed expression describing work
rather than executing Spark. Rendering and execution already translate this expression to PySpark `functions.concat`.
`tests/integration/pyspark/support/backend_matrix.py` supplies sessions, generated project loading, and Spark fixtures.
`tests/concepts/live_pyspark/` holds public tests comparing direct execution with generated execution on live Spark.
The shared scenario is `tests/helpers/string_addition.py`; its live test is
`tests/concepts/live_pyspark/test_string_addition_parity.py`.

## Validation and Acceptance


`"order:" + row.order_id` produces `"order:12"` for `order_id="12"`. Two string fields with values `"12"` and `"3"` produce
`"123"`, not numeric 15. A null string operand produces null. `coalesce(row.name, "") + "!"` produces `"!"` for
a null name. `"n=" + row.count.cast(types.string())` succeeds, but an uncast numeric operand, Boolean, binary, array,
or bare `None` fails during compilation. Existing numeric addition, widening, and other arithmetic operators continue to pass
the full build. New tests must also verify nullable results cannot be assigned to non-nullable output fields.

## Interfaces and Dependencies


Keep the existing signatures `Expression.__add__(self, other: object) -> Expression` and
`Expression.__radd__(self, other: object) -> Expression`. Existing numeric operand pairs retain arithmetic semantics;
two String operands gain concat semantics. The helper `concat` and its public contract remain unchanged. No extra
dependencies, configuration flags, or serialization expression kinds are introduced.
