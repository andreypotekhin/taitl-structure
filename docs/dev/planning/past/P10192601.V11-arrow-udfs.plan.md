# Implement V11 Arrow UDF support


This ExecPlan is a completed implementation record. Its planning history follows [Plans.md](../../auto/Plans.md).

Status: complete. Arrow UDF behavior, documentation, focused parity, regression coverage, and build pass. The ordinary full 4.1 lane retains one separately owned foreachBatch failure, recorded below. The governing release plan is [V11 PySpark 4.1 adoption](../P08042601.V11-pyspark-4.1-adoption.plan.md).

## Purpose / Big Picture


Users will be able to declare Spark 4.1 Arrow UDFs on a Transform and call them with typed Structure expressions. An Arrow UDF is a user Python function that processes Arrow arrays in Spark workers. Its body remains ordinary Python, while Structure records its input dependencies, declared SQL result, execution mode, and source owner. The same declaration must work through online execution and generated PySpark.

The contract covers scalar batches, scalar iterators, and grouped aggregates, including analytic aggregate windows. Ordinary and Spark Connect batch support require independent evidence on exact `>=4.1,<4.2` profiles. Ordinary scalar and iterator streaming require processed-data and checkpoint-restart parity. Grouped Arrow streaming and analytic windows on streaming inputs are rejected before execution because the pinned native runtime rejects them.

The default profile remains `>=3.5,<4.1`. Arrow UDTF, state processors, and foreach/foreachBatch interfaces remain separate work packages. No implementation is authorized by the creation of this document alone.

## Surprises & Discoveries


The PySpark 4.1.0 Arrow UDF reference contains contradictory keyword guidance: a Notes paragraph denies keyword arguments, while its examples demonstrate them. Native source inspection and actual ordinary 4.1 execution confirm that scalar and grouped Arrow calls accept named columns. Positional, reversed named, and mixed scalar calls each returned `11` for inputs `1` and `10`.

Ordinary Python parameters accept positional or keyword arguments unless the signature uses `/` or `*` to restrict them. Native scalar Arrow registration accepts `def f(a, *, b)` and a named call, but rejects `def f(*, a, b)` with `INVALID_PANDAS_UDF` and the message that zero-argument Arrow UDFs are unsupported. This is a Spark registration restriction, not invalid Python syntax. Preserve it with an early actionable diagnostic.

Native Arrow modes are exposed as `ArrowUDFType.SCALAR`, `SCALAR_ITER`, and `GROUPED_AGG`. Native creation has a Spark Connect path, but source availability does not establish Connect execution parity. Explicit native mode selection currently emits Spark's preference warning about annotations; mode selection must remain explicit in Structure, and that native warning must not be hidden by a global warning filter.

Ordinary grouped and analytic-window probes passed. Mixing an Arrow grouped aggregate with built-in `count()` failed with `INVALID_PANDAS_UDF_PLACEMENT`. A zero-argument grouped Arrow callback worked. A global Arrow aggregate over an input made empty by `limit(0)` returned no rows. Do not assume built-in aggregate empty-input cardinality; verify native behavior for actual empty sources and filtered inputs too.

Starting a streaming query was insufficient evidence. Scalar and iterator file-stream probes processed two batches correctly. A grouped Arrow query started, then failed on its first processed batch with `Streaming aggregation doesn't support group aggregate pandas UDF`. ## Decision Log


Decision (2026-10-19, user and Codex): Add `@special(type="arrow_udf")` rather than an execution flag on `type="udf"`. Arrow callbacks receive arrays or iterators, whereas the existing scalar Python UDF receives individual Python values. The declaration must make that contract visible.

Decision (2026-10-19, user): Include all native modes in the first implementation. Use explicit `function_type` strings, defaulting to `"scalar"`, with `"scalar_iter"` and `"grouped_agg"` alternatives. Annotations are optional and do not select the mode.

Decision (2026-10-19, user): Obtain SQL input types from typed call arguments. Require an explicit Structure `return_type`; an Arrow array annotation does not identify its SQL element type. Keep `nullable=True` as the default author declaration.

Decision (2026-10-19, user): Preserve Spark's return behavior. Structure validates declarations and calls during compilation, but does not execute callback bodies, inspect returned values, perform nested nullability scans, or add a strict-validation option. This avoids runtime validation overhead and preserves native conversions and errors.

Decision (2026-10-19, user and Codex): Follow native positional, named, and mixed calling behavior for scalar/grouped modes, respecting Python signatures and Spark restrictions. Iterator columns remain positional. The grouped call's `over` keyword is reserved for a typed Structure window, as selected during design.

Decision (2026-10-19, user and Codex): Make `deterministic` optional. Omission uses Spark's deterministic default. Explicit `True` declares that default, and `False` applies the public `asNondeterministic()` method. Supplied values must be Boolean; no body-based inference or new configuration setting is introduced.

Decision (2026-10-19, user and Codex): Seek separate ordinary and Connect 4.1 batch admission and ordinary streaming evidence. Reject native-ineligible grouped and analytic-window streaming with `STREAM-E0801`. Iterator-local initialization/state has no checkpoint persistence guarantee.

## Interfaces and Dependencies


The minimal declaration on a Transform is:

    @special(type="arrow_udf", return_type=double())
    def multiply(value, weight):
        import pyarrow.compute as pc
        return pc.multiply(value, weight)

`function_type="scalar"` and `nullable=True` are optional defaults. `deterministic` is also optional and is normally omitted. Supplying `deterministic=False` declares a native nondeterministic UDF; it does not seed randomness or make worker behavior reproducible.

Scalar callbacks receive one Arrow array for each supplied column and return an array of the same batch length. Iterator callbacks receive one iterator argument: its items are arrays for one input column or tuples of arrays for multiple input columns. Their output is an iterator of arrays preserving total row count, while native Spark governs batch boundaries and checks. A grouped callback receives arrays for its supplied columns and returns one native-supported Python, NumPy, or Arrow scalar. Compound SQL results may be arrays, maps, or structs where native Arrow conversion supports the declared Structure type.

Scalar and grouped calls accept positional and keyword expression arguments, including valid mixtures. Preserve argument names rather than guessing argument order. Validate binding with the Python signature, including defaults, `/`, `*`, and duplicate/unknown names. Do not turn callback Python default values into extra broadcast columns. Iterator calls accept one or more positional column expressions, but validate the callback against one iterator argument rather than the number of input columns. Permit zero-argument grouped callbacks where native registration permits them. Mirror the native scalar zero-positional-parameter restriction.

A grouped declaration uses `function_type="grouped_agg"`. `self.mean(row.value)` participates in grouped/global aggregation; `self.mean(row.value, over=rolling)` applies the existing typed `WindowSpec`. Only grouped mode accepts the Structure window argument. Diagnose a grouped callback parameter named `over` at declaration to avoid ambiguous binding. No new per-metric filtering keyword is introduced; other callback parameter names follow native calling rules.

Validate a callable's declaration, synchronous execution contract, supplied flags, mode, return declaration, and call signature without running its body. Python itself checks source syntax when modules are imported, and generated source must parse successfully. Reject coroutines and asynchronous generators. An iterator callback may be a synchronous generator or an ordinary function returning an iterator; do not require particular body syntax.

`return_type` must be a concrete Structure type. Existing schema/profile restrictions still apply, and Spark remains responsible for Arrow conversion support and runtime results. Input nulls reach the callback under native behavior; there is no automatic null-skipping wrapper. `nullable` is an author-supplied DSL contract, while physical Spark UDF schema nullability remains native. Preserve native failures for return length, type conversion, callback exceptions, and unsupported result types.

Use public `pyspark.sql.functions.arrow_udf`, `ArrowUDFType`, and `UserDefinedFunction.asNondeterministic()`. Map the three explicit Structure mode strings to the corresponding enum members. Omission or explicit `True` needs no determinism override; only `False` applies `asNondeterministic()` before use. Do not introduce a mandatory PyArrow dependency for compiler imports. Callers provision native worker dependencies and callback packages; use the existing pinned integration image and native dependency checks.

Add independently admitted capabilities `expression.arrow_udf_scalar`, `expression.arrow_udf_scalar_iter`, `aggregate.arrow_udf_grouped_agg`, and `window.arrow_udf_grouped_agg`, gated to exact `>=4.1,<4.2` ordinary/Connect profiles with positive evidence for each. Earlier and later profiles remain rejected. Connect streaming remains outside the existing backend contract.

## Validation and Acceptance


A Transform using only `@special(type="arrow_udf", return_type=double())` must compile as scalar mode without supplying `deterministic`. Omitting determinism and explicitly declaring `True` must retain Spark's default; explicit `False` must produce the public native nondeterminism call. Invalid supplied flags or malformed calls must fail during compilation with the helper location and a corrective example.

For a Long addition callback with inputs `1` and `10`, positional, reversed named, and mixed calls must all return `11` in native, online, and generated execution. A scalar callback with one ordinary parameter and one keyword-only parameter must work where native Spark works; an entirely keyword-only scalar callback must receive an early explanation of the native registration restriction.

For grouped means over `(key=1,value=1.0)`, `(1,3.0)`, and `(2,5.0)`, expected grouped results are `2.0` and `5.0`. An ordered trailing-two-row window produces `1.0`, `2.0`, and `5.0`. Mixed built-in/Arrow aggregation is rejected early. Empty/global cases match the corresponding native plan's cardinality and values without fabricated rows.

Ordinary scalar and iterator streams processing values `[1,3]`, then `[5,9]`, through an increment callback produce `[2,4]`, then additionally `[6,10]`. Restart checks must preserve committed progress under the same configuration without claiming persistence of Python iterator-local state. Grouped and analytic-window streaming fail at compilation, before source/sink/query lifecycle is started.

Completion requires exact-profile capability rejection tests, all claimed online/generated/native runtime cases, shared regressions, documented full-lane outcomes without hidden failures, synchronized public and machine-readable records, generated-source safety, and successful `make build`. No support is inferred from design probes, source inspection, startup alone, or a different backend's success.
