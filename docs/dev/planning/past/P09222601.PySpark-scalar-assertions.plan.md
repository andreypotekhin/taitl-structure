## Purpose / Big Picture

Users can add compiler-visible PySpark failure guards directly to a Structure predicate. For example,
`where(assert_true(order.total > 0, message="total must be positive"))` preserves rows when every reached row has a
positive total and raises Spark's error when a reached row is non-positive or null. `raise_error("...")` provides an
intentional, unconditional failure expression. The expressions work the same in generated source and online execution;
they do not create an output field or run a Python-side action.

## Decision Log

- Decision: expose only `assert_true` and `raise_error` in this slice; do not add `assert_false`, `assert_equal`, or
  relation-level aliases.
  Rationale: these are the native PySpark baseline primitives. Existing comparisons and `~` compose into the omitted
  forms, while relation assertions have different all-rowset semantics.
  Date/Author: 2026-09-22 / Codex and user.
- Decision: return a non-null Boolean guard that lowers to native assertion output followed by `.isNull()`.
  Rationale: native `assert_true` returns null on success, but a Boolean result lets users place a guard directly in
  `where(...)` without adding an output field. It still throws exactly when Spark evaluates a failed native assertion.
  Date/Author: 2026-09-22 / Codex and user.
- Decision: accept an optional Python string literal `message`; do not accept a message expression.
  Rationale: deterministic authored diagnostics are the requested contract. Dynamic Spark columns can be considered in
  a later parity expansion.
  Date/Author: 2026-09-22 / Codex and user.
- Decision: admit scalar guards in caller-owned streaming transformations.
  Rationale: both lower to Spark SQL expressions and do not create Structure-managed state. A failure belongs to the
  caller's active Spark evaluation or micro-batch.
  Date/Author: 2026-09-22 / Codex and user.

## Context and Orientation

`src/structure/plugin/pyspark/dsl/expressions.py` constructs immutable, typed `Expression` objects during symbolic
authoring. `MapPySparkExpression` maps them into immutable recipes after checking target capabilities.
`RenderPySparkExpression` renders recipes into readable generated `pyspark.sql.functions as F` calls, and
`EvaluatePySparkExpression` executes the same recipes against a live `F` module for online execution. The root
`structure.plugin.pyspark` package re-exports DSL names through its `_DSL_EXPORTS` and `__all__` lists.

PySpark's `assert_true(condition, errMsg)` returns null when `condition` is true and otherwise raises a Spark error.
`raise_error(errMsg)` always raises. Structure will adapt both to Boolean expressions by rendering or evaluating their
native result followed by `.isNull()`: successful `assert_true` therefore yields `True`; failed assertions never return.
This is a typed convenience surface, not a claim that native PySpark returns Boolean.

The existing relation helpers in `dsl/relation_sets.py` remain separate. They create lazy aggregate guards that attempt
to validate a whole relation, while scalar assertions are evaluated only for rows reached by Spark's plan.

## Plan of Work

as a raw string fragment or a Python action.

Extend both rendering paths with one direct branch each so source uses the exact native function followed by `.isNull()`.

## Validation and Acceptance

Compilation must accept `where(assert_true(row.total > 0, message="total must be positive"))`, render
`F.assert_true((F.col("rows.total") > F.lit(0)), 'total must be positive').isNull()`, and report a Boolean,
non-null expression type. It must reject a non-Boolean condition and non-string message before Spark starts.
`raise_error("stop")` must render `F.raise_error('stop').isNull()` and reject a missing or non-string message. A streaming
transform containing the successful conditional guard must remain compatible. Existing relation assertions and their
batch-only classification must remain unchanged.

## Interfaces and Dependencies

The public signatures are:

    def assert_true(condition: object, *, message: str | None = None) -> Expression
    def raise_error(message: str) -> Expression

Both return `Expression(kind="assertion", type=BooleanType(), nullable=False, ...)`. They require the shared
`expression/assertion` PySpark capability, which belongs to the ordinary and Spark Connect baseline profile. They use
only public `pyspark.sql.functions.assert_true` and `raise_error`; no Python UDF, DataFrame action, Spark internals, or
new dependency is permitted.
