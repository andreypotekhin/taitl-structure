## Purpose / Big Picture

A caller can already supply a native Delta table to a Structure transform and run typed mutations. This increment lets a transform read a historical snapshot or a bounded batch change data feed (CDF), use values that vary between runs without compiling a new artifact for each value, and perform a selective overwrite with an explicit commit call. For example, two invocations of one compiled `ReadOrderChanges` transform can read different version ranges by binding different `variable()` values. A separate streaming example passes a caller-created Delta CDF stream through a typed Structure transform.

The observable result is a typed output DataFrame containing the selected snapshot or CDF events, an unchanged compiled artifact key across different variable bindings, and a Delta table whose selected rows were replaced after `delta_replace_where(...).execute()`. Delta support remains release-gated until the wider V11 PySpark 4.1 matrix is admitted. The first live evidence uses ordinary PySpark 4.1.0 and `delta-spark` 4.1.0, without claiming Spark Connect support.

## Surprises & Discoveries

- Observation: `parameter(default)` stores a bound Python value in the compiled artifact key and can shape Python control flow during symbolic compilation. `variable()` must instead put a typed reference in the compiled plan and pass the bound value only to execution. Evidence: `src/structure/core/dsl/model/transforms/ParameterDeclaration.py`, `src/structure/core/compiler/artifacts/commands/BuildCompiledTransform.py`, and `docs/reference/Transform.ref.md`.
- Observation: `Transform.__init__` recognizes declared relation inputs and parameters, while step parameters are currently Schema relations or sinks. Accessing a declared variable through `self.field` avoids adding scalar step-argument resolution. Evidence: `src/structure/core/dsl/model/transforms/Transform.py` and `src/structure/core/compiler/frontend/commands/CompileTransform.py`.
- Observation: generated execution forwards only bound relation inputs today. A reusable generated artifact needs a separate variable argument channel; baking values into emitted Python would recreate specialization. Evidence: `src/structure/plugin/pyspark/execution/commands/RunGeneratedPySparkTransform.py` and `src/structure/plugin/pyspark/render/logic/modules/RenderPySparkTransformModule.py`.
- Observation: `param_join(policy)` checks singleton cardinality and joins a relation inside a Spark plan. Delta reader options such as `startingVersion` require driver values before that plan is built, so `param_join` cannot directly supply them. Evidence: `src/structure/plugin/pyspark/dsl/InputScope.py`, `src/structure/plugin/pyspark/execution/logic/PolicyChecks.py`, and Delta CDF's reader-option API.
- Observation: batch CDF endpoints are inclusive; only changes after CDF was enabled are available. `delta.enableChangeDataFeed=true` is a table property, while the Spark Delta extension/catalog are session setup. Evidence: `https://docs.delta.io/delta-change-data-feed/` and `https://docs.delta.io/quick-start/`.

## Decision Log

- Decision: Create a separate `VariableDeclaration` and public `variable(type, default=...)` rather than rename or alter `ParameterDeclaration`. A variable is bound on the transform invocation, accessed as `self.field`, and forwarded through composed stages. Rationale: preserve existing compile-time `parameter()` behavior while supporting reusable artifacts. Date/Author: 2026-10-05 / user and Codex.
- Decision: A variable can be used in typed Spark expressions and Delta read selectors. It cannot drive Python `if`, change graph shape, or include/exclude operations; those uses require `parameter()`. Rationale: a single compiled artifact cannot have a different Python method body for each runtime value. Date/Author: 2026-10-05 / user and Codex.
- Decision: First-release variable values are Spark scalars: `bool`, `int`, `float`, `str`, `bytes`, `Decimal`, `date`, `datetime`, and optional `None`. Rationale: these have typed Spark literal representations and practical Delta selector uses; arbitrary Python objects remain `parameter()` values. Date/Author: 2026-10-05 / user and Codex.
- Decision: Bind version or timestamp selectors on each invocation, not in a policy DataFrame or mutable class attribute. Rationale: this puts selection in transform code and avoids driver collection from a policy relation and stale artifact keys from class mutation. Date/Author: 2026-10-05 / user and Codex.
- Decision: Batch `delta_changes` has a required start and optional end, with version and aware-datetime timestamp forms. `delta_snapshot` has one required version or timestamp. The output Schema is selected by the method return type. Rationale: match typed transform data flow and Delta's native reader options. Date/Author: 2026-10-05 / user and Codex.
- Decision: `delta_replace_where(target, source, where=...).execute()` is a builder that commits a same-schema selective overwrite. Rationale: `.execute()` matches existing merge/append builders and clearly marks the side effect. Date/Author: 2026-10-05 / user and Codex.
- Decision: Streaming CDF remains a native caller-created `readStream` DataFrame bound to `input(Change, streaming=True)`. Structure transforms its rows and the caller owns `writeStream`, checkpoint, and lifecycle. Rationale: retain Structure's streaming boundary while showing a complete typed example. Date/Author: 2026-10-05 / user and Codex.

## Interfaces and Dependencies

Export `variable` from `structure`, backed by `VariableDeclaration` under `src/structure/core/dsl/model/transforms/`. The factory signature is `variable(type: type | UnionType, *, default=UNSET, precision: int | None = None, scale: int | None = None)`. `variable(int)` is required; `variable(int | None, default=None)` permits null. For `Decimal`, require explicit valid precision and scale, such as `variable(Decimal, precision=18, scale=2)`, and reject values that do not fit without rounding. Fix the Spark type at declaration: `int` maps to `BIGINT`, `float` to `DOUBLE`, and the other supported Python types to their corresponding Spark scalar types. This prevents the inferred type from changing when an integer crosses the 32-bit boundary. A supplied override with the wrong type fails at invocation construction; a missing required binding fails before step execution. `bool` is not accepted as an `int`; reject `bytearray` rather than silently normalizing it. `None` is legal only when declared optional. Store an invocation's bound variables separately from relation inputs and compile-time parameters. Do not allow post-construction assignment to change a bound variable; make a new invocation for a new value.

Inside symbolic compilation, `self.field` for a variable yields a typed variable reference. Outside compilation it yields that invocation's concrete value. Teach PySpark expression conversion, validation, online evaluation, and generated rendering to lower references as runtime literals with the declared Spark type. This must work on either side of supported expression operators and in `where`, projection assignments, `when`, and join predicates. The same reference may appear in a Delta read option, where execution uses the validated driver value directly. Its Boolean conversion in Python fails with a diagnostic directing the author to `parameter()` for compile-time branching or a typed expression for row-level branching. Literal-only structural options that cannot be deferred must reject variable references explicitly. A variable forwarded as a child stage argument remains a variable reference in the composed plan and receives the parent invocation's bound value at execution. Preserve the current meaning of `parameter(default)` and its cache behavior.

Export `delta_snapshot(table, *, version=None, timestamp=None)` and `delta_changes(table, *, starting_version=None, starting_timestamp=None, ending_version=None, ending_timestamp=None)` from `structure.plugin.pyspark`. Both accept only a `delta_input` relation and return a relation-producing symbolic result whose Schema is the method's declared ordinary `output(Schema)` return. `delta_snapshot` requires exactly one selector. `delta_changes` requires exactly one start; an end is optional and must use the same selector kind as the start. Versions are nonnegative `int` values excluding `bool`; reject an end before the start. Timestamps are timezone-aware Python `datetime` values; reject naive values and an end before the start. Convert aware instants into the active Spark session time zone when formatting native reader options, so non-UTC sessions select the same instant. An omitted CDF end asks Delta for the latest available changes. Use native `spark.read.format("delta")` with `versionAsOf` or `timestampAsOf` for snapshot and `readChangeFeed=true` with inclusive `startingVersion`/`endingVersion` or timestamp options for CDF. Obtain the path of the caller-bound Delta table at execution, not compilation. Validate the current bound table against its `delta_input` Schema and validate the produced DataFrame against its declared output Schema; historical schemas may differ from the current one. Do not claim catalog-managed or Spark Connect behavior without separate live evidence.

Export `delta_replace_where(target, source, *, where)` from `structure.plugin.pyspark` as an immutable builder with `.execute()`. The target must be a same-schema `delta_output`, the source a batch relation with the same output shape, and `where` an explicit typed Boolean expression over target fields only. `where=True` means an intentional whole-table replacement; reject an omitted predicate. Render the predicate to the native writer's `replaceWhere` SQL option using the existing safe expression renderer, then write the source with `format("delta").mode("overwrite")` to the bound table path. Keep Delta's default check that written rows satisfy the predicate. Do not enable `overwriteSchema`, `mergeSchema`, or session-wide schema evolution. Validate table shape and CHECK metadata before the commit and exact declared shape afterward; return the caller's original table handle through the existing effect-output contract. Native failures preserve their exception type and gain transform/step context.

## Idempotence and Recovery

Compiling and reading are repeatable. Snapshot/CDF reads return lazy Spark DataFrame plans whose actions may occur later; constructing a new transform invocation never changes an earlier invocation's bound variables. CDF availability depends on table history and retention. Selective overwrite is a native commit, so use disposable tables in tests, do not automatically retry an uncertain commit, and report partial completion if an earlier effect committed before a later failure. Keep user-created tables and properties caller-owned. ## Artifacts and Notes

The intended batch authoring shape is:

    from structure import Schema, Transform, input, output, step, transform, variable
    from structure.plugin.pyspark import (delta_changes, delta_input,
                                          delta_replace_where, long, string, timestamp, where)

    class Order(Schema):
        id = string(nullable=False)
        status = string(nullable=False)

    class OrderChange(Schema):
        id = string()
        status = string()
        change_type = string(alias="_change_type")
        commit_version = long(alias="_commit_version")
        commit_timestamp = timestamp(alias="_commit_timestamp")

    @transform
    class ReadOrderChanges(Transform):
        orders = delta_input(Order)
        start_version = variable(int)
        end_version = variable(int | None, default=None)
        changes = output(OrderChange)

        def read(self, order: Order) -> OrderChange:
            return delta_changes(order, starting_version=self.start_version,
                                 ending_version=self.end_version)

    first = ReadOrderChanges(orders=table, start_version=18).run(session).changes
    second = ReadOrderChanges(orders=table, start_version=24).run(session).changes

The matching streaming recipe is a different transform. The caller supplies the CDF stream; the transform only handles rows:

    @transform(streaming=True)
    class SelectOrderUpdates(Transform):
        changes = input(OrderChange, streaming=True)
        updates = output(OrderChange)

        def select(self, change: OrderChange) -> OrderChange:
            where(change.change_type == "update_postimage")
            return OrderChange.project(change)

    stream = (spark.readStream.format("delta").option("readChangeFeed", "true")
              .option("startingVersion", 18).load(orders_path))
    updates = SelectOrderUpdates(changes=stream).run(session).updates
    query = (updates.writeStream.format("parquet")
             .option("checkpointLocation", checkpoint_path).start(updates_path))

The overwrite effect is explicit:

    @step(input=(replacements, orders), output=orders)
    def replace(self, replacement: Order, order: Order) -> None:
        delta_replace_where(order, replacement, where=order.region == "west").execute()
