# Expose composed stage outputs through a guarded result tree

This ExecPlan is a living document. It follows `docs/dev/auto/Plans.md`; the `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` sections must remain current throughout implementation.

## Purpose / Big Picture

`SearchDocuments` currently returns its ranked document relation plus query/document embeddings and inference-status relations. The latter relations are useful because callers persist cache additions and inspect inference failures, but they are not search results. They should not occupy the transform's primary output namespace or require every composed wrapper to repeat them as public declarations.

After this change, `SearchDocuments` has one top-level output, `results`. Callers can still access the declared outputs of its composed stages through a read-only recursive result tree, for example `result.vectorized.query_embeddings` and `result.vectorized.query_inference_status`. The same tree is available in online and generated PySpark execution. Stage access is allowed by default and can be disabled with `allow_stage_outputs=False` without changing final-result computation.

## Surprises & Discoveries

- Observation: `SearchDocuments` re-declares five outputs from `OnlineVectorization` because current composition only permits child outputs to escape through wrapper `output(...)` declarations.
  Evidence: `examples/search/transforms/searching/search_docs/SearchDocuments.py` declares `results`, two embedding outputs, and two inference-status outputs; `ComposedHookOwnership.design.md` explicitly leaves exposing earlier-stage outputs deferred.
- Observation: the existing `TransformResult` mapping is intentionally limited to final declared outputs and is used by both online and generated runners.
  Evidence: `RunOnlinePySparkTransform` and `RunGeneratedPySparkTransform` build results from `plan.outputs`, while `TransformResult.as_dict()` returns exactly those mappings.
- Observation: stage frames already exist in flattened composed plans, so exposing them can be implemented as metadata and result packaging rather than a second execution path.
  Evidence: `ComposeTransformGraph` rewrites each child output to a stable stage-prefixed frame, and downstream stages consume those rewritten frames.
- Observation: cache output semantics must remain unchanged in this slice.
  Evidence: `OnlineVectorization.query_embeddings` and `document_embeddings` are the merged policy-compatible relations consumed by scoring, not a new inference-delta relation.
- Observation: the documented `make gold` command uses a POSIX `PYTHONPATH` separator and fails on Windows before running the generator.
  Evidence: `make gold` failed with `ModuleNotFoundError: No module named 'helpers'`; invoking the same generator with `sys.path` entries for `.`, `src`, `tests`, and the iterable plugin completed successfully.
- Observation: exposing recursive declared outputs increases generated source size because every declared child output is materialized at the result boundary.
  Evidence: the regenerated Search artifact now includes stage records for the declared stage tree, while the golden suite still passed all 17 tests.

## Decision Log

- Decision: Make `results` the only top-level `SearchDocuments` output.
  Rationale: ranked results are the transform's primary product; embeddings and statuses are cache/operational artifacts and should not require wrapper-level output duplication.
  Date/Author: 2026-08-26 / user and Codex.
- Decision: Expose stage outputs through `result.<stage>.<output>` and `result.stages["<stage>"]["<output>"]`.
  Rationale: dot access is natural for authored stage names, while the mapping form supports dynamic stage/output names without flattening or collision-prone aliases.
  Date/Author: 2026-08-26 / user and Codex.
- Decision: Expose declared outputs recursively, but never lanes or hook frames.
  Rationale: child `output(...)` declarations are stable transform contracts; lanes and hook frames are implementation details whose exposure would make internal refactors breaking API changes.
  Date/Author: 2026-08-26 / user and Codex.
- Decision: Add `allow_stage_outputs`, defaulting to `True`.
  Rationale: preserve the convenient default while allowing strict final-output-only deployments to avoid returning stage namespaces. The option must affect artifact fingerprints because generated result packaging changes with it.
  Date/Author: 2026-08-26 / user and Codex.
- Decision: Remove the old auxiliary top-level `SearchDocuments` names immediately.
  Rationale: retaining them permanently would preserve the duplication this contract is intended to remove, and the user selected an immediate migration rather than a deprecation period.
  Date/Author: 2026-08-26 / user and Codex.

## Context and Orientation

The Search example is under `examples/search`. `SearchDocuments` composes `OnlineFiltering`, `OnlineVectorization`, `OnlineScoring`, `RetrieveDocuments`, `FuseDocuments`, and `RerankDocuments`. The child stages produce intermediate relations used by later stages. Today only wrapper-declared `output(...)` fields are returned from a transform invocation; intermediate `lane(...)` fields never leave their declaring transform.

The compiler represents a transform as `TransformPlan`, which contains inputs, flattened steps, and final `OutputPlan` records. Composition rewrites child frames with stable stage prefixes. The PySpark plugin lowers those plans to `PySparkExecutionPlan`; both the online runner and generated runner then construct `TransformResult` from the final output recipes. The implementation must preserve this execution model while adding enough recursive stage metadata for result assembly.

## Plan of Work

1. Add a core stage-result model. Introduce a read-only stage namespace with mapping lookup, attribute lookup, per-stage `schema`, and nested `stages`. Keep canonical output iteration and `as_dict()` limited to final outputs. Stage aliases remain lookup synonyms, just as they are for final results.

2. Extend compiler IR metadata. Add recursive stage descriptors containing authored/pipeline stage names, declared output descriptors, nested stage descriptors, source frame names, schemas, aliases, and validation information. Update `ComposeTransformGraph` and `ComposeTransformPlans` to preserve and rewrite this metadata while flattening plans. Do not add lanes or hook frames to the descriptor tree.

3. Extend PySpark plan lowering and execution. Carry stage descriptors into `PySparkExecutionPlan`, map their output recipes through the same source-frame and schema logic as final outputs, and let both runners assemble the same `TransformResult`/stage tree. If `allow_stage_outputs` is false, omit stage packaging while retaining final output assembly.

4. Define injected-executor behavior. A composed plan with stage exposure enabled must receive a stage-aware `TransformResult` from an injected online executor; a plain DataFrame remains valid for a transform with no stage descriptors. Produce an actionable error when an injected executor cannot satisfy the stage contract.

5. Add `allow_stage_outputs` to the configuration defaults, TOML/programmatic resolution, validation, `StructureConfig`, `CompilerOptions`, compiler settings, artifact fingerprints, generated configuration, and configuration reference docs. Disabled access returns final outputs only; attempting `result.vectorized` raises an actionable attribute error explaining how to enable the option.

6. Update `SearchDocuments` to remove `online_query_embeddings`, `online_document_embeddings`, `query_inference_status`, and `document_inference_status` declarations. Update SearchFields, examples, README/spec/reference text, generated golden expectations, and any callers to use the recursive stage namespace. Regenerate generated files from source rather than editing them manually.

## Validation and Acceptance

Acceptance requires all of the following:

- `SearchDocuments(...).run(session).results` remains the ranked document relation.
- With default configuration, `result.vectorized.query_embeddings`, `result.vectorized.document_embeddings`, and both inference-status relations are available; nested paths such as `result.vectorized.merged_queries.embeddings` work where the child composition declares them.
- `result.stages["vectorized"]["query_embeddings"]` returns the same relation as dot access, and corresponding stage schemas are available.
- `list(result)` and `result.as_dict()` contain only `results` for `SearchDocuments`.
- `lane(...)` and hook frames cannot be accessed through the stage tree.
- `allow_stage_outputs=False` preserves final result behavior and removes stage access in both online and generated execution.
- Online and generated execution agree on final outputs, stage paths, schemas, aliases, and disabled-access behavior.
- `SearchFields` does not need to re-declare or forward SearchDocuments auxiliary outputs.
- Configuration changes alter compiler artifact fingerprints and invalid configuration values produce the project-standard configuration diagnostic.
- Focused tests pass, generated golden output is current, and `make build` completes with no unresolved failures.

## Interfaces and Dependencies

The new public interfaces are:

- `TransformResult.stages`: a read-only mapping of stage name to stage-result namespace;
- stage-result attribute and mapping lookup for declared child outputs;
- stage-result `schema` and nested `stages`; and
- `allow_stage_outputs: bool = True` in the standard Structure configuration.

The compiler/plugin boundary must carry recursive stage descriptors without making plugin implementations depend on Search-specific schemas. The PySpark plugin remains responsible for DataFrame materialization and validation; core remains responsible for stage identity and result structure. No new third-party dependency is required.
