# Add Compiled Transform Artifacts

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and
`Outcomes & Retrospective` must be kept up to date as work proceeds.

This document follows [Plans.md](../auto/Plans.md). It is self-contained so a contributor can implement reusable
compiled transform artifacts, generated transform artifacts, and reentrant transform execution without prior
conversation history.

## Purpose / Big Picture

Structure users should be able to catch compiler-class transform problems at application startup, before a rare batch
or rarely used branch reaches runtime. After this change, a user can call `EnrichOrders.compile()` to build and cache
the checked in-memory execution artifact for a transform class, call `EnrichOrders.generate()` to create runnable
generated Python artifacts in disk, package-import, or memory storage, and call `EnrichOrders(...).run(session)`
repeatedly with fresh DataFrames while reusing class-static compiled state.

The observable behavior is:

    EnrichOrders.compile(project_root=".")

    for batch in batches:
        result = EnrichOrders(
            orders=batch.orders,
            customers=batch.customers,
            products=batch.products,
        ).run(session)

The first line performs frontend compilation, target capability checks, PySpark lowering, and schema preparation once.
Each loop iteration creates a new invocation with fresh input DataFrames, but it reuses the already prepared artifact
for the transform class and compatible compiler options.

  Evidence: `src/structure/app/runtime/session/model/StructureSession.py` calls
  `Compiler.frontend.compile()`, `PySpark.plan.lower()`, and `Schemas.build()` inside `run(...)`.

- Observation: The current config resolver already has the desired option chain.
  Evidence: `src/structure/app/configuration/commands/ResolveStructureConfig.py` merges defaults,

- Observation: Generated project rendering currently iterates over transform classes rather than source modules.
  Evidence: `src/structure/app/cli/commands/RenderConfiguredPySparkProject.py` loops over `project.transforms` and
  calls `PySpark.render.project()` once per transform. This must be refactored for one artifact per source unit.

- Observation: Generated transform module paths already mostly follow source-module cardinality.
  Evidence: `src/structure/app/target/pyspark/commands/RenderPySparkProject.py` maps a source transform such as
  `orders.transforms.order.EnrichOrders` to `structure_generated/pyspark/transforms/order.py`.

- Observation: The old project renderer overwrote transform modules when a source file contained multiple transforms.
  Evidence: `RenderConfiguredPySparkProject` previously called `files.update(...)` once per transform; two transforms
  from the same source module produced the same generated path.

## Decision Log

- Decision: `compile()` takes compiler options or project-root/config overrides, not a `StructureSession`.
  Rationale: Users should compile at application startup or in build tooling without constructing a runtime session,
  Spark session, or runtime context. The options must still resolve from the same configuration chain as sessions so
  users do not duplicate target settings.
  Date/Author: 2026-07-08 / Codex and project owner

- Decision: `CompilerOptions` is a projection of `StructureConfig`.
  Rationale: `StructureConfig` contains runtime and build settings. Compilation needs only target backend, profile,
  variant, generated package, validation modes, schema materialization inputs, and source-root data. A projection keeps
  the public API small while preserving one source of truth.
  Date/Author: 2026-07-08 / Codex and project owner

- Decision: Compiled state is class-static and keyed by compiler options.
  Rationale: Batch jobs should create new transform invocations for fresh input DataFrames while reusing the same
  checked class artifact. The key prevents accidental reuse across incompatible backend or validation settings.
  Date/Author: 2026-07-08 / Codex and project owner

- Decision: Compiled artifacts must never contain live DataFrames or runtime results.
  Rationale: Compiled artifacts represent transform shape, checked semantics, lowered recipes, and schemas. DataFrames
  are invocation-specific runtime values and would make reuse, serialization, and concurrent execution unsafe.
  Date/Author: 2026-07-08 / Codex and project owner

- Decision: Disk artifacts are one-to-one with source units, not one-to-one with transform classes.
  Rationale: Python and compiled languages both allow multiple classes per source file. A source-unit artifact preserves
  file cardinality, matches generated transform module layout, and leaves room for timestamp or dependency-file based
  build tools such as `make`.
  Date/Author: 2026-07-08 / Codex and project owner

- Decision: Staleness detection may begin with timestamps plus source fingerprints and must leave room for dependency
  fingerprints.
  Rationale: Timestamps support simple build-tool integration, while fingerprints protect correctness when clocks are
  coarse, files are copied, or dependent schema/helper modules change.
  Date/Author: 2026-07-08 / Codex and project owner

- Decision: Use `storage` naming and avoid the `Store` suffix.
  Rationale: The public names should be short and direct. Use `DiskStorage`, `MemoryStorage`, and
  `PackageImportStorage`; do not use names such as `artifact_store` or `ReadOnlyImportArtifactStore`.
  Date/Author: 2026-07-08 / Codex and project owner

- Decision: Generated execution must support no-disk environments through explicit memory storage.
  Rationale: Some deployments cannot write to disk or scratch space. They should still be able to generate source in
  memory, compile it into an in-memory module, and execute it explicitly without silently changing execution mode.
  Date/Author: 2026-07-08 / Codex and project owner

- Decision: In-memory generated artifacts preserve the "no generated files required" promise.
  Rationale: The promise means users do not have to commit, publish, or write generated Python files for ordinary
  execution. Online mode continues to run from checked compiled artifacts and shared PySpark recipes, while generated
  mode may use `MemoryStorage` explicitly when users want generated-code semantics without filesystem artifacts.
  Date/Author: 2026-07-08 / Codex and project owner

## Context and Orientation

Structure transforms are Python classes that inherit from `Transform`. A transform class declares named input
DataFrames with `input(Schema)`, intermediate lanes with `lane(Schema)`, final outputs with `output(Schema)`, and
schema-returning methods that compile into Spark-visible DataFrame operations. A transform invocation is an instance
such as `EnrichOrders(orders=orders_df)`. The invocation stores bound input DataFrames until `run(session)` executes it.

A compiled artifact is an immutable in-memory object representing checked transform shape for a specific set of
compiler options. In this plan, "checked" means the compiler has parsed the transform class, built `TransformPlan` IR,
validated static transform semantics, resolved backend capabilities, lowered the plan to `PySparkExecutionPlan`, and
prepared schema metadata. A compiled artifact is not generated Python source and does not contain DataFrames.

A generated artifact is runnable Python source or an importable module produced from the same lowered plan used by
online execution. Generated artifacts can be written to disk, imported from an already packaged module, or kept in
memory for no-disk environments. Generated artifacts are not synonymous with generated files; memory-backed generated
artifacts are first-class artifacts and must participate in the same online/generated parity contract.

A source unit is one Python source module/file, for example `orders/transforms/order.py`. The source unit may contain
one transform class or multiple transform classes. This plan requires disk artifacts to follow source-unit cardinality:
one source module produces one compiled artifact file and one generated transform module, with per-class metadata inside
the artifact when the source module contains multiple transforms.

The current online execution path is:

1. `src/structure/app/dsl/model/transforms/Transform.py` stores constructor-bound inputs and delegates `run(session)` to
   the session.
2. `src/structure/app/runtime/session/model/StructureSession.py` resolves runtime configuration, compiles the transform
   or pipeline, lowers it to PySpark recipes, validates inputs, builds runtime schemas, and delegates to online or
   generated execution.
3. `src/structure/app/runtime/execution/online/commands/RunOnlinePySparkTransform.py` interprets the lowered PySpark
   recipes against live DataFrames.
4. `src/structure/app/runtime/execution/generated/commands/RunGeneratedPySparkTransform.py` imports a generated class
   and calls its `run(...)` method.

The current generated-code path is:

1. `src/structure/app/cli/commands/CompileStructureProject.py` discovers the project, renders PySpark files and docs,
   and writes or compares generated files.
2. `src/structure/app/cli/commands/RenderConfiguredPySparkProject.py` resolves backend capabilities and renders each
   transform.
3. `src/structure/app/target/pyspark/commands/RenderPySparkProject.py` creates generated package, runtime, schema,
   transform, and traceability files.
4. `src/structure/app/target/pyspark/commands/RenderPySparkTransformModule.py` renders the generated transform class
   that generated-mode execution imports.

The current configuration path is:

1. `StructureConfig.resolve(...)` delegates to `ResolveStructureConfig`.
2. `ResolveStructureConfig` merges defaults, `structure.toml`, `pyproject.toml [tool.structure]`, and programmatic
   overrides.
3. `StructureSession` can either receive a resolved `StructureConfig` or resolve one from project root plus overrides.

This plan preserves that chain and adds `CompilerOptions` as a smaller view over the same resolved configuration.

## Plan of Work

First, add the compiler-options model. Create `src/structure/app/compiler/options/model/CompilerOptions.py` or the
nearest package that fits the current app layout. The model should be frozen and should contain only fields needed to
produce checked and generated artifacts. At minimum it needs project root, source roots, generated package, target
backend, target profile, target variant, validation modes that affect recipes, and enough schema materialization inputs
to build the same schemas online and generated execution expect. Add `CompilerOptions.resolve(...)` so users can pass a
resolved `StructureConfig`, a project root, or programmatic overrides. It must reuse `StructureConfig.resolve(...)`
rather than reimplementing TOML loading. Add a `StructureConfig.compiler_options()` convenience method only if that
fits local style better than a classmethod projection.

Next, add compile-key and artifact models. A `CompileKey` should be frozen and hashable. It should include the source
unit identity, transform class identity or pipeline shape, Structure version, compiler options fingerprint, source
fingerprint, and dependency fingerprints when available. The first implementation may use source timestamps for disk
staleness, but the key model must include fingerprints so correctness does not depend on timestamps forever.
`CompiledTransform` should hold the checked `TransformPlan`, lowered `PySparkExecutionPlan`, materialized
`TransformSchemas`, and enough metadata to report diagnostics and import hooks. It must not hold live DataFrames,
`SparkSession`, runtime context, or `TransformResult`.

Then update `Transform`. Add class-static compiled state initialized per subclass in `__init_subclass__`, such as
`_structure_compiled: dict[CompileKey, CompiledTransform]` and `_structure_compile_lock`. Add
`@classmethod compile(cls, options=None, *, project_root=None, config=None, force=False)`. This method resolves
`CompilerOptions`, computes the key, returns the cached artifact on hit, or runs the compiler pipeline on miss. It must
be idempotent and safe when called repeatedly. It should use a lock so two threads do not compile and publish different
artifacts for the same key. Keep the lock around cache lookup and publish; avoid holding it around slow compiler work if
the implementation can use a double-check pattern safely.

After single transforms work, update `TransformPipeline`. A pipeline's compiled state cannot live on one source
transform class because the pipeline shape is an ordered sequence of transform invocations. Add a pipeline compile path
that computes a key from the ordered stage classes and options, stores compiled pipeline artifacts in a shared pipeline
cache, and still keeps DataFrames only on invocations. The existing `TransformPipeline._structure_bound_inputs` should
remain invocation data, not compiled data.

Then update `StructureSession.run(...)`. The session should still own Spark, `ctx`, execution mode, runtime runner
selection, and runtime-only overrides, but it should not be the only owner of compilation. It should expose or compute
compiler options from its resolved config. During `run(...)`, validate that session runtime options are compatible with
the artifact key, call `compile(...)` implicitly on cache miss, validate invocation inputs every run, and execute using
the artifact's lowered plan and schemas. Running the same transform class with new invocation instances must not
recompile when the key is unchanged.

Next, add generated artifacts and storage. Use `storage` as the parameter and short class names:

    DiskStorage(root=...)
    MemoryStorage()
    PackageImportStorage(package=...)

`DiskStorage` writes source-unit generated modules and sidecar metadata. `MemoryStorage` keeps rendered source strings
and module objects in memory and is the explicit no-disk path, preserving generated execution without requiring
generated files. `PackageImportStorage` imports generated modules already available on `sys.path`, such as modules
bundled into an application container or wheel. The generated runner should accept storage from the session or from the
generated artifact. It must never silently fall back from disk import to memory execution; users must opt into memory
generation.

Then refactor generation to avoid duplication. The compile pipeline should be the shared semantic source:

    source Transform class
    -> Compiler.frontend.compile()
    -> PySpark.plan.lower()
    -> Schemas.build()
    -> CompiledTransform
    -> either online execution or generated rendering

`generate()` should call or reuse `compile()`, then render from the same lowered `PySparkExecutionPlan`. Refactor
`RenderConfiguredPySparkProject` so it groups transforms by source module. For each source unit, render one generated
transform module containing all transform generated classes from that source module. Keep schema modules source-unit
based as they already are. Update traceability sidecars so one source-unit artifact can record per-transform metadata.

Finally, update docs and diagnostics. Public docs should explain that `compile()` catches static transform problems
early and prepares online execution, while `generate()` emits runnable Python artifacts. Diagnostics from compile-time
failures should point to the transform class, source unit, compiler options source, and relevant docs. Runtime errors
should still point to input names, hooks, execution mode, and generated import details when known.

## Validation and Acceptance

The feature is accepted when a human can verify all of the following behavior:

Calling `EnrichOrders.compile(project_root=".")` compiles the transform without requiring a Spark session and catches
static transform errors before `run(session)` is called. A test with an invalid transform must fail at compile time with
a diagnostic naming the transform and pointing to the relevant documentation.

Calling `EnrichOrders(...).run(session)` after explicit compile must not recompile for the same compatible compiler
options. Calling `run(session)` without explicit compile must implicitly compile once and then reuse the artifact for
later invocations of the same class.

New transform invocation instances must remain independent. A batch loop that constructs a new invocation per batch
must use that batch's DataFrames and must not retain previous DataFrames through compiled state.

A source module containing multiple transform classes must produce one source-unit generated transform module containing
all generated classes for that module. The second transform must not overwrite the first transform's generated module.

Generated execution must work with `PackageImportStorage` when generated modules are already importable, with
`DiskStorage` when generated files are written, and with explicit `MemoryStorage` when the environment cannot write to
disk. Disk import errors must remain errors unless memory storage was explicitly selected.

`CompilerOptions.resolve(...)` and `StructureSession` must read the same target settings from defaults,
`structure.toml`, `pyproject.toml [tool.structure]`, and programmatic overrides. Users must not have to repeat
`target_backend`, `target_profile`, `target_variant`, or `generated_package` separately for compile and run.

## Idempotence and Recovery

All compile and generate operations must be safe to repeat. Repeating `compile()` with the same key returns the same
cached artifact unless `force=True` is supplied. Repeating `generate()` with `DiskStorage` writes deterministic content
and reports unchanged files when content has not changed. Repeating memory generation replaces or reuses in-memory
modules for the same key without leaking prior DataFrames.

If a cache entry is corrupt or incompatible, delete only the corresponding artifact under `.structure/cache` or rerun
with `force=True`. Do not require users to delete generated source files to fix in-memory compiled state.

If a compile attempt fails, do not publish a partial artifact into the class-static cache. The next call should retry
from a clean miss. If generation fails halfway while writing to disk, write through temporary files and replace final
paths atomically where practical.

## Artifacts and Notes

The public API should converge on this shape:

    options = CompilerOptions.resolve(project_root=".")

    EnrichOrders.compile(options)
    EnrichOrders.generate(options, storage=DiskStorage(root="generated"))

    session = StructureSession(project_root=".", spark=spark)
    result = EnrichOrders(orders=orders_df, customers=customers_df, products=products_df).run(session)

For no-disk generated execution:

    storage = MemoryStorage()
    EnrichOrders.generate(project_root=".", storage=storage)

    session = StructureSession(
        project_root=".",
        spark=spark,
        execution_mode="generated",
        storage=storage,
    )
    result = EnrichOrders(orders=orders_df, customers=customers_df, products=products_df).run(session)

For packaged generated execution:

    session = StructureSession(
        project_root=".",
        spark=spark,
        execution_mode="generated",
        storage=PackageImportStorage(package="structure_generated"),
    )

The source-unit artifact layout should preserve one-to-one source correspondence:

    src/orders/transforms/order.py
    .structure/cache/pyspark/orders/transforms/order.json
    generated/structure_generated/pyspark/transforms/order.py
    generated/structure_generated/traceability/transforms/order.json

If `orders/transforms/order.py` contains `EnrichOrders` and `PublishOrders`, the generated `order.py` module contains
both `EnrichOrdersGenerated` and `PublishOrdersGenerated`, and the JSON sidecar records per-transform keys and source
fingerprints.

## Interfaces and Dependencies

Add or expose these interfaces by the end of the work. Exact package placement may follow local app conventions, but
names and responsibilities should remain stable.

`CompilerOptions` is a frozen value object resolved from `StructureConfig`. It must be constructible from a resolved
config, project root plus overrides, or default current working directory. It is the only options object needed by
`compile()` and `generate()`.

`CompileKey` is a frozen hashable value object. It identifies a compatible compiled artifact by source unit, transform
class or pipeline shape, Structure version, compiler options fingerprint, and source/dependency fingerprints.

`CompiledTransform` is a frozen value object. It contains checked compiler IR, lowered PySpark execution plan, runtime
schemas, diagnostics metadata, and source-unit metadata. It contains no DataFrames, Spark session, runtime context, or
result values.

`GeneratedTransform` is a value object returned by `generate()`. It names the source unit, generated module, generated
classes, storage, and sidecar metadata.

`DiskStorage` writes generated artifacts and optional compiled cache files to disk.

`MemoryStorage` stores generated source and importable in-memory modules without requiring a filesystem write.

`PackageImportStorage` imports already generated modules from an installed package or application bundle.

`Transform.compile(...)` is a classmethod for source transform classes. It resolves compiler options, returns a
`CompiledTransform`, and populates class-static compiled state.

`Transform.generate(...)` is a classmethod for source transform classes. It resolves compiler options, calls or reuses
`compile()`, renders generated Python from the compiled/lowered artifact, writes or registers it through `storage`, and
returns `GeneratedTransform`.

`StructureSession.compiler_options` is a property or method exposing the compiler-options projection of the session's
resolved config. `StructureSession.run(...)` uses it to find or implicitly build compatible compiled artifacts.
