# Reuse compiled artifacts across Search integration execution

This ExecPlan is maintained according to `docs/dev/auto/Plans.md`. Keep Progress, Surprises & Discoveries,
Decision Log, and Outcomes & Retrospective current throughout implementation.

## Purpose / Big Picture


Reduce repeated Structure compilation in `test_search.py` by sharing in-memory artifacts between generated-source
preparation and runtime sessions. An artifact contains the analyzed transform, execution recipes, and schema
metadata; it contains neither Spark results nor a pre-executed Spark query plan. Other integration modules should
be able to adopt the same helpers.

This is the next resolution step for
[I09272601 Search Integration Performance](../issues/I09272601.Search-integration-performance.issue.md).
Success is fewer actual compilations with identical results, plus measured full-module cost including setup.
Precompilation must not hide work by moving it outside the reported runtime. Spark DataFrame construction,
analysis, serialization, and eager checkpoints still occur when the transform runs.

## Context and Orientation


`src/structure/core/runtime/session/model/StructureSession.py` accepts `artifacts=CompiledArtifactPool()`.
Every `run()` calls `compile(invocation)`, including generated execution. Without an explicit pool, each session
owns a fresh one. `compile()` reuses compatible entries; `load()` admits an existing artifact; `cache_status()`
reports entries, hits, misses, and loads. Calling the transform class's `.compile()` directly builds an artifact
but does not populate a subsequent runtime session's pool.

`src/structure/core/compiler/artifacts/model/CompiledArtifactPool.py` already provides synchronized compilation
and caching. `BuildCompiledTransform.key()` in the sibling `commands/` directory includes source/dependency
fingerprints, compiler options, and non-default constructor parameters. Building this key still costs time on a
cache hit. Runtime DataFrames are not compiler parameters. Preserve the existing key and invalidation behavior.

`tests/integration/pyspark/support/backend_matrix.py` constructs a fresh session on each `session(...)` call.
Its rendering helpers call the transform class's `.compile()` independently. `support/generated_sources.py`
defines `GeneratedSources`, which caches rendered file dictionaries. The module-scoped `generated_sources`
fixture in `tests/integration/pyspark/conftest.py` reuses those dictionaries but not their compilation artifacts.

`tests/integration/pyspark/search/test_search.py` uses module-scoped `search_sources` to render `TRANSFORMS`,
then creates many runtime sessions. Its online calls usually default to package `structure_generated`, while
generated calls use `integration_search_generated`. Generated package names participate in compiler keys;
execution mode does not. Sharing works only after otherwise equivalent compiler settings match.

The existing preparation snapshots, generated module installation, row caches, and temporary-view cleanup have
separate lifetimes. Sharing compiler metadata must not extend any of those lifetimes or retain runtime inputs.

## Surprises & Discoveries


Both online and generated execution currently compile through the runtime session. Generated Python files alone
therefore do not eliminate runtime compilation. Rendering also discards a reusable artifact after producing files.

The integration owner now retains only the module-mode pool. In `off` mode, rendering and runtime pools are returned
without owner retention, so their compiler entries can be released with their caller. The owner records only scalar
diagnostic values and never keeps transform invocations or Spark objects.

The latest isolated Spark 3.5 observation recorded 56.79 seconds combined construction, including 6.691 seconds
explaining plans and 36.938 seconds of subsequent checkpoint work. Approximately 13.16 seconds remains for
Structure compilation and all other construction overhead. That remainder is not a measured compilation cost
or a promised saving. See the guard-reuse section of the
[benchmark report](../issues/I09272601/SearchIntegrationPerformance.bench.md).

## Decision Log


Decision (2026-09-27): Reuse the public `CompiledArtifactPool` and session APIs through integration helpers.
This requires no new public library API, process-global cache, persistent artifact format, or compiler-key shortcut.

Decision (2026-09-27): Share metadata at pytest module scope; retain distinct runtime sessions and existing runtime
cleanup boundaries. This benefits repeated transforms without sharing live DataFrames or Spark results.

Decision (2026-09-27): Populate the pool during existing generated-source preparation, then compile lazily for
previously unseen runtime specializations. Do not add a second eager traversal of all transforms merely to warm it.

Decision (2026-09-27): Compare isolated and module reuse with the same generated package and all other settings.
Keep setup inside total measurements and report cold builds and warm lookups independently.

Decision (2026-09-27): Use a phase label on the shared pool immediately before each request rather than creating
separate module pools. This keeps one compatibility cache while allowing source-preparation and runtime records to be
distinguished; compilation requests are synchronous at this boundary.

## Plan of Work


### Milestone 1: Shared helper ownership and honest measurements


Add `tests/integration/pyspark/support/compiled_artifacts.py` for integration-only pool ownership and timing.
Expose a module-scoped `compiled_artifacts` fixture in the existing PySpark conftest. Its owner supplies pools to
rendering and session creation and releases its references at module teardown. It must not retain invocations,
DataFrames, Spark sessions, generated modules, or results in its records.

Add integration-only `STRUCTURE_COMPILED_ARTIFACT_REUSE=module|off`, defaulting to `module`, with invalid values
rejected before setup. In module mode, the owner supplies one shared pool. In off mode, it supplies a new pool
for each session and each rendering compilation, reproducing isolated artifact ownership while keeping settings
identical. Existing rendered-source dictionary caching remains enabled in both modes.

Add `STRUCTURE_PROFILE_COMPILATION=1` to enable compiler timing independently of Spark query-plan profiling.
Use a test-support subclass of `CompiledArtifactPool` overriding `get_or_compile` to time the complete request,
including key construction. Delegate actual work to `super()` and use existing counters to distinguish a build
from a hit during sequential benchmark runs. Record failures separately and re-raise unchanged. Report transform
identity, phase (source preparation or runtime), elapsed time, counter deltas, and module totals. Do not change
the production cache API or describe a miss duration as exclusively compiler execution: it includes lookup work.

Extend `backend_matrix.session`, `render_generated_project`, and `render_generated_projects` with an optional
`artifacts: CompiledArtifactPool | None = None` keyword. Preserve isolated behavior when omitted. Pooled rendering
must resolve the same `CompilerOptions` as runtime execution and use `get_or_compile`, then render from that
artifact. Keep schema-module mappings in the rendered-source cache key; do not bypass rendering on an artifact hit.

Allow `GeneratedSources` to receive the module owner and supply the appropriate pool on each cache miss. Keep
`GeneratedSources()` usable without a pool owner, preserving existing helper consumers and defensive file-map copies.
Add a function-scoped `runtime_sessions` fixture: a callable factory accepting the existing session helper arguments
and injecting a pool from the module owner. Other integration modules can request this fixture explicitly.

Keep the existing Spark view cleanup mechanism. Do not call `close()` on a temporary session merely because one
transform returned: its lazy results may still need the views. Clear compiler ownership at module teardown after
runtime consumers are finished. In off mode, release temporary rendering pools once rendering completes.

### Milestone 2: Search adoption and compatibility proof


Replace Search's module-level session partial with a function-scoped `search_session` factory fixture wrapping
`runtime_sessions`. Bind `allow_stage_outputs` and `generated_package=PACKAGE` equally for online and generated
execution. Pass the factory explicitly to tests and helpers such as `_run_indexing`; avoid module globals,
monkeypatching production session construction, or keeping live sessions in module-scoped fixtures.

Use the same module owner for `search_sources`, any extra Search rendering, and all Search runtime session creation.
Maintain the existing Connect 3.5 exclusions. Do not broaden backend support, change SearchDocuments' graph,
alter checkpoint placement, disable safety validation, or remove UDFs in this milestone.

Prove that rendering a default specialization then running it online and generated with matching options produces
cache hits. A non-default parameter such as `streaming=True` must compile separately. Different package names,
backend profiles, boundary policies, validation settings, schema registries, or stage-output settings must never
reuse incompatible artifacts. Keep existing source/dependency-change invalidation tests passing.

Add focused tests in `tests/app/test_integration_compiled_artifacts.py` and extend
`tests/app/test_integration_generated_sources.py`. Test shared versus isolated build counts, explicit precompile
followed by a hit, unchanged source rendering, separate input bindings, module-owner isolation, failure followed
by a successful retry, configuration mismatches, and teardown releasing compiler references without closing Spark.
Use deterministic build-count and identity assertions, not timing thresholds. Exercise both source rendering and
runtime lookup; a mocked file-map cache alone is insufficient proof of artifact reuse.

### Milestone 3: Controlled runtime evidence and documentation


Use identical inputs and fresh runner processes for each sample. Run three alternating off/module pairs for the
focused reranking test, the text-fixture test, and the complete `test_search.py` module on ordinary Spark 3.5,
ordinary Spark 4.0, and Spark Connect 4.0. Set `STRUCTURE_PLAN_BOUNDARIES=auto` and stage outputs to zero for all
samples; this experiment changes artifact reuse, not the Spark boundary policy. Enable both profilers equally.
Do not run concurrent Spark benchmarks or builds against the same constrained Docker host.

Report per-run compilation misses/hits, preparation compilation and rendering, runtime miss and hit durations,
construction, explain/checkpoint work, collection, cleanup, total pytest time, total runner time, and heap failures.
For combined values compute each run's sum first, then the median. Compiler time nested inside construction and
checkpoint time nested inside construction must not be added a second time. Retain existing construction labels
for comparison and describe any derived remainder as other construction work, not pure Spark planning.

Record raw concise logs under `docs/dev/issues/I09272601/` with a distinct artifact-reuse prefix and append results
to `SearchIntegrationPerformance.bench.md` there. Keep earlier observations unchanged. A single cold `.compile()`
followed by `.run()` is useful attribution evidence but is not a total-runtime improvement by itself.

Update `docs/dev/Testing.md` and `docs/dev/optimization/Performance.opt.md` with the fixture usage and measured
benefit/limits. Link evidence from I09272601, leaving its status open until its broader closure conditions are met.
If reuse removes compilation but does not improve total medians, report that result and identify the measured
remaining phase; do not expand this plan into a new production graph rewrite or fingerprint caching project.

## Concrete Steps


Run commands from the repository root. After implementing helper tests:

    poetry run pytest tests/app/test_integration_compiled_artifacts.py \
      tests/app/test_integration_generated_sources.py \
      tests/specifications/online-execution/test_v1_structure_session.py -q

For a live sample, start the relevant Compose services through the supported integration setup, then run:

    docker compose --env-file infra/compose/.env -f infra/compose/docker-compose.yaml \
      -p structure-integration run --rm \
      -e STRUCTURE_COMPILED_ARTIFACT_REUSE=off -e STRUCTURE_PROFILE_COMPILATION=1 \
      -e STRUCTURE_PROFILE_QUERY_PLANS=1 -e STRUCTURE_PLAN_BOUNDARIES=auto \
      -e STRUCTURE_SEARCH_STAGE_OUTPUTS=0 -e STRUCTURE_INTEGRATION_TIMEOUT=600 \
      -e 'INTEGRATION_PYTEST_ARGS=-k=test_document_search_reranks_bm25_candidates_for_multiple_queries -vv -s' \
      structure-integration-pyspark35 bash /workspace/infra/compose/images/pyspark/run-integration.sh pyspark35

Repeat with `STRUCTURE_COMPILED_ARTIFACT_REUSE=module`. Alternate this pair three times. Substitute
`-k=test_text_fixture_runs_online_and_generated` for the text case; use `-k=test_search.py` and a 1800-second
deadline for the full module. Repeat the matrix with service/backend pairs
`structure-integration-pyspark40`/`pyspark40` and `structure-integration-spark-connect40`/`spark-connect40`.
Record the actual runtime versions and heap settings, including differences between backends.

Finally run:

    make build
    git diff --check

## Validation and Acceptance


The focused helper suite passes and proves that equivalent rendering/runtime requests build once per shared pool,
while isolated requests build independently. Distinct configuration and parameter variants remain separate.
Hits still validate compiler keys. Runtime results reflect new inputs on each invocation, not previously bound data.

All selected live Search cases retain expected rankings, schemas, intentional sentence UDF behavior, and
online/generated equality. No runtime view is dropped before its lazy result is consumed; no compiler fixture
retains Spark results across tests. Existing policy/fusion validation tests remain green in the full build and
relevant live safety coverage if runtime-helper adoption touches them.

The benchmark includes all compilation/setup costs and demonstrates actual avoided builds. Publish full-module
medians with individual runs. Claim elapsed-time improvement only when the measured comparison supports it.
If runs fail or Docker is unavailable, record exact failures and leave the evidence milestone incomplete rather
than treating skips or a relocated timer as success. Finish with a passing build and clean whitespace check.

## Idempotence and Recovery


Preserve existing uncommitted work. The new sharing is explicitly fixture-owned and can be disabled with
`STRUCTURE_COMPILED_ARTIFACT_REUSE=off`. Never clear a global cache, stop unrelated containers, or remove another
test's files to recover a sample. Repeat a failed run only after its own runner has exited. Use existing generated
package and snapshot cleanup. No source regeneration is needed unless implementation actually changes emitted code.

## Interfaces and Dependencies


Use `structure.CompiledArtifactPool`, `StructureSession(artifacts=...)`, `.compile()`, `.load()`, and cache reports
as already implemented. The additions are test-support fixtures, optional helper arguments, and diagnostic
environment switches. There is no public library API migration and no new package dependency. In-memory artifacts
must remain free of runtime DataFrame ownership. Use the existing compiler fingerprint as the compatibility authority.
