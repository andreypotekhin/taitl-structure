# Structure-level unused-branch optimization


This ExecPlan follows `docs/dev/auto/Plans.md`. Keep its progress, discoveries, decisions, and outcomes current.

## Purpose / Big Picture


Avoid constructing unused runtime branches without changing returned results or required behavior. Core will select
steps using plugin-supplied dependency and safety facts; plugins retain ownership of their executable payloads.
This is reusable Structure work, not a Search-specific graph rewrite. It contributes to
[I09272601](../issues/I09272601.Search-integration-performance.issue.md) without closing that issue.

## Context and Orientation


`src/structure/core/compiler/frontend/commands/CompilePluginTransform.py` invokes plugin compilation and assembles
diagnostics. `src/structure/plugin/api/v1/api/PluginAPI.py` defines optional plugin facets. A lowered plan is the
plugin's executable instructions; Core does not interpret that payload. PySpark creates DataFrames later, in its
executor, and renders generated code from those same instructions.

`TransformResult` exposes only declared outputs and, by default, declared outputs of recursively composed stages.
Private lanes and hook frames are not public results. `allow_stage_outputs=False` already disables stage access.
Keep its default true, existing aliases, schema lookup, and implicit matching of lanes to declared outputs.

`src/structure/plugin/pyspark/compiler/model/PySparkStepRecipe.py` contains resolved validations, operations, hooks,
and multiple result recipes. Prune after lowering to avoid changing which step receives intermediate validation.
`CompilerAPI.compile` already runs projection-union optimization. Preserve that independent optimization.

## Plan of Work


### Milestone 1: Configuration and plugin-neutral framework


Add `prune_unused_steps` to configuration defaults, validation, transform options, compiler options and fingerprints.
Add immutable public optimization graph, node, request, selection, and report contracts to Plugin API v1 and an
optional `optimizer` facet with describe/apply methods. Default omitted facts to non-removable. Validate unique node
identities, complete step inventories, roots, known dependencies, and acyclic ordered dependencies. Core computes
retained steps from final outputs, enabled stage outputs, and all unsafe nodes. Keep original order and whole-step
semantics; missing producer information must never silently drop dependencies.

Apply the selection after plugin compilation, before runtime/code generation. Documentation compilation and plugins
without the facet are unchanged. Preserve original analysis and diagnostics; attach a neutral report to compilation
for explain and serialized artifacts. Verify compatibility with an opt-in non-PySpark fixture and a legacy plugin.

### Milestone 2: PySpark safety and dependency facts


Describe each lowered step. Resolve frame dependencies using ordered producers, including hook replacements and
multi-result steps. Include sources embedded in operations, not just ordinary joins. Recognize safe built-in
expressions explicitly; an unknown expression or operation is non-removable. Do not mistake determinism for safety.
Retain checks, hooks, UDFs, explicit checkpoint/cache/persist/unpersist, nondeterminism, and unknown behavior.
Enabled intermediate validations remain roots even if that prevents all pruning. Keep retained validation recipes
unchanged, including last-step treatment. Do not run or initialize Spark during optimization.

Apply selection by filtering whole steps only. Preserve final outputs and public schemas. Disabled stage descriptors
may remain for helpful access errors but must not be dereferenced during execution/rendering. Record removed and kept
reasons, original/retained counts, and explain why stage access or validation prevents elimination.

### Milestone 3: Verification and evidence


Test dependency chains, shared producers, disconnected pure branches, aliases, nested stages, multi-result steps,
hook frame replacement, cycles, unknown facts, rollback, idempotence, and artifact round trips. Demonstrate that an
unused certified pure branch is absent from generated code and runtime construction. Restore it when stage outputs
are enabled. Safety roots retain their prerequisites and source order; compilation errors remain visible.

Run Search comparisons against the checkpoint-work task's settled revision, holding its code and settings fixed.
Alternate pruning off/on three times on ordinary Spark 3.5, ordinary Spark 4.0, and Connect 4.0. Cover reranking,
text-fixture, full Search, and representative streaming tests. Record stage-access and validation settings, original
and retained step counts, preparation, construction, nested checkpoint time, collection, cleanup, totals, and failures.
Do not claim savings from structural counts alone, or add checkpoint time to construction a second time.

## Idempotence and Recovery


Optimization is deterministic and idempotent. Never mutate the authored or original lowered plan. Turning the option
off requires a distinct compilation fingerprint and restores the prior path. Do not weaken checks, remove UDFs, or
alter Search rankings to increase elimination. Keep unrelated changes intact and leave the issue open.

## Interfaces and Dependencies


The new core option is Boolean `prune_unused_steps=True`. The optional plugin optimization facet describes an opaque
compilation through stable nodes and dependencies, then applies Core's retained-node selection. Existing plugins are
not required to implement it. Use only existing dependencies. No Search-specific cache, retrieval variant, or
partial-result pruning is introduced.

## Surprises & Discoveries


The current public result contract already hides private lanes. No restriction of method-return convenience is
necessary. Enabled intermediate schema validation can prevent elimination on ordinary Spark; preserve it explicitly.

The checkpoint-work task's settled lexical-gap source has 93 steps. All 93 remain with pruning on across ordinary
Spark 3.5/4.0 and Connect 4.0, both with stage access enabled and disabled. Safety roots and dependency closure explain
the result; see [compiler evidence](../issues/I09272601/Unused-branch-optimization.evidence.md). This pass is reusable
but does not currently remove Search computation. No runtime benefit is claimed from these counts.

Some composed operation payloads retain local reference names after input bindings are rewritten. Rather than change
their runtime semantics here, the dependency description conservatively retains all possible preceding producers for
those operations. Missing declared input producers still fail early. Hooks and unknown operations also conservatively
retain preceding work. A dedicated regression protects this fallback.
