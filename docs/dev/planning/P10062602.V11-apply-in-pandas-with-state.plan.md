## Purpose / Big Picture

After this work, a user targeting ordinary PySpark 3.5 can put a keyed Pandas state operation inside a Structure streaming transform, with declared input, key, state, and output schemas. The same explicit operation remains available on ordinary PySpark 4.0 and 4.1 for existing legacy callbacks. Users can either write a typed Structure callback or bind a native PySpark function. Online execution and generated Python must run the same Spark `GroupedData.applyInPandasWithState` operator and produce the same result.

The visible proof is a file-stream example that accumulates a total per key across batches, stops, and resumes from the same application-owned checkpoint. A separate timed example must receive a processing-time or event-time expiration callback. The application still creates the source, sink, trigger, checkpoint, and query. Structure only owns the declared transform boundary.

This is the pre-4.0 Python state gap: `transform_with_state_in_pandas(...)` already targets ordinary PySpark 4.0 and 4.1, while `applyInPandasWithState` was added in PySpark 3.4. Spark's `mapGroupsWithState` is a Scala/Java typed Dataset method, not a PySpark method, so this plan does not add or claim it. The new API is separate because the legacy callback and persisted state layout differ from the Spark 4 state-processor API.

## Surprises & Discoveries

- Observation: PySpark's legacy operation receives `(key, Iterator[pandas.DataFrame], GroupState)` and emits an iterator of Pandas DataFrames. Both the number and size of input and output batches can vary; it performs a full grouping shuffle.
  Evidence: Apache Spark 3.5.7 `GroupedData.applyInPandasWithState` reference, `https://spark.apache.org/docs/3.5.7/api/python/reference/pyspark.sql/api/pyspark.sql.GroupedData.applyInPandasWithState.html`.
- Observation: PySpark 3.5 `GroupState` exposes `exists`, `get`, `getOption`, and `hasTimedOut` as properties; `update` accepts a tuple, `remove` clears state, and timeout setters accept integer milliseconds. `getCurrentWatermarkMs()` requires an upstream watermark.
  Evidence: Apache Spark v3.5.7 `python/pyspark/sql/streaming/state.py`, `https://raw.githubusercontent.com/apache/spark/v3.5.7/python/pyspark/sql/streaming/state.py`.
- Observation: The existing repository has a native three-key `applyInPandasWithState` integration prototype. The present Structure state DSL admits one grouping field, so this feature's first public contract also admits one; the native prototype remains useful as upstream evidence but is not a Structure API example.
  Evidence: `tests/integration/pyspark/search/test_search_streaming_prototype.py` and `src/structure/plugin/pyspark/dsl/Stateful.py`.
- Observation: The Compose PySpark image already installs pandas 2.2.3 and PyArrow 19.0.1, while Structure's local compiler environment keeps Pandas optional.
  Evidence: `infra/compose/images/pyspark/Dockerfile` and the earlier Pandas state plan's recorded collection failure after a module-scope Pandas import.

## Decision Log

- Decision: Add `apply_in_pandas_with_state(...)` instead of silently adapting `transform_with_state_in_pandas(...)` to older Spark.
  Rationale: Spark uses different callback classes, timeout rules, state storage, and checkpoint formats. An explicit operation keeps generated code and migration decisions honest.
  Date/Author: 2026-10-06 / User and Codex.
- Decision: Support both typed and native callbacks on ordinary PySpark 3.5, 4.0, and 4.1; leave Spark Connect unclaimed.
  Rationale: The typed path preserves Structure schema declarations, and the native path accepts existing PySpark functions. A Connect claim needs its own live parity and restart evidence.
  Date/Author: 2026-10-06 / User and Codex.
- Decision: Follow the current single-field grouping rule and allow Spark's zero-to-many output behavior. Do not expose `mapGroupsWithState` or enforce one result per key.
  Rationale: `mapGroupsWithState` is not a PySpark API, and output cardinality is a separate contract from the requested legacy operation.
  Date/Author: 2026-10-06 / User and Codex.
- Decision: Give the typed legacy callback a dedicated `PandasGroupState` facade rather than reusing `ValueState` or `TimerContext` from Spark 4 processors.
  Rationale: Legacy `GroupState` combines tuple state and one timeout callback in a single object. Copying the Spark 4 surface would imply semantics the legacy API does not have.
  Date/Author: 2026-10-06 / Codex.
- Decision: Keep all Spark, Pandas, and Arrow imports late-bound and keep application query/checkpoint ownership outside Structure.
  Rationale: Structure must import and compile without optional runtime packages, while Spark workers execute callback bodies and applications choose their recovery policy.
  Date/Author: 2026-10-06 / Codex.

## Context and Orientation

Structure turns `Schema` declarations and `Transform` step methods into a PySpark plan. Symbolic capture records a DSL operation without running Spark; lowering turns it into an immutable recipe. Online execution interprets that recipe; generated execution renders equivalent Python. A state operation must therefore appear in the public DSL, capability matrix, captured plan, lowered recipe, both execution paths, streaming analysis, explain output, traceability output, tests, and public documentation.

The current state DSL lives in `src/structure/plugin/pyspark/dsl/Stateful.py`; its `transform_with_state(...)` and `transform_with_state_in_pandas(...)` functions accept typed processor classes or `external_state_processor(...)` bindings. Captured and lowered state records live in `src/structure/plugin/pyspark/dsl/operations/StatefulTransformPlan.py` and `src/structure/plugin/pyspark/compiler/model/PySparkStatefulTransformRecipe.py`. The dispatch helper is `src/structure/plugin/pyspark/execution/stateful.py`. Capture and lowering pass through `CapturePySparkStep.py` and `MapPySparkStep.py` in their respective PySpark plugin packages. The online runner, generated step renderer, and `ClassifyStreamingCompatibility.py` each recognize the current state operation. Inspect these files before editing because this checkout also contains unrelated in-progress work.

In legacy PySpark, `frame.groupBy(key).applyInPandasWithState(func, outputStructType, stateStructType, outputMode, timeoutConf)` invokes `func` for each input group and again for timed-out groups with no input rows. Spark persists one tuple-shaped state record per key. The callback may emit zero or more Pandas DataFrames. `GroupStateTimeout` has `NoTimeout`, `ProcessingTimeTimeout`, and `EventTimeTimeout`; processing timeout sets a duration in milliseconds, and event timeout sets an epoch-millisecond timestamp. Expiration depends on future streaming triggers and is not guaranteed at an exact wall-clock instant. No input-row order or Pandas batch boundary is guaranteed. Spark calls this API experimental and requires a full shuffle.

The current profile strings are `>=3.5,<4.0`, `>=3.5,<4.1`, `>=4.0,<4.1`, and `>=4.1,<4.2`; the default broad `>=3.5,<4.1` profile includes both 3.5 and 4.0. The new operation must work for each relevant ordinary profile and reject unsupported profiles and Connect during compilation. Spark 4.2 is outside this plan's claimed matrix. The live backend names are `pyspark35`, `pyspark40`, and `pyspark41`.

### Milestone 2: Add the public typed and native declarations

Extend `src/structure/plugin/pyspark/dsl/Stateful.py` and its exports in `src/structure/plugin/pyspark/__init__.py` with `PandasGroupStateProcessor[InputSchema, KeySchema, StateSchema, OutputSchema]`, optional `@pandas_group_state_processor` validation, `PandasGroupState[StateSchema]`, `external_pandas_state_function(...)`, and `apply_in_pandas_with_state(...)`. Generic arguments are the source of truth for typed callback schemas, including specialized intermediate base classes. Reject unresolved, conflicting, or non-`Schema` bindings. The required typed callback is `on_batches(self, key, batches, state) -> Iterator[pandas.DataFrame]`; the callback body is ordinary worker-side Python and is never symbolically interpreted. `key` is a Structure key-schema instance; `batches` remains a lazy iterator of real Pandas DataFrames.

`PandasGroupState` exposes `exists: bool`, `get() -> StateSchema | None`, `update(value: StateSchema) -> None`, `remove() -> None`, `has_timed_out: bool`, `set_timeout_duration(duration_ms: int) -> None`, `set_timeout_timestamp(timestamp_ms: int) -> None`, `current_processing_time_ms: int`, and `current_watermark_ms: int`. Conversion between the typed state instance and Spark's tuple follows declared schema field order. Validate update type and nullable fields before calling Spark. The facade delegates timeout rules to Spark and supplies an actionable error with a link to `docs/reference/Streaming.ref.md` when the selected timeout policy or missing watermark makes a requested timeout operation invalid. A timeout invokes the same `on_batches` callback with an empty input iterator and `has_timed_out=True`; no separate timer callback exists.

`external_pandas_state_function(func, *, input, key, state, output)` binds a top-level importable native function and four Structure schema classes. Pass the function unchanged to Spark: its callback receives the native key tuple, Pandas iterator, and PySpark `GroupState`. Do not wrap its state access or output batches. Require the function to be importable by generated modules and workers; reject closures and local functions with a remedy to move them to an importable module.

`apply_in_pandas_with_state(*, key, processor, output_mode, timeout)` accepts either a typed processor class or that native binding. `key` is one field from the current streaming input and must match the one-field declared key schema. Accept `output_mode="Append"` or `"Update"` and `timeout="none"`, `"processing_time"`, or `"event_time"`; map the timeout names to Spark's three `GroupStateTimeout` constants. Reject `Complete`, invalid schema/output matches, a non-streaming driving input, multiple operations in the same step, or a return other than the state result with actionable diagnostics. There is no `time_mode`, `initial_state`, or automatic state-schema migration argument because the legacy Spark call has none.

## Artifacts and Notes

The intended typed source shape is below. These new symbols are specified by this plan and become importable after implementation. The four schema classes make the input, grouping key, persisted state, and emitted rows explicit. Pandas is imported inside the worker callback so merely importing the module does not require it.

    from structure import Schema, Transform, input, output, step
    from structure.plugin.pyspark import (
        PandasGroupState,
        PandasGroupStateProcessor,
        apply_in_pandas_with_state,
        integer,
        pandas_group_state_processor,
        string,
    )


    class Event(Schema):
        account_id = string(nullable=False)
        amount = integer(nullable=False)


    class AccountKey(Schema):
        account_id = string(nullable=False)


    class TotalState(Schema):
        total = integer(nullable=False)


    class TotalOutput(Schema):
        account_id = string(nullable=False)
        total = integer(nullable=False)


    @pandas_group_state_processor
    class AccountTotals(PandasGroupStateProcessor[Event, AccountKey, TotalState, TotalOutput]):
        def on_batches(self, key, batches, state: PandasGroupState[TotalState]):
            import pandas as pd

            old = state.get()
            total = 0 if old is None else old.total
            for batch in batches:
                total += int(batch["amount"].sum())
            state.update(TotalState(total=total))
            yield pd.DataFrame({"account_id": [key.account_id], "total": [total]})


    class AccumulateTotals(Transform):
        events = input(Event, streaming=True)
        totals = output(TotalOutput)

        @step(input=events, output=totals)
        def accumulate(self, event: Event) -> TotalOutput:
            return apply_in_pandas_with_state(
                key=event.account_id,
                processor=AccountTotals,
                output_mode="Update",
                timeout="none",
            )

For a caller who already has a native PySpark callback, reuse the same four schemas and declare the function at module scope. Spark supplies a tuple key and its own `GroupState`; this path does not receive Structure's typed facade. The timeout branch runs when Spark invokes the function with no input batches.

    from structure.plugin.pyspark import external_pandas_state_function


    def native_totals(key_tuple, batches, pyspark_group_state):
        import pandas as pd

        if pyspark_group_state.hasTimedOut:
            pyspark_group_state.remove()
            return

        total = pyspark_group_state.get[0] if pyspark_group_state.exists else 0
        for batch in batches:
            total += int(batch["amount"].sum())
        pyspark_group_state.update((total,))
        pyspark_group_state.setTimeoutDuration(60_000)
        yield pd.DataFrame({"account_id": [key_tuple[0]], "total": [total]})


    class AccumulateNativeTotals(Transform):
        events = input(Event, streaming=True)
        totals = output(TotalOutput)

        @step(input=events, output=totals)
        def accumulate(self, event: Event) -> TotalOutput:
            return apply_in_pandas_with_state(
                key=event.account_id,
                processor=external_pandas_state_function(
                    native_totals,
                    input=Event,
                    key=AccountKey,
                    state=TotalState,
                    output=TotalOutput,
                ),
                output_mode="Update",
                timeout="processing_time",
            )

For input rows `("a", 2)` and `("a", 1)` in one trigger, followed by `("a", 4)` in another, either transform emits totals `3` then `7`. The native example also removes its state after 60 seconds without new input; the exact expiration trigger is controlled by Spark. Neither source form dictates physical Pandas batch sizes or callback order across keys.

The driver and workers need compatible PySpark, pandas, and PyArrow; the repository Compose images already pin these. Keep optional imports out of Structure package import and Spark-free compilation.
