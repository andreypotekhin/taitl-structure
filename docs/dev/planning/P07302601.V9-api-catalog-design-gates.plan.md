# Address v9 API Catalog Design Gates

This ExecPlan is a living document. Maintain it according to `docs/dev/auto/Plans.md`; its `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` sections must describe the actual state whenever work stops.

## Purpose / Big Picture

V9 made PySpark Structured Streaming coverage broad and honest by classifying API families as Structure-supported, caller-owned-guided, design-gated, streaming-ineligible, or out of scope. The public APICatalog still contains other planned or deferred rows outside streaming, such as `sample`, aggregate aliases, XML helpers, variant/geospatial helpers, join reordering, and nearest as-of joins. This v9 follow-up turns all those open catalog rows into concrete outcomes. After this plan is implemented, a user can see exactly which gated APIs became supported, which stayed unsupported, and which require a separate design, with tests and evidence behind each decision.

This plan addresses chained window aggregation, chained stateful operators, selected-row helpers, analytic window projections, `foreach`/`foreachBatch`, arbitrary state APIs, variant/geospatial helpers, join reordering, nearest as-of joins, aggregate aliases, sampling, and missing-column set composition. XML helpers are recorded as low-priority design-gated work but are not an active implementation target for this v9 follow-up. The plan does not reopen Structure-owned streaming lifecycle by implication, but it is support-first for the extended streaming API surface: attempt implementation or executable caller-owned guidance before retaining a gate.

The dated release sequence and final hardening boundary are coordinated by
`docs/dev/planning/P07302603.V9-closeout-and-release.plan.md`. This document remains the detailed implementation plan;
the closeout plan owns sprint sequencing, release evidence, and the final V9 decision.

## Context and Orientation

Structure is a Python-to-PySpark compiler. Users write typed `Transform` classes with schema-returning methods. Structure runs those transforms online through `StructureSession` or emits generated PySpark classes. For streaming, Structure accepts caller-supplied streaming DataFrames and returns a transformed DataFrame plan. Caller code still owns PySpark source creation, sink creation, checkpoint locations, triggers, output modes, query starts and stops, deployment, and recovery.

The main files for this plan are:

- `src/structure/plugin/pyspark/resources/pyspark-streaming-api-coverage.json`: the v9 API-family ledger.
- `docs/dev/design/V9StreamingDesignGates.md`: design rationale for the gated families.
- `docs/dev/specifications/V9StreamingDesignGatedFeatures.md`: implementation-ready contracts for each gate.
- `docs/dev/design/V9ApiCatalogDesignGates.md`: design rationale for non-streaming APICatalog open rows.
- `docs/dev/specifications/V9ApiCatalogDesignGatedFeatures.md`: implementation-ready contracts for non-streaming APICatalog open rows.
- `docs/APICatalog.md`: public support catalog.
- `docs/api/Streaming.api.md`: public streaming API reference.
- `src/structure/plugin/pyspark/compiler/commands/ClassifyStreamingCompatibility.py`: current compiler streaming compatibility classifier.
- `tests/specifications/streaming-compatibility/test_v1_streaming_compatibility.py`: no-Spark compatibility tests for accepted and rejected streaming shapes.
- `tests/integration/pyspark/v3/streams/test_file_streams.py`: live PySpark file-stream adoption evidence.

Definitions:

Structured Streaming is Spark's incremental DataFrame execution model. A stateful operation keeps state across micro-batches, such as a watermarked aggregation, dedupe, session aggregation, or stream-stream join. A lifecycle API starts, stops, writes, monitors, checkpoints, or schedules a streaming query. A design-gated row has a documented design but no support claim yet.

Second, prototype chained event-time window aggregation directly in PySpark before touching Structure. This lane is now
closed: the file-stream fixture applies `withWatermark`, first-stage `groupBy(window(...))`, `window_time(...)`, and
second-stage `groupBy(window(...))` on PySpark 3.5 and 4.0, with online/generated parity and deterministic output.
Structure admits only this chained pair.

Third, make stateful-operation tracking explicit enough for diagnostics. This is now implemented: the checker recognizes
the approved first-window/`window_time`/second-window pair and rejects any other second stateful operation with
`STREAM-E0801` guidance naming caller-owned PySpark or batch materialization.

Fourth, prototype selected-row helpers for finite event-time windows. Try a typed struct aggregate lowering for latest/earliest per key within a watermarked window. Do not use `row_number()` over a streaming DataFrame unless Spark 3.5 and 4.0 prove it works with bounded semantics. The target outcome is a supported finite-window API with explicit tie behavior; move selected-row helpers to `streaming-ineligible` only if public Spark DataFrame APIs cannot express the bounded contract safely.

Fifth, prototype finite analytic-window alternatives rather than admitting broad batch projection windows over streams. The target outcome is one or more explicit finite-state streaming APIs for common intents such as top-N, previous/next value, or rolling aggregate within an event-time window. Existing batch helpers should remain available for batch transforms. Streaming diagnostics should distinguish event-time grouping windows, supported finite alternatives, and batch-only analytic projection windows.

Sixth, handle side-effect APIs without lifecycle ownership. `foreachBatch` already has caller-owned executable guidance. Add row-level `foreach` guidance only if it can remain outside generated Structure transforms and tests can prove generated modules still contain no lifecycle calls. Otherwise, keep `streaming.foreach` design-gated with an implementation-ready lifecycle contract.

Seventh, create the typed arbitrary-state model rather than treating arbitrary state as permanently out of reach. The implementation target is a separate explicit model with state schema, timeout policy, output schema, restart evidence, target-profile gates, and generated-code shape. Do not expose `applyInPandasWithState`, `transformWithState`, or state processor APIs through `@raw(streaming=True)`.

Finally, update the ledger, public docs, diagnostics, generated artifacts, and evidence. Every status change must be backed by tests. Every admitted Structure-owned streaming claim needs live PySpark 3.5 and 4.0 evidence, or profile-specific positive and rejection evidence when the API is target-gated.

In parallel with the streaming gates, resolve the non-streaming catalog gates. XML helpers remain low-priority design-gated documentation. Variant and geospatial helpers require public type-model decisions. Join reordering must be opt-in and explainable. Nearest as-of joins need tolerance and tie policy. Aggregate aliases should probably close as unsupported/not-applicable because output schemas already own names, unless a narrow schema-local alias helper is designed. Sampling needs seed and reproducibility rules. Missing-column set composition needs schema-fill rules.

Aggregate aliases are now resolved: raw `GroupedData.agg` aliases are unsupported/not-applicable because Structure names
aggregate outputs through Schema constructor assignments and physical Spark column names through field `alias=...`.

Nearest as-of is now resolved for `ties="error"`: the public helper remains `as_of_one(...)`, with
`direction="nearest"` selecting the closest non-null right time and failing equidistant best matches. Directional tie
preferences are not public API.

Sampling is now resolved: the public helper is `sample(fraction, with_replacement=False, seed=None, reproducible=True)`.
It records a relation operation, renders Spark `DataFrame.sample(...)`, rejects missing `seed` unless
`reproducible=False`, and remains batch-only for streaming compatibility.

Missing-column set composition is now resolved for its first batch slice:
`union_by_name(relation, allow_missing_columns=True)` admits nullable top-level missing fields and lowers to Spark
`unionByName(..., allowMissingColumns=True)`. Missing non-null fields, `defaults=...`, nested partial fills, and
streaming missing-column union remain design-gated.

Join reordering is now resolved for v9 as design-gated with no public helper. Existing join predicates may legally
depend on earlier joined scopes, so logical reordering requires dependency-safe predicate analysis before Structure can
move joins without changing source semantics. Spark remains free to perform physical optimization below Structure's
generated DataFrame plan.

Variant/geospatial helpers are now resolved for v9. Variant field support is implemented as an opaque schema type,
rendered and materialized as `VariantType` only for the resolved PySpark 4 profiles. The admitted Variant value helper
set is implemented for the owning 4.0 and 4.2 profiles; the remaining completion sequence is linked above. Apache
Sedona 1.9.0 is selected as the optional integration provider. V9 admits a narrow, provider-neutral planar Geometry
slice with literal SRIDs, WKT conversion, and topology predicates. The bundled PySpark plugin owns the typed DSL and
common Spark SQL lowering without importing or requiring Sedona; the active provider is resolved only when a runtime
Geometry type is materialized. Sedona is only the Compose integration provider.

### Geometry implementation milestone

The first Geometry milestone adds a provider-neutral field and expression surface to the existing PySpark plugin. The
field factory `geometry(srid=..., nullable=True)` creates a typed planar Geometry value whose positive literal SRID is
part of the type. `geometry_from_wkt`, `geometry_as_wkt`, `intersects`, `contains`, and `within` are captured as typed
symbolic calls; mismatched SRIDs are rejected before compilation. Rendered PySpark must use only `F.call_function`
with the common `ST_GeomFromWKT`, `ST_AsText`, `ST_Intersects`, `ST_Contains`, and `ST_Within` names. Generated schema
modules import only `structure.geo.geometry_type`, whose late provider lookup supplies the active runtime DataType.

The second milestone defines the `GeoProvider` entry point and diagnostics. A provider supplies `geometry_type()` and
common-contract availability checks. No provider is required for Spark-free compilation or source generation; missing
or multiple providers fail only at schema materialization or online execution with provider-neutral GEO diagnostics.

The third milestone supplies a test-only Apache Sedona 1.9.0 adapter. Compose images pin the Python package, matching
Spark/Scala shaded JAR, and GeoTools wrapper for each supported Spark lane. Integration tests prove WKT construction,
WKT serialization, all three predicates, null propagation, and SRID behavior without changing generated source.

Streaming side-effect APIs are now split. `foreachBatch` is caller-owned-guided through
`examples.streams.adoption.start_foreach_batch_query(...)`, which attaches the side-effect sink after Structure returns
a transformed streaming DataFrame. Row-level `foreach` remains design-gated because it still needs sink identity,
idempotence, retry, security, and recovery contracts.

- focused tests and `make build` pass.

The final report should name every row whose status changed and provide the evidence command for each admitted feature.

## Idempotence and Recovery

The plan is additive. If a prototype fails on either PySpark target, do not weaken the contract to pass tests. Record the failed shape in `Surprises & Discoveries`, keep or move the ledger row to a non-supported status, and add a diagnostic or documentation update. Do not add lifecycle calls to generated transform modules. If generated artifacts drift, rerun the documented generation command and review the diff before committing.

## Interfaces and Dependencies

Use only public PySpark DataFrame and SQL function APIs in generated transforms. Do not use SparkContext, RDDs, private JVM/Py4J fields, hidden SQL strings, or arbitrary Python row loops. Use PySpark `functions.window_time` only if both supported target profiles expose it and live streaming evidence passes.

Public Structure APIs added by this plan must live under `structure.plugin.pyspark`, use existing typed expression and relation patterns, and preserve online/generated parity. Any lifecycle or side-effect recipe must live outside transform methods and generated transform modules.
