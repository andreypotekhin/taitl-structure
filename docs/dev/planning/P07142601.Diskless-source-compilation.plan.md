## Purpose / Big Picture

Structure currently compiles Python classes which have already been imported from a filesystem project. After this
change, a notebook, service, or other disk-less process can supply a named tree of Python source files, compile every
concrete Structure transform contained in that tree, select one transform by its Python module name when it is run,
and never write the supplied source to disk. A caller can also create a complete `StructureConfig` in Python without
reading configuration files or requiring a source-root directory.

The observable notebook workflow is:

    sources = StructureSources.files({
        "orders/schemas/order.py": schema_text,
        "orders/transforms/order.py": transform_text,
    })
    config = StructureConfig.create(execution_mode="online")
    session = StructureSession(spark=spark, config=config)

    artifacts = session.compile(sources)
    result = session.run(transform="orders.transforms.order:EnrichOrders", orders=orders_df)

`artifacts` contains an artifact for every concrete transform entrypoint in `sources`; the `transform` argument only
selects which already-compiled transform to instantiate and execute. A transform address is a Python module name, then
`:`, then a class name or nested class qualified name, for example `orders.transforms.order:EnrichOrders`. The source
tree retains POSIX paths for source loading, provenance, and diagnostics, but paths are not run-time identifiers.

## Surprises & Discoveries

- Observation: a class defined through `exec` in an in-memory `ModuleType` does not currently compile.
  Evidence: `BuildArtifactManifest._dependency()` calls `inspect.getsourcefile(value)` without handling its
  `TypeError` for a module without `__file__`; a minimal in-memory `Copy(Transform)` fails before frontend
  compilation.

- Observation: simply catching that exception would make source changes unsafe.
  Evidence: `CompiledArtifactPool.get_or_compile()` derives its key before compilation from
  `BuildCompiledTransform.key()`. The current no-file fallback has no content digest, so separate notebook definitions
  with the same module and class name would share a key.

- Observation: `MemoryStorage` solves disk-less generated-code output, but not input source loading.
  Evidence: `src/structure/app/target/pyspark/storage/MemoryStorage.py` accepts generated path-to-text files only;
  `DiscoverStructureProject` still recursively scans `StructureConfig.source_roots` on disk.

- Observation: the full build is currently blocked outside this change.
  Evidence: `make build` reaches Flake8, then reports E203 in the pre-existing untracked file
  `src/structure/lib/cross/errors/BuildSourceSpan.py:26`.

## Decision Log

- Decision: use `StructureSources` as the sole first-slice source input to `Transform.compile(...)` and
  `StructureSession.compile(...)`.
  Rationale: a distinct immutable source-tree object supplies names, text, content identity, importing, discovery,
  and future directory/archive adapters without overloading raw mappings or paths at the public compiler boundary.
  Date/Author: 2026-07-14 / Codex and user.

- Decision: compiling a `StructureSources` object compiles all discovered concrete transform entrypoints and returns
  `CompiledSources`, an immutable mapping from canonical source address to `CompiledTransform`.
  Rationale: supplied code commonly contains reusable bases, pipelines, and several callable transforms. Compilation
  validates the complete source set early; run-time selection must not silently leave sibling transforms unchecked.
  Date/Author: 2026-07-14 / Codex and user.

- Decision: transform addresses use `python.module.name:ClassName`; POSIX source paths remain provenance and diagnostic
  information only.
  Rationale: module names match Python imports, class `__module__`, generated-code imports, and the source importer's
  identity. A user selects the same name that source code itself imports, regardless of whether it originated in memory
  or a filesystem directory.
  Date/Author: 2026-07-14 / Codex and user.

- Decision: session source compilation accumulates artifacts and transform registrations. `session.run(transform=...)`
  selects from that accumulated registry and does not receive `StructureSources` again.
  Rationale: callers explicitly compile source sets once, then execute any registered transform concisely. Duplicate
  transform addresses across registered source sets fail as ambiguous; Structure never chooses a source set by order.
  Date/Author: 2026-07-14 / Codex and user.

- Decision: defer archive loading. The first slice supports `StructureSources.files(...)` and
  `StructureSources.from_directory(...)` only.
  Rationale: both establish the source-tree abstraction and provide an ergonomic test adapter. Archive root selection,
  package metadata, and archive lifecycle can be added later without changing the compilation or execution interfaces.
  Date/Author: 2026-07-14 / Codex and user.

- Decision: retain `Transform.compile` as a class method rather than converting it to `@staticmethod`.
  Rationale: `EnrichOrders.compile(...)` must continue to identify `EnrichOrders`, while
  `Transform.compile(sources, ...)` is recognized by `cls is Transform` and dispatches to source-set compilation.
  Date/Author: 2026-07-14 / Codex and user.

- Decision: add `StructureConfig.create(...)`, a direct programmatic constructor that performs no configuration-file
  reads and allows an empty source-root set.
  Rationale: a source tree passed explicitly to compilation replaces project discovery. `resolve(...)` remains the
  filesystem-project API and keeps its source-root validation and precedence behavior.
  Date/Author: 2026-07-14 / Codex and user.

- Decision: source-backed artifact identity includes both individual source-file digests and a digest of the complete
  `StructureSources` snapshot.
  Rationale: individual digests identify declared transform/schema owners, while the complete digest conservatively
  invalidates an artifact when an imported helper module changes before dependency-graph tracking is available.
  Date/Author: 2026-07-14 / Codex and user.

## Context and Orientation

`src/structure/app/dsl/model/transforms/Transform.py` provides the public class method
`Transform.compile(options=None, *, project_root=None, config=None, ...)`. It resolves `CompilerOptions` and invokes
`BuildCompiledTransform` for one transform class. `TransformPipeline.compile(...)` has the same one-subject shape.

`src/structure/app/runtime/session/model/StructureSession.py` owns a `CompiledArtifactPool`. Its
`compile(transform_or_pipeline)` returns one `CompiledTransform`; its `run(invocation)` receives an already-created
transform invocation, compiles the invocation class on demand, validates bound inputs, and delegates execution.

`src/structure/app/cli/commands/DiscoverStructureProject.py` is the current filesystem discovery mechanism. It adds
each configured source root to `sys.path`, recursively finds `.py` files, imports them, and recognizes concrete
`Transform` subclasses with final outputs or a class-field pipeline. `StructureSources` must use the same entrypoint
rule, but derive modules from in-memory relative paths rather than `Path.rglob`.

`src/structure/app/compiler/artifacts/commands/BuildArtifactManifest.py` and
`src/structure/app/compiler/artifacts/commands/BuildCompiledTransform.py` construct the dependency manifest and the
pre-build cache key. Both currently call `inspect.getsourcefile`; filesystem classes receive a path digest, but classes
without a source file are not handled consistently. `CompiledArtifactPool` uses that key before it invokes the builder.

`src/structure/app/configuration/model/StructureConfig.py` exposes `StructureConfig.resolve(...)`. Its resolver reads
`structure.toml` and `pyproject.toml`, and its validator requires at least one existing source-root directory. That is
correct for CLI discovery but unsuitable when `StructureSources` supplies source explicitly.

A source tree is an immutable mapping of a relative POSIX `.py` path to UTF-8 Python text. Directories implied by paths
are virtual packages; an explicit `__init__.py` supplies package code, while a missing one is an implicit namespace
package. The first slice accepts in-memory files or snapshots a real directory; both become the same immutable tree.
The tree derives Python module names from paths below its root. Source text is trusted application Python: importing it
executes Python class bodies and imports, so the import-safe source rule continues to apply. This feature is not a
sandbox for untrusted text.

## Plan of Work

### Milestone 1: Model and load source trees

Create `src/structure/app/sources/` with public API and model modules, then export `StructureSources`,
`CompiledSources`, and `SourceTransformAddress` from `src/structure/__init__.py`. `StructureSources.files(files)` must
validate that every key is a normalized relative POSIX `.py` path with no `.` or `..` segments, every value is text, and
all module path segments are Python identifiers. It stores a sorted immutable snapshot and exposes its aggregate
SHA-256 digest. `from_directory(path)` recursively reads Python sources into the same snapshot; this is the test
fixture adapter and the only filesystem source adapter in the first slice. It must use ordinary driver-side Python
file access, not PySpark: source importing/compilation occurs in the caller's Python process before Spark executes a
plan. Do not add archive handling or a Spark-session dependency in this slice.

Implement a source importer using `importlib.abc.MetaPathFinder` and `importlib.abc.Loader`. It must create packages
before module execution, serve relative and absolute imports within the supplied tree, and put only Structure-owned
modules into `sys.modules`. It must reject a collision with an unrelated preexisting module rather than replacing it.
For a later snapshot of the same source paths, replacement is permitted only when the existing module was installed by
Structure; guard install/reload operations with one process-wide reentrant lock. A session retains the source object it
compiled so the importer and module globals remain available to source-backed invocations. Do not promise simultaneous
execution of two different snapshots with the same module names in this first slice; report an actionable collision
diagnostic instead. Callers can use distinct package roots for simultaneous variants.

Create `DiscoverStructureSources` by factoring the class-recognition predicates from
`DiscoverStructureProject`. It imports every virtual module deterministically, locates schema and concrete transform
classes, and returns addresses in lexical module then class declaration order. It must retain classes sharing one source
file and skip reusable no-output bases, exactly as filesystem discovery does. Implement `SourceTransformAddress` parsing
for the canonical `python.module:Class` form. Ambiguity and unknown addresses must produce a structured diagnostic
containing the requested address, its source path where available, and the available canonical addresses.

Add unit tests under `tests/app/sources/` for path validation, module discovery, absolute/relative sibling imports,
implicit and explicit packages, nested class addressing if supported by normal class lookup, multiple transforms from
one file, directory snapshots, source-import exceptions, and collisions. Do not add archive tests or an archive
dependency.

### Milestone 2: Compile every source transform through existing compilation

Add `CompileStructureSources` under `src/structure/app/compiler/artifacts/commands/`. Given `StructureSources` and
resolved `CompilerOptions`, it discovers source entrypoints, delegates compilation of each concrete transform to a
supplied `compile_one` operation, and returns `CompiledSources`. `CompiledSources` is a frozen mapping-like model.
Its iteration
order is canonical transform address order; it exposes `artifact(address)`. If any transform cannot compile, fail the
full operation and surface that compiler diagnostic; do not
return a partially compiled source set.

`Transform.compile(sources, ...)` supplies a direct `BuildCompiledTransform` operation, preserving its existing
standalone-artifact behavior. `StructureSession.compile(sources)` supplies
`CompiledArtifactPool.get_or_compile`, once per discovered transform, so every result is added to the same existing
session pool and a repeated identical source snapshot receives normal per-transform cache hits. `CompiledSources`
retains its `StructureSources` snapshot solely as the source-registration handle; its contained `CompiledTransform`
values remain data-only.

Add overload-style runtime dispatch while preserving existing calls:

    EnrichOrders.compile(config=config) -> CompiledTransform
    Transform.compile(sources, config=config) -> CompiledSources
    session.compile(EnrichOrders) -> CompiledTransform
    session.compile(sources) -> CompiledSources

`Transform.compile` recognizes the source form only when invoked on the base `Transform` class and its first positional
argument is `StructureSources`; subclasses continue to interpret that argument as their existing compiler options.
`StructureSession.compile` recognizes `StructureSources` by type. Both source forms compile every entrypoint; neither
requires a transform address. In the session form, every returned artifact resides in the existing artifact pool and
the session retains the source snapshot in a private digest-keyed registry. Repeated compilation of the same snapshot
hits that pool; compilation of a different snapshot adds its artifacts without evicting earlier ones.

Extend `StructureSession.load(...)` and `load_many(...)` to accept `CompiledSources`: register its `StructureSources`
snapshot, then load every contained artifact into the same pool. This preserves the existing explicit artifact-loading
workflow when a caller used `Transform.compile(sources, config=session.config)` for early diagnostics.

Extend `StructureSession.run` without changing `session.run(existing_invocation)`: permit a transform-only form with
no positional invocation. It requires `transform=` and accepts the remaining keyword arguments as transform input
bindings. It resolves the selected class from the accumulated session source registry, instantiates it with those
bindings, obtains its artifact from the existing pool, and follows the existing runner and validation path. For example:

    session.run(transform="orders.transforms.order:EnrichOrders", orders=orders_df)

If no compiled source transform has that address, tell the caller to compile its `StructureSources` first. If multiple
accumulated source sets expose the address, fail with an ambiguity diagnostic that names each source-set digest and
source path. `clear_compiled()` clears compiled artifacts but retains registered source snapshots so a later
transform-only run can recompile them; source removal is deliberately outside this first slice.

Add specification tests under `tests/specifications/diskless-source-compilation/`. Use fake schema types and a fake
online executor so compile/run coverage stays Spark-free. Prove that compiling a two-transform hierarchy builds both
artifacts, selecting either address uses its matching plan, module-name resolution works, and
existing class/pipeline calls retain their return types and behavior.

### Milestone 3: Make provenance and caching safe for memory source

Create a small source-origin registry owned by `StructureSources`. For each loaded class, it returns its virtual POSIX
path, file digest, and source-set digest. Consult it before `inspect.getsourcefile` in both
`BuildArtifactManifest._dependency` and `BuildCompiledTransform._source`. For registered source classes, record the
relative virtual path and digest. Add a `source_set` manifest dependency with the aggregate digest. This produces a
deterministic key before compilation and avoids file timestamps, object identities, or absolute paths.

For normal filesystem classes, retain the current behavior. Harden both code paths against `TypeError` as well as
`OSError` from `inspect.getsourcefile`. For an unregistered class with no readable source file, emit a compile
diagnostic that tells the caller to compile through `StructureSources`; do not use an object id or a digest-less cache
key. This is the resolution for the current in-memory `exec` failure and the stale-cache risk.

Add tests that compile two snapshots with identical paths/classes but different text into one session and prove that
the second snapshot rebuilds rather than hits the first artifact. Verify identical snapshots hit the session cache.
Verify that manifests
contain only relative virtual paths and digests, and no source compilation requires a filesystem source file. Retain the
existing normal-project artifact-key tests.

### Milestone 4: Create configuration entirely in Python

Add `StructureConfig.create(**settings)` to `src/structure/app/configuration/model/StructureConfig.py` and expose it
from the root package. It starts with the normal defaults and validation/capability checks. It never consults the
current directory, `structure.toml`, or `pyproject.toml`. It permits `source_roots=()` because explicitly supplied
`StructureSources` supersedes project discovery. Every default setting records `default` in `source_map`; explicit
settings record `programmatic`.

Make the configuration model represent the absence of filesystem output explicitly: programmatically created source-only
configs have `project_root=None`, `source_roots=()`, `generated_dir=None`, and `generated_docs_dir=None` unless the
caller supplies an output root. Update `StructureConfigBuilder`, `StructureConfigValidator`, and `CompilerOptions` to
preserve that distinction while leaving `StructureConfig.resolve(...)` behavior unchanged. Any disk-generation path
that needs a missing directory must fail early with a diagnostic explaining to supply `generated_dir` or
`MemoryStorage`; online source compilation and execution must not inspect those optional paths.

Add configuration tests proving `StructureConfig.create()` performs no filesystem/config-file reads (monkeypatch the
loader and `Path.exists`), retains normal defaults and capability validation, accepts relevant overrides, makes an empty
source set legal only for this API, and configures `StructureSession(config=config)` for source compilation. Add a
regression test that `StructureConfig.resolve()` still rejects an empty/nonexistent filesystem source root.

## Validation and Acceptance

Acceptance is behavioral. With two source files that define schemas and two concrete transforms,
`session.compile(sources)` returns two artifacts addressed by their module names and class names. Neither source file
exists
on disk. Repeating compilation of the same immutable snapshot returns cache hits. Replacing source text produces a new
artifact and executes the new plan rather than stale code.

With a `StructureConfig.create(...)` config and a fake online executor,
`session.run(transform="orders.transforms.order:EnrichOrders", orders="orders-df")` returns the selected result.
An unknown or ambiguous address names the available canonical module addresses and source paths. Existing
`EnrichOrders.compile()`,
`session.compile(EnrichOrders)`, and `session.run(EnrichOrders(...))` remain compatible. The full `make build` command
passes.

## Idempotence and Recovery

`StructureSources` snapshots are immutable, so creating and compiling the same snapshot repeatedly is safe. Source
module installation must be guarded and must not overwrite unrelated `sys.modules` entries. If an implementation test
leaves Structure-owned modules registered, its fixture must remove only the modules and finder it installed in a
`finally` block. Do not delete arbitrary modules, source directories, or artifact-pool entries. A failed
source-set compilation must leave no partially returned `CompiledSources`; callers may fix the source text, create a new
snapshot, and retry.

## Interfaces and Dependencies

The implementation uses only Python standard-library `importlib`, `sys`, `types`, `hashlib`, and `pathlib` for source
loading. Do not add a package dependency. The required end-state interfaces are:

    class StructureSources:
        @classmethod
        def files(cls, files: Mapping[str, str]) -> StructureSources: ...
        @classmethod
        def from_directory(cls, directory: Path | str) -> StructureSources: ...
        @property
        def digest(self) -> str: ...

    @dataclass(frozen=True)
    class SourceTransformAddress:
        module: str
        qualname: str
        def __str__(self) -> str: ...  # "python.module:Class"

    class CompiledSources(Mapping[SourceTransformAddress, CompiledTransform]):
        sources: StructureSources
        def artifact(self, address: SourceTransformAddress | str) -> CompiledTransform: ...

    Transform.compile(sources: StructureSources, *, config: StructureConfig | None = None, ...) -> CompiledSources
    StructureSession.compile(sources: StructureSources) -> CompiledSources
    StructureSession.load(artifacts: CompiledSources) -> None
    StructureSession.run(*, transform: SourceTransformAddress | str, **inputs) -> TransformResult
    StructureConfig.create(**settings) -> StructureConfig

`CompiledTransform` remains data-only and is not made to own live module or class objects. `StructureSources` and the
session source registry own source modules for the life of source-backed execution.
