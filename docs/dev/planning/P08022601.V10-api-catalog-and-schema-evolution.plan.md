## Purpose / Big Picture

V10 turns the remaining actionable API Catalog rows into precise implementation or deferral work. Users will be able to
compose relations with explicit sampling and schema-evolution rules, use provider-neutral Geometry without a bundled
provider dependency, and understand exactly why XML, unreleased Variant mutation profiles, and unsafe join reordering
remain gated when they do. The result is visible in typed source APIs, generated PySpark, diagnostics, catalog rows, and
target evidence.

## Surprises & Discoveries

- Observation: `union_by_name(..., defaults=...)` was initially a deliberately rejected placeholder and is now
  implemented for batch nullable and explicitly defaulted top-level and nested-struct fields.
  Evidence: `src/structure/plugin/pyspark/dsl/relation_sets.py` validates canonical defaults and the V6 relation-union
  tests cover typed defaults, nested paths, and alias-preserving rendering.
- Observation: Sampling already has a public reproducibility policy and batch-only streaming classification.
  Evidence: `sample(..., seed=..., reproducible=...)` and its V9 specification tests.
- Observation: Geometry has provider-neutral DSL/runtime scaffolding, but the catalog and optional-provider evidence
  remain the governing closure surface.
  Evidence: `src/structure/plugin/pyspark/geo/` and `tests/specifications/v9-api-catalog/test_v9_geometry.py`.
- Observation: Spark nested defaults must be applied with `Column.withField(...)` using physical aliases rather than
  rebuilding a struct from logical names.
  Evidence: nested union rendering asserts `shipping_address` and `city_name` while authoring uses `address.city`.

## Decision Log

- Decision: Keep `union_by_name` as the single public entry point and make `defaults` an explicit mapping of canonical
  field paths to type-checked literals.
  Rationale: This extends the existing rejected interface without adding a second schema-evolution API.
  Date/Author: 2026-08-02 / Codex.
- Decision: Admit nested struct fields and aliases; reject implicit evolution inside arrays and maps until a separate
  contract exists.
  Rationale: Struct fields have stable names and schemas, while collection-element evolution changes cardinality and
  element semantics.
  Date/Author: 2026-08-02 / Codex.
- Decision: Preserve the caller-owned streaming boundary. Missing-column streaming union is promoted only after public
  Spark 3.5/4.0 evidence; otherwise it remains `streaming-ineligible` with a corrective diagnostic.
  Rationale: A skipped runtime lane is not evidence and schema evolution can change stateful query compatibility.
  Date/Author: 2026-08-02 / Codex.
- Decision: XML, unreleased Variant mutation profiles, and optimizer join reordering receive explicit dispositions but
  are not silently claimed as supported.
  Rationale: Their target, optimizer, or malformed-input contracts remain materially incomplete.
  Date/Author: 2026-08-02 / Codex.
- Decision: Permit an explicit default for a missing struct field, but keep array/map element evolution rejected.
  Rationale: A complete Structure instance has a typed, deterministic schema, while collection element evolution still
  lacks a safe cardinality and nullability contract.
  Date/Author: 2026-08-02 / Codex.

## Context and Orientation

Structure captures typed transform operations into an intermediate representation (IR), runs them online, and emits
generated PySpark. The API Catalog at `docs/APICatalog.md` is the public status ledger. Relation operations are defined
under `src/structure/plugin/pyspark/dsl/`; Geometry is split between provider-neutral DSL types and optional runtime
providers. Capability inventories under `src/structure/plugin/pyspark/resources/` and diagnostics are release artifacts,
not optional documentation.

The governing design documents are `docs/dev/design/ApiCatalogDesignGates.design.md`,
`docs/dev/design/TypedRelationOperations.design.md`, and `docs/dev/specifications/V9ApiCatalogDesignGatedFeatures.spec.md`.
Update matching `docs/background/*.back.md` companions where they exist.

## Plan of Work

First inventory the API Catalog and both machine-readable ledgers, distinguishing already implemented V9 behavior from
V10 candidates. Extend the existing `defaults` interface with canonical field-path validation, literal type checking,
nullable fallback behavior, alias preservation, and nested-struct rendering. Keep array/map evolution explicitly
rejected.

Next complete the Geometry contract: positive literal SRIDs, nullable WKT construction and serialization, compatible
SRID predicates, provider-neutral generated calls, and late provider availability diagnostics. Optional Sedona evidence
must live in a separate integration lane and must not add a bundled dependency or generated provider import.

Finally reconcile sampling, XML, Variant mutation, join reordering, and schema-evolution rows across public docs,
capabilities, diagnostics, traceability, examples, and tests. Join reordering may only be opt-in and explainable for
contiguous inner equality chains; uncertainty falls back to source order.

## Validation and Acceptance

Acceptance requires typed defaults for nullable and explicitly defaulted nested struct fields; preserved logical field
aliases; deterministic generated `unionByName` calls; clear rejection for arrays, maps, non-literal defaults, and
non-nullable missing fields without defaults; and explicit streaming classification.

Geometry acceptance requires symbolic SRID checks, provider-neutral generated code, unavailable-provider diagnostics,
and live optional-provider evidence where available. Sampling acceptance preserves literal validation, reproducibility,
no-order/no-count guarantees, and batch-only streaming behavior. Every APICatalog row touched by this plan must link to
its evidence or rationale.

## Idempotence and Recovery

The work is additive and rerunnable. If target evidence is unavailable, retain the last honest status and record the
missing lane. If a schema-evolution prototype changes nullability or alias behavior, preserve the smallest failing
fixture and update the decision log before changing the public contract.

## Artifacts and Notes

Expected artifacts are source-level tests, generated PySpark snapshots, capability-ledger entries, diagnostic anchors,
APICatalog/reference updates, optional-provider integration logs, and the final V10 reconciliation report.

## Interfaces and Dependencies

Use the existing `union_by_name(relation, allow_missing_columns=False, defaults=None)` interface, Structure Schema field
identity and aliases, `Geometry`/`GeoProvider`, backend capability checks, shared online/generated PySpark recipes, and
the existing diagnostic registry. Use public PySpark APIs only. Sedona remains optional and late-bound.
