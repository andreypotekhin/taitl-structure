## Purpose / Big Picture

Schema authors can state the Python shape of a field directly and omit a
redundant PySpark factory. For example, `name: str` means the same thing as
`name = string()`, while `price: Decimal = decimal(12, 2, nullable=False)`
retains the Spark-specific decimal details. The selected plugin validates the
hint and materializes the same PySpark schema used by existing declarations.

## Surprises & Discoveries

- Observation: `Schema.__init_subclass__` currently recognizes only assigned `FieldDeclaration` values.
  Evidence: it iterates `cls.__dict__.items()` and ignores `__annotations__`.
- Observation: the plugin architecture forbids Core from importing PySpark type definitions.
  Evidence: concrete PySpark types and schema validation live under `structure.plugin.pyspark`, while Core stores opaque field types.
- Observation: an annotated factory assignment is valid Python but not expressible as an ordinary mypy assignment.
  Evidence: mypy reports an incompatible assignment from a descriptor-like object to `str`; public factory typing must deliberately accommodate declaration context.

## Decision Log

- Decision: Infer `str`, `bool`, `int`, `float`, `date`, `datetime`, parameterized `list`, parameterized `dict`, and Schema subclasses; require a factory for decimals.
  Rationale: native hints cover ordinary PySpark migrations, but decimal precision/scale cannot be inferred safely.
  Date/Author: 2026-07-21 / project owner and Codex.
- Decision: `float` denotes Spark `double`; `decimal.Decimal` is mandatory for `decimal(...)` and `float = decimal(...)` is invalid.
  Rationale: Spark DecimalType values are exact decimal values, not binary floats.
  Date/Author: 2026-07-21 / project owner and Codex.
- Decision: Hints do not encode nullability.
  Rationale: existing factory defaults and `nullable=` remain the single nullability contract; optional unions are not schema hints.
  Date/Author: 2026-07-21 / project owner and Codex.
- Decision: An annotated ordinary assignment remains a class attribute; only an unassigned annotation or `FieldDeclaration` assignment declares a field.
  Rationale: this retains flexible schema-local constants without adding field defaults.
  Date/Author: 2026-07-21 / project owner and Codex.

## Context and Orientation

`src/structure/core/dsl/model/schemas/Schema.py` owns class-body field capture,
inheritance, and field ordering. `FieldDefinition` is the target-neutral record
consumed by schema fields and compiler structure. The selected plugin validates
schema classes before a transform invokes user code. PySpark's
`ValidatePySparkSchemas` owns the concrete type model and must therefore map
Python hints to PySpark types and validate compatibility.

## Interfaces and Dependencies

The accepted declaration grammar becomes:

    field := NAME ':' hint | NAME ':' hint '=' field_factory | NAME '=' field_factory

Bare hints infer the corresponding default PySpark type with existing nullable
and collection-null defaults. `Decimal` always needs `decimal(precision,
scale)`. An explicit factory permits aliases, metadata, descriptions,
nullability, decimal precision/scale, and collection nullability. `Optional`,
unions, unparameterized collections, and unsupported hint objects fail with a
hint-specific diagnostic.

Compatibility is structural: `int` accepts integer or long; `float` accepts
float or double; `Decimal` accepts decimal only; scalar, collection, and struct
hints otherwise match their exact PySpark type shape. Hints never override
factory nullability.

## Plan of Work

Extend `FieldDefinition` and `FieldDeclaration` to preserve a resolved Python
hint without making Core understand a plugin's concrete types. In `Schema`,
evaluate local annotations, convert unassigned supported-looking annotations
into an unresolved field definition, and attach an annotation to assigned field
factories. Preserve unannotated factory declarations, inheritance order, and
ordinary annotated class assignments.

In the PySpark schema validator, resolve annotations to PySpark types before
the current alias and recursive-type checks. A factory-bearing schema resolves
during its current class validation; a bare-only schema resolves when its
selected schema service validates it before compilation, materialization, or
source generation. Cache resolved definitions per schema and selected plugin so
Core remains target-neutral. Reject incompatible annotations with the schema,
field, hint, factory type, and a remediation.

Expose annotation-friendly return types for public field factories so mypy
accepts annotated declaration assignments without a user-installed plugin;
runtime returns remain immutable `FieldDeclaration` values. Add a type-check
fixture to the existing `make type` roots.

Update the schema syntax and reference documentation and add concise examples
that show bare fields, decimal decoration, explicit nullable/collection detail,
and the fact that `T | None` does not control nullability.

## Validation and Acceptance

`name: str`, `items: list[str]`, and `address: Address` produce the same
PySpark field types and defaults as explicit factories. `price: Decimal =
decimal(12, 2)` succeeds, while bare `Decimal`, `price: float = decimal(12,
2)`, `str | None`, and recursively incompatible collections fail before a
schema is used. Existing factory-only schemas remain unchanged. A fixture with
`name: str = string()` passes mypy, and `make build` passes.

## Idempotence and Recovery

working-tree edits. If a validator refactor exposes a legacy schema whose
annotation is not a field, treat ordinary assigned values as constants rather
than reinterpret them as defaults.
