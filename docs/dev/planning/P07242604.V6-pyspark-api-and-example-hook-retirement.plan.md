# Deliver a focused v6 PySpark DSL and retire the example hooks it makes obsolete

This ExecPlan is a living document. Maintain it according to `docs/dev/auto/Plans.md`. Keep `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` accurate whenever work stops or a design fact changes.

## Purpose / Big Picture

v6 makes Structure's PySpark authoring surface more useful than its raw-hook escape hatch for the example applications that ship with the project. A developer will be able to express the Security inventory predicates, normalized BM25 windows, typed row expansion, global summaries, sorted token collections, and relation composition as ordinary schema-returning step methods whenever their semantics are admitted. Those steps remain visible to compilation, generated PySpark, online execution, diagnostics, explain, traceability, and compatibility checks.

The release also makes the PySpark plugin easier to change safely. The largest modules are decomposed into narrow delegates before new semantics are added, so a feature affects one operation family rather than a dispatcher that also owns unrelated rendering or execution. The final observable evidence is that the current Security hooks are removed; selected Search hooks are removed in bounded slices; the remaining hooks have an explicit, tested reason and a scheduled capability rather than an implicit DSL gap.

This plan deliberately does not promise to replace the matrix-inversion hook. It collects data on the driver and runs a Python numerical algorithm, which is a real, intentional raw boundary rather than a missing Spark DataFrame transformation.

## Context and Orientation

Structure transform methods return declared `Schema` instances. The PySpark plugin symbolically captures those methods, lowers the result into immutable `PySpark*Recipe` values, executes the recipes online, and renders equivalent generated PySpark. A raw hook receives live DataFrames and is opaque to the compiler. It is legitimate only when the typed DSL has no sufficiently precise contract; it loses field-level visibility and should not become a convenience API.

The PySpark public import is `structure.plugin.pyspark`. Its current helper façade is `src/structure/plugin/pyspark/dsl/operations_api.py`; symbolic values and field access are in `dsl/Expression.py`, `dsl/expressions.py`, `dsl/InputScope.py`, and `dsl/RowScope.py`. Step-body capture and validation live under `symbolic_execution/`. The compiler maps those bodies through `compiler/logic/maps/` into recipes. `execution/logic/running/RunOnlinePySparkTransform.py` interprets recipes, while `render/logic/` produces generated source. Every admitted operation must preserve that shared path.

A relation operation changes the set, order, or cardinality of rows, unlike a scalar expression that evaluates inside an existing row. Relation operations must therefore declare which input relation they consume, the result schema(s), duplicate behavior, ordering guarantees, streaming classification, and traceability sources. A generator is a relation operation that expands one input row into zero or more output rows. A global aggregate is an aggregate without grouping keys; unlike ordinary grouped output, it must specify whether an empty input produces exactly one row or zero rows.

The authoritative v4 catalog is
`src/structure/plugin/pyspark/resources/pyspark-transformation-coverage.json`; it is the starting ledger for v6, not a
promise to clone every PySpark method. `docs/dev/design/Challenges.md` records the project-level design risks. The
user-facing examples are the acceptance clients: Security in `examples/security/transforms/`, Search in
`examples/search/transforms/`, and the deliberately raw numerical example in `examples/school/transforms/matrices.py`.

## API Ledger and Priority

### P0: implement first

1. **Lambda-bound struct fields.** Allow a symbolic lambda parameter to expose typed struct fields through normal attribute and `get_field(...)` access. It must lower `arr_exists(candidate.device_apps, lambda app: app.id == candidate.software_id)` to Spark's `exists` without a raw hook. This retires `retain_reconciled_inventory` and `reconcile_device_inventory`, removes the temporary `device_has_software` and `is_reconciled` placeholder assignments, and adds online/generated/live parity tests.

2. **Partitioned analytic maximum.** Add `window_max(value, over=...)` for an explicit `WindowSpec`, including the existing order/frame typing and nullability rules. The first client is normalized BM25; the feature must not invent implicit partitions or raw `WindowSpec` escape hatches. Add a test with multiple query partitions to prove maxima do not leak across queries.

3. **Ordered aggregate collection and exact-one validation.** Add `collect_list(value, order_by=...)` with a deterministic, explicitly ordered collection contract, plus `exactly_one(...)` as a relation/aggregate validation operation that fails with a diagnostic when a declared group has zero or multiple values. These enable the reusable-token portion of `CreateSimilarityQueries`; do not use Spark's unordered `collect_list` as an apparent deterministic result.

4. **Implicit global aggregates.** Preserve aggregate output construction without any preceding `group_by(...)` call. Formalize it as the existing no-key aggregate shape rather than requiring a new `group_all()` helper. Specify its empty-input policy: it yields one row when every output is a valid Spark aggregate result and rejects required non-aggregate projections. This behavior is necessary for the `Index` summaries and must have online/generated evidence.

5. **Opt-in scalar Python UDF examples.** Keep the existing `@special(type="udf")` contract supported for ordinary PySpark as an explicit, typed, warning-governed escape hatch; it is not a fallback for missing symbolic expressions and remains excluded from Spark Connect. Add a small shipped example and documentation that declare return type and nullability, show the `warn_on_udfs` behavior, and contrast an appropriate UDF with a symbolic helper and a raw hook.

P0 excludes binary encoding, JSON/CSV parsing, `mode`, raw `Column.alias`, and raw `WindowSpec`; their existing deferral reasons remain valid unless this plan explicitly changes the ledger.

### P1: relation operations that retire Search hooks

1. **Typed generators.** Add `explode`, `explode_outer`, `posexplode`, `posexplode_outer`, `inline`, and `inline_outer` only through a schema-returning relation operation. The contract names the driving expression, output schema, ordinal field where relevant, null/empty behavior, and row-expanding cardinality. Start with `posexplode` on `array<struct>` because it unblocks token and hierarchy expansion; admit the other five only when tests prove their distinct semantics.

2. **Typed set composition.** Add `union_all` and `union_by_name` first, with exact schema compatibility and explicit missing-column policy. Add `intersect`, `intersect_all`, `subtract`, and `except_all`, ensuring their duplicate semantics are separately tested. Do not overload joins to achieve union behavior. This is needed for the canonical/reversed similarity construction.

3. **Self-alias relation joins.** Add a named relation alias operation that creates independent, typed left/right scopes for the same declared schema. Require explicit output projection and preserve existing join cardinality rules. This, together with union and ranked selection, enables `ReduceSimilarityScores` without raw DataFrame aliases.

4. **Relation ordering and bounded selection.** Add `order_by`, `limit`, and `offset` as relation operations. `order_by` requires one or more typed order descriptors; `limit` and `offset` require non-negative integer literals. Ordering is observable only at the materialized output boundary; downstream relational operators may not claim it remains stable unless their own contract preserves it. Defer `sample` until its seed, replacement, and reproducibility contract is designed.

5. **Relation assertions and bounded hierarchy expansion.** Add compiler-visible `require_unique(...)`, `require_all(...)`, and `require_reference(...)` relation assertions plus a bounded parent-hierarchy operation. `require_reference` validates nullable `parent_band_id` values against the declared band-id relation without collecting the catalog. The hierarchy requires literal `max_depth`, explicit id/parent/ordering fields, and `ERROR` policies for missing parents and cycles; it lowers as a finite sequence of public self joins, never a driver `collect()` or a Python UDF. It exposes typed closure/path rows and a `hierarchy_fallbacks(...)` expansion that produces every deterministic parent-substitution fallback plus the terminal global fallback. Validate band identifiers, age ranges, parent references, and child-priority ordering before expansion. Existing self aliases and anti-existence selection express leaf-band membership; they need no raw DataFrame escape.

6. **Context fan-out and priority selection.** Generalize `union_all` into a branchable relation flow so a typed global branch and a typed fallback-context branch can rejoin one declared output lane. Add a ranked first-qualified relation selection operation: the author supplies a stable declared row key, candidate relation, eligibility predicate, and explicit priority order; the operation selects at most one eligible candidate per key or reports the configured missing/tie policy. This replaces `monotonically_increasing_id()` and raw `row_number()` selection in `RerankDocuments`, and lets `BuildRelevanceSignals` expand global/scoped facts without raw DataFrames.

P1 clients are implemented in this order: `ExtractText` only after the generator contract; `ScoreOverlap` and `ScoreBm25` after typed row expansion and aggregate expression coverage; `Index` after global aggregate; `CreateSimilarityQueries` after ordered collection/exact-one; `ReduceSimilarityScores` after alias plus union; `BuildRelevanceSignals` after branch/union; `RerankDocuments` after declared-key priority selection; and `ResolveCohortBands` after relation assertions, bounded hierarchy, and hierarchy-fallback expansion. ### P2: deliberately deferred or separately designed

- Binary functions require a public binary field type and a type-coercion/rasterization policy.
- JSON/CSV functions require inline schema transport and normalized options in recipes and source rendering.
- Deterministic `mode` cannot be honestly supported across the PySpark 3.5 baseline until a tie policy is expressible; retain raw hooks.
- `sample`, repartition, coalesce, checkpoint, and broader physical directives require a performance/physical-plan specification.
- Bounded ordered recurrence is owned by `P07182601.V6-timeline-scan-recurrence.plan.md`; it is not a substitute for general generators or global aggregates.
- Matrix inversion, Spark actions, arbitrary Python, RDD/Pandas APIs, Python UDTF/UDT registration, sources, sinks, and streaming query lifecycle remain raw/caller-owned boundaries. Explicit scalar `@special(type="udf")` remains supported as described in P0, never as automatic lowering.

## Validation and Acceptance

Acceptance is behavioral.

- Security: a device app struct whose `id` equals the vulnerability software ID passes reconciliation; a different ID fails; an OS-ID match also passes. Both online and generated transforms return the same declared rows, generated source contains `F.exists`/the public equivalent, and explain/traceability reports no raw boundary for either migrated method.
- Analytic maximum: two query partitions with different maxima receive their own maximum; an aggregate-only output method without a preceding `group_by(...)` retains global aggregation and follows the documented empty-input policy; invalid missing order/partition contracts fail before Spark execution with documented diagnostics.
- Ordered collection/exact-one: repeated runs over intentionally shuffled input produce the specified ordered token array; zero or multiple values in an exact-one group fail with the registered code.
- Generators: one input row with a three-element array produces three declared output rows with ordinal values 0, 1, and 2; empty/null cases match the documented inner/outer semantics; online and generated schemas and rows agree.
- Relation composition: union/set duplicates and alias self-joins follow their documented cardinality; unaligned schemas, unnamed aliases, and unsupported duplicate policies fail before rendering.
- Relevance context: one scoped fact expands once per non-global fallback and one global fact remains single; the typed branch/union plan matches the current raw hook for impressions and clicks.
- Priority selection: tied or missing declared row keys, ambiguous qualifying fallback candidates, and missing priority order fail with diagnostics. `RerankDocuments` chooses the same exact, parent, then global score as its raw plan without `monotonically_increasing_id()`.
- Band hierarchy: duplicate identifiers, invalid age ranges, missing parent references, non-increasing child priority, cycles, and a hierarchy longer than `max_depth` fail without driver collection. A valid catalog yields the same `BandMembership` rows (including ancestor and resolved-user-band rows) and ordered `BandFallback` rows as `ResolveCohortBands.resolve_bands`; each fallback chain ends with its null global fallback.
- Hook inventory: all example raw hooks have a ledger entry. Security and Search have no active raw hooks; School
  matrix inversion is explicitly intentional.
- Opt-in UDF: the shipped example declares a return type and nullability, compiles/renders/runs on ordinary PySpark with the documented warning policy, and remains rejected for Spark Connect. It never becomes an implicit fallback for unsupported source.
- Architecture: public imports retain their existing meanings, generated snapshots remain deterministic, the AST app-boundary suite passes, and no PySpark plugin module imports a private Core implementation.
- Release: `make build` passes. The plan includes exact outcomes from every supported live PySpark target; skipped or failed lanes are clearly separated from passing evidence.
