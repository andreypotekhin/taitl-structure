# V4 Caller-Owned Streaming Migration

This ExecPlan is a living document. Maintain it according to `docs/dev/auto/Plans.md`; its `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` sections must reflect actual work.

## Purpose / Big Picture

After this work, a developer can replace the transformation portion of a plain PySpark Structured Streaming pipeline with a typed Structure transform while retaining ownership of source, sink, checkpoint, trigger, output-mode application, and query lifecycle. The supported migration shapes are static-gap session aggregation, bounded stream-stream left/right/full outer joins, bounded stream-stream left-semi joins, and stream-static semi filtering.

The observable result is a caller-created streaming DataFrame passed to `StructureSession` or a generated class and a streaming DataFrame returned. The caller can then apply `writeStream.outputMode("append")` and start the query. No Structure API creates or manages the query.

## Surprises & Discoveries

- Observation: Existing `window(...)`, `watermark(...)`, `event_time_between(...)`, `rowset_join(...)`, and `exists(...)` already provide most of the required public vocabulary.
  Evidence: `src/structure/app/dsl/model/transforms/operations.py` defines event-time `window(...)`; the streaming specifications define watermarks, bounded inner stream-stream joins, and caller-owned lifecycle.
- Observation: `exists(...)` previously rejected an `event_time_between(...)` conjunct before streaming classification.
  Evidence: the general equality-only join validator rejected the semi-join predicate; V4 now admits that explicit bound for `exists(...)` while preserving ordinary equality-key validation.

## Decision Log

- Decision: Keep streaming lifecycle ownership with the caller.
  Rationale: Source, sink, checkpoint, trigger, output-mode application, deployment, and recovery are operational policy rather than a symbolic DataFrame transformation.
  Date/Author: 2026-07-15 / project owner and Codex.
- Decision: Require static positive session gaps and watermarks on both stream-stream inputs in v4.
  Rationale: This gives one cross-target, compiler-checkable contract; dynamic gaps and weaker watermark variants can be reconsidered only after live evidence establishes their semantics.
  Date/Author: 2026-07-15 / project owner and Codex.
- Decision: Report only `append` for a session-window aggregate, while retaining existing append/update reporting for ordinary watermarked windows.
  Rationale: the V4 contract needs a conservative, caller-visible output-mode requirement without changing the established V3 window contract.
  Date/Author: 2026-07-17 / Codex.

## Context and Orientation

Structure compiles typed schema-returning transform methods into a data-only intermediate representation and then into shared PySpark recipes. `StructureSession` interprets recipes in online mode; generated classes render and run the same recipes. The streaming compatibility pass classifies each operation as compatible, batch-only, or unknown before runtime. A watermark is DataFrame metadata that bounds state and late-data handling; it is not lifecycle ownership.

Relevant public forms live in `src/structure/app/dsl/model/transforms/operations.py` and are re-exported from `src/structure/__init__.py`. Streaming checking starts in `src/structure/app/compiler/compileability/streaming_compatibility/commands/ClassifyStreamingCompatibility.py`. `OperationPlan`, `JoinPlan`, the shared PySpark recipe model, the online runner, and the generated renderer must agree on every new fact. Documentation contracts are `docs/dev/specifications/StreamingCompatibility.md`, `docs/dev/specifications/V4CallerOwnedStreamingMigration.md`, and `docs/api/Streaming.api.md`.

## Plan of Work

It accepts a typed timestamp and a positive fixed interval string, returns `Struct[TimeWindow]`, and records a distinct expression kind with its static gap. Re-export it from public DSL modules. Extend expression mapping and rendering to call PySpark's `functions.session_window`; retain the analytical `window(partition_by=..., order_by=...)` behavior unchanged.

Extend aggregate planning and the compatibility classifier to recognize a session grouping key. On a streaming current frame, require a prior watermark on its event-time expression, one additional group key, and `append` as the only reported output mode. Emit a `STREAM-E0801` finding with a precise operation name and remedy for every violated rule. Batch session aggregation must retain normal batch behavior.

Extend join compatibility without creating new public join functions. For a stream-static `exists(...)`, classify the normal left-semi relation as compatible and require that the consulted input is static. For stream-stream `rowset_join` with `Join.LEFT`, `Join.RIGHT`, or `Join.FULL`, and stream-stream `exists(...)`, require both declarations to be `StreamingMode.YES`, watermarks on both event-time inputs, and an `event_time_between(...)` conjunct. ## Validation and Acceptance

Acceptance is met when a caller can pass a streaming DataFrame to a transform using each admitted form and both online and generated execution return a streaming DataFrame accepted by a short, bounded test query. A session aggregate requires `append`; each bounded outer/semi stream-stream join exposes its watermarks and time bound in explain output; and stream-static `exists(...)` has no state or output-mode requirement.

Tests must fail before implementation for dynamic/non-positive session gaps, global session grouping, absent or mismatched watermarks, missing streaming input declarations, missing time bounds, non-append outer/semi modes, stream-static right/full/cross/anti shapes, and a chained stateful plan. Generated source must contain none of `readStream`, `writeStream`, `start`, `awaitTermination`, `foreach`, `foreachBatch`, `collect`, `count`, `toPandas`, or `.rdd` in a compatible transform body.

## Idempotence and Recovery

Compiler, fake-recipe, and documentation tests are safe to rerun. Each live test uses a unique temporary checkpoint and stops its own query in `finally`; it deletes only paths it created. If a supported PySpark line rejects a claimed shape, retain the documentation as `planned`, restore its batch-only classification, record the evidence here, and do not add a target-specific silent fallback.
