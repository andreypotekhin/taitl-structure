## Purpose / Big Picture

After this plan is complete, Structure users can express common array and map operations that remain planned in
`docs/dev/Gaps.md`: collection size and membership, array construction and concatenation, map lookup, and map
concatenation. These helpers keep nested-data transforms Spark-plan-visible and typed, avoiding hooks for ordinary
array and map manipulation.

Users can see the result by compiling and running transforms that calculate collection sizes, test array membership,
build arrays from typed values, repeat and union arrays, look up map values with clear missing-key nullability, and
merge maps with deterministic duplicate-key behavior.

## Decision Log

- Decision: Implement non-row-expanding collection helpers before generator helpers such as `explode(...)`.
  Rationale: Row expansion changes transform cardinality and output construction rules. The planned v3 slice can close
  common nested-data parity without taking on generator semantics.
  Date/Author: 2026-07-07 / Codex.
- Decision: Keep arbitrary Python callback control flow unsupported.
  Rationale: Existing higher-order helpers require symbolic callbacks so Spark can optimize the plan. This plan does
  not change that boundary.
  Date/Author: 2026-07-07 / Codex.

## Context and Orientation

Structure supports typed array and map schema fields plus a first set of Spark higher-order helpers. Higher-order
helpers are functions that accept symbolic callbacks over array or map elements. This plan is about simpler collection
helpers and nested-data constructors, not arbitrary Python list or dictionary execution.

Relevant files and documents:

- `docs/dev/Gaps.md`: source gap list for this plan.
- `docs/reference/AdvancedAnalyticalOperations.md`: current public higher-order helper reference.
- `src/structure/app/dsl`: public array and map helpers.
- `src/structure/app/compiler/symbolic_execution`: callback and expression capture.
- `src/structure/app/compiler/ir`: collection expression records.
- `src/structure/app/target/pyspark`: shared collection helper lowering.
- `src/structure/app/compiler/traceability`: collection dependency reporting.

## Plan of Work

Milestone 1 implements collection size and membership. Add helpers for `size(...)` and `array_contains(...)` or the
project's chosen public names. Validate operand types, nullable elements, and Boolean result nullability. Render through
PySpark functions in online and generated execution.

Milestone 2 implements array construction and concatenation. Add typed `array(...)`, `array_repeat(...)`, and
`array_union(...)` helpers. Type unification must be explicit: compatible element types are admitted, incompatible
element types fail with diagnostics naming the conflicting operands. Array construction from zero operands should be
rejected unless the API requires an explicit element type.

Milestone 3 implements map lookup and concatenation. Add `element_at(...)` or a Structure-native name for map and array
lookup where it is clearer than indexing. Add `map_concat(...)`. Diagnostics must define missing-key behavior and
duplicate-key behavior; if Spark behavior is target-specific or configuration-sensitive, make that explicit through
capabilities or docs.

Milestone 4 updates explain, traceability, docs, compatibility tables, and generated examples. Explain output should
name helpers and operand fields compactly. Streaming compatibility should remain conservative for helpers whose Spark
streaming behavior is not proven by existing first-slice evidence.
