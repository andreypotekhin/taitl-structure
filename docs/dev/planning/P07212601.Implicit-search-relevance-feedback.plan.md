## Purpose / Big Picture

The Search example currently calculates lexical BM25 scores and presents sentence matches. After this work, an
application can continuously summarize clicks on document search results, correct their position bias with inverse
propensity scoring (IPS), and use that evidence to rerank the 100 best BM25 document candidates for any number of
queries in one invocation. A document with no click history still appears in lexical order, so feedback improves
results without creating a cold-start failure.

The observable workflow has three caller-owned stages. The caller writes the streaming daily click aggregate to durable
storage, periodically builds a batch relevance snapshot, then gives that snapshot and `AddScores.scored_documents` to
`SearchDocuments`. Structure owns neither stream lifecycle nor persistence. Its example supplies the typed schemas,
Spark transformations, deterministic scoring rule, generated artifacts, and tests.

## Surprises & Discoveries

- Observation: reusable document-level BM25 scores already exist.
  Evidence: `AddScores.scored_documents` carries `search_query_id`, `score_overlap`, and `score_bm25`, so the new
  document presentation boundary can reuse the lexical pipeline instead of creating a second index.

- Observation: an unbounded query-and-document aggregate is not streaming-compatible by itself.
  Evidence: `ClassifyStreamingCompatibility` requires a watermarked event-time grouping key for streaming grouped
  aggregates. Grouping daily facts by the watermarked impression display window bounds state and permits durable
  exposure and attributed-click outputs that share an exact key even across midnight.

- Observation: bounded inner stream-stream joins are available in the example/runtime contract.
  Evidence: `examples/streams/transforms/penalties.py` joins two watermarked streams with an
  `event_time_between(...)` bound. Click attribution can use the same supported shape with an impression ID and a
  24-hour click-after-display bound.

## Decision Log

- Decision: retain the existing sentence-result capability as `SearchSentences`; add a distinct `SearchDocuments`.
  Rationale: sentence and document results have different output shapes and ranking semantics. A rename makes the
  existing public behavior explicit without silently changing it.
  Date/Author: 2026-07-21 / user and Codex.

- Decision: both presentation transforms accept plural `queries: input(SearchQuery)` and partition every rank by query
  ID.
  Rationale: index scoring already supports multiple query rows. The presentation boundary must not impose the old
  one-query restriction.
  Date/Author: 2026-07-21 / user and Codex.

- Decision: add one `Impression` per displayed document and make `Click` reference its immutable impression ID.
  Rationale: impressions provide unclicked exposures and the exact query, document, position, and propensity that was
  shown. Click IDs permit watermark-bounded deduplication without guessing from timestamps or dwell time.
  Date/Author: 2026-07-21 / user and Codex.

- Decision: use a streaming daily aggregate and a caller-materialized batch snapshot.
  Rationale: it bounds Structured Streaming state while allowing an exact 30-day decay and whole-history snapshot to
  be recalculated deterministically outside the stream.
  Date/Author: 2026-07-21 / user and Codex.

- Decision: record `examination_propensity` on each impression and use it directly for IPS.
  Rationale: impressions alone provide CTR denominators but cannot identify position propensity. A value emitted by
  the serving policy or a randomized experiment makes the IPS correction auditable and avoids an arbitrary rank curve.
  Date/Author: 2026-07-21 / user and Codex.

- Decision: define CTR as binary clicked impressions, retain raw click count separately, and use a self-normalized
  propensity-corrected CTR estimate.
  Rationale: a single impression can legitimately have several engagement clicks, but it represents only one exposure
  in CTR. Applying the same logged propensity and age weight to clicked and shown impressions produces an auditable
  ratio bounded by zero and one.
  Date/Author: 2026-07-22 / user and Codex.

- Decision: blend normalized IPS dwell and IPS CTR at 70/30, with CTR held at zero below 20 impressions per grain.
  Rationale: dwell is usable immediately, while low-exposure CTR is too volatile to influence rank. Applying the
  threshold independently to query-document and global-document signals preserves their different evidence scales.
  Date/Author: 2026-07-22 / user and Codex.

- Decision: retrieve candidates solely by descending BM25, limited to 100 per query.
  Rationale: overlap remains useful in sentence/paragraph examples, but document retrieval starts with the requested
  BM25-only first stage. Overlap is not a candidate selector or final tie-breaker in this path.
  Date/Author: 2026-07-21 / user and Codex.

- Decision: express document candidate selection, limiting, feedback enrichment, and final ranking as separate
  Structure step methods; retain one raw in-place lane hook only for partitioned BM25 maximum normalization.
  Rationale: the visible stages document the two-stage search dataflow and produce traceability, while the current DSL
  has no partitioned analytic `max` expression. The raw hook is native Spark only and has one narrow responsibility.
  Date/Author: 2026-07-21 / user and Codex.

- Decision: factor document retrieval and reranking into `RetrieveDocuments` and `RerankDocuments`; expose their
  composed behavior through `SearchDocuments(RetrieveDocuments, RerankDocuments)`.
  Rationale: the source makes the BM25-first and feedback-reranking stages legible while the intermediate candidate
  lane remains internal, so callers do not pass a redundant candidate DataFrame.
  Date/Author: 2026-07-21 / user and Codex.

## Context and Orientation

`examples/search/schemas/search.py` currently defines `SearchQuery`, `SentenceSearchResult`, indexed-target schemas,
and lexical score schemas. `examples/search/transforms/score.py` enriches corpus `Document` rows with
one lexical score row per matching query. Move the current sentence-only `Search` transform into
`examples/search/transforms/searching/SearchSentences.py`; do not leave a deprecated `Search` alias, because this is
an example API correction rather than a compatibility layer.

Event contracts and streaming aggregation belong in `examples/search/schemas/clicks.py` and
`examples/search/transforms/clicks/`. Batch policies and signal construction belong in
`examples/search/schemas/relevance.py` and `examples/search/transforms/relevance/`; document and sentence presentation belong in
`examples/search/transforms/searching/`. Keep `Impressions`, `Clicks`, and `Signals` focused: the first creates
durable exposure facts, the second attributes click facts, and the third turns both into batch snapshot scores.
`SearchDocuments` only retrieves and reranks candidates. Shared query normalization must be extracted from the current
scoring algorithm into a small reusable Search-example helper if it cannot be invoked directly from all boundaries.

An `Impression` has a unique ID, display timestamp, raw query, document ID, one-based displayed position, and an
`examination_propensity` in `(0, 1]`. A `Click` has its own unique ID, occurrence timestamp, impression ID, and
nonnegative dwell seconds. A position is the rank displayed at impression time, not the reranked output's current
rank. The caller calculates and logs calibrated propensity; the transforms watermark-deduplicate both event IDs.

### Milestone 2: Define click and relevance contracts

Create `examples/search/schemas/clicks.py` for event and daily-fact schemas, and
`examples/search/schemas/relevance.py` for policy and signal schemas; export both through the Search example's schema

- `Impression`: `id`, `shown_at`, `query`, `document_id`, `position`, and `examination_propensity`; all are non-null.
- `Click`: `id`, `occurred_at`, `impression_id`, and `dwell_seconds`; all are non-null.
- `DailyImpressions`: a typed one-day `TimeWindow`, normalized query, document ID, position, recorded propensity, and

  `clicked_impression_count`, raw dwell seconds, capped dwell credit, and long clicks.
- `RelevancePolicy`: `evaluated_at`, `half_life_days`, `bm25_weight`, `feedback_weight`, dwell and CTR feedback
  weights, and the minimum CTR-impression threshold. Fixture defaults are `30`, `0.7`, `0.3`, `0.7`, `0.3`, and `20`.
  The click transform uses fixed example dwell constants of 60 seconds capped and 10 seconds for a long click.
- `QueryDocumentSignals` and `DocumentPopularity`: each exposes impressions, raw clicks, binary clicked impressions,
  raw and IPS CTR, IPS-weighted clicks and dwell credit, normalized dwell and CTR components, and a final normalized
  score in `[0, 1]`.
- `DocumentSearchResult`: `search_query_id`, `rank`, `candidate_rank`, document ID/title/URL, `score_bm25`,
  `score_feedback`, and `score_rank`.

Keep the candidate limit as `SearchDocuments.maximum_candidates: Final = 100`; it is deliberately not a policy field.
The result has no overlap score because overlap is excluded from this document search path.

### Milestone 3: Aggregate streaming impressions and attributed clicks

Create `examples/search/transforms/clicks/Impressions.py` with `@transform(streaming_compatible=True)` class
`Impressions`. It accepts streaming `Impression` rows, watermarks `shown_at` by seven days, deduplicates `id` within
that watermark, normalizes `query`, and groups by a one-day window, query, document, position, and recorded
propensity to emit `DailyImpressions`. This independent aggregate deliberately retains unclicked exposures.

Create `examples/search/transforms/clicks/Clicks.py` with streaming `impressions` and `clicks` inputs. Watermark
and deduplicate both IDs within seven days, then perform a bounded inner stream-stream join on `click.impression_id ==
impression.id` and `event_time_between(impression.shown_at, click.occurred_at, upper="24 hours")`. Group the attributed
rows by the displayed impression's one-day window and the daily-impression key. Calculate dwell credit before summing it as
`least(greatest(dwell_seconds, 0), 60) / 60`, and long clicks as dwell at least 10 seconds. Orphan, duplicate, and
late clicks produce no attributed daily fact.

Document caller-owned `update` sinks for both daily outputs, keyed by their complete daily keys. The seven-day
watermark may discard later events. The example does not start queries or choose checkpoint storage.

### Milestone 4: Build relevance snapshots and rerank documents

Create `examples/search/transforms/relevance/Signals.py` with batch-only `BuildRelevanceSignals`. It accepts persisted
`DailyImpressions`, `DailyClicks`, and the one-row `RelevancePolicy` and produces `QueryDocumentSignals` and
`DocumentPopularity`. Join daily facts on their full keys, treating missing clicks as zero. Calculate age from the
the end of its `TimeWindow` to `evaluated_at`, clamp negative age to zero, and apply
`2 ** (-age_days / half_life_days)`. Divide click
and dwell-credit evidence by the recorded `examination_propensity`, then multiply by the age weight. CTR has a binary
numerator: multiple clicks on one impression retain their raw engagement count but increment
`clicked_impression_count` only once. Calculate propensity-corrected CTR as the self-normalized ratio of weighted
clicked impressions to weighted impressions. Aggregate raw exposures, raw clicks, binary CTR, IPS CTR, IPS clicks, and
IPS dwell at query-document and document grains. Log-scale each IPS dwell total and divide by the maximum at its own
grain; an empty or zero maximum yields zero. The CTR component is zero below 20 impressions at each independent grain;
otherwise blend normalized dwell and IPS CTR as `0.7 * dwell + 0.3 * CTR`.

Create `examples/search/transforms/searching/SearchDocuments.py` with `SearchDocuments`. It accepts plural
`queries`, pre-scored documents, query-document signals, and document popularity. Match each `SearchQuery.content` to
the same normalized feedback query, then select at most 100 documents per `SearchQuery.id` using only descending
`score_bm25`, with document ID ascending as the deterministic equal-BM25 tie-breaker. This is candidate rank.

Left join feedback, treating missing values as zero. Calculate `score_feedback` as
`0.8 * query_document.normalized_score + 0.2 * document_popularity.normalized_score`. Normalize a candidate's BM25
by the largest BM25 in that query's 100 candidates. Calculate
`score_rank = policy.bm25_weight * normalized_bm25 + policy.feedback_weight * score_feedback`. The fixture policy is
0.7 and 0.3. Rank by descending `score_rank`, then document ID ascending; do not use overlap anywhere in this
transform. Emit ranks one through 100 per query.

## Validation and Acceptance

The completed feature must demonstrate all of the following:

- `SearchSentences` returns correct independent ranks for multiple query rows, while the old `Search` symbol is absent.
- A streamed impression produces exactly one daily exposure row for its complete key. A unique click produces at most
  one attributed row only when its matching impression occurred no more than 24 hours earlier; duplicate, orphan, and
  late clicks do not produce a row.
- An attributed click uses the propensity recorded on its matching impression, and a long dwell gets at most one
  capped dwell credit.
- Two click events on one impression retain `click_count = 2` but produce one clicked impression, so CTR cannot exceed
  one. An eligible click after midnight contributes to the displayed impression's daily window.
- IPS CTR is self-normalized by recorded propensity, and its 30% feedback component is zero below 20 impressions at
  each query-document and document grain.
- Unclicked impressions contribute to exposure counts and CTR denominators.
- Equivalent query text differing only in supported normalization joins the same feedback; a stale click is discounted
  by the 30-day half-life.
- A positive feedback signal can rerank two BM25 candidates inside the first 100. A candidate originally ranked 101
  never appears, and a no-history query retains BM25 order.
- Changing only document ID breaks equal final scores deterministically. No assertion relies on Spark's physical row
  order.
- Generated execution matches online execution for click aggregation, relevance snapshots, and multi-query document
  search; the golden generated project includes all new sources and reference pages.

## Artifacts and Notes

The rank calculation is intentionally transparent:

    aged_ips_dwell = sum(dwell_credit / examination_propensity * 2 ** (-age_days / half_life_days))
    ips_ctr = sum(clicked_impressions * age_weight / propensity)
              / sum(impressions * age_weight / propensity)
    signal = 0.7 * normalized_dwell + 0.3 * normalized_ctr  # CTR only at 20+ impressions
    feedback = 0.8 * query_document_score + 0.2 * document_popularity_score
    rank_score = 0.7 * normalized_bm25 + 0.3 * feedback

`normalized_bm25` is calculated only over the BM25 top 100 candidates for a query. IPS dwell is log-scaled and
normalized in the batch snapshot; IPS CTR is already bounded and is gated by exposure. Raw clicks remain an
engagement metric rather than CTR's numerator, preventing repeated clicks from mechanically inflating a probability.
The example does not infer non-click relevance or personalize by user. It consumes rather than learns propensity:
emitting a rank-only guess as the logged value would not make IPS calibrated.

## Interfaces and Dependencies

No third-party dependency is added. Use existing Structure/PySpark DSL facilities: `StreamingMode.YES`, `watermark`,
event-time `window`, `group_by`, aggregates, `row_number`, `inner_join`, `left_join`, `when`, `coalesce`, `least`,
`greatest`, `log`, `exp`/`pow`, and native Spark expressions only. Do not introduce Python, Pandas, or scalar UDFs;
they would make high-volume click metrics opaque to Spark's optimizer.

The public Search example API after implementation is:

    SearchSentences(queries=SearchQuery, scored_sentences=Sentence)
    Impressions(impressions=Impression streaming DataFrame) -> daily_impressions
    Clicks(impressions=Impression streaming DataFrame, clicks=Click streaming DataFrame) -> daily_clicks
    BuildRelevanceSignals(
        daily_impressions=DailyImpressions,
        daily_clicks=DailyClicks,
        policy=RelevancePolicy,
    )
        -> query_document_signals, document_popularity
    SearchDocuments(
        queries=SearchQuery,
        scored_documents=Document,
        query_document_signals=QueryDocumentSignals,
        document_popularity=DocumentPopularity,
        policy=RelevancePolicy,
    ) -> results
