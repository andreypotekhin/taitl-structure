# v3 Project Plan

## Goal

v3 closes the scheduled PySpark parity gaps and hardens admitted streaming transformations. It delivers a coherent,
compiler-visible PySpark surface while callers retain streaming source, sink, trigger, checkpoint, output-mode, and
query-lifecycle ownership.

## Release Principles

- Close only gaps marked `planned` unless the gap document and corresponding ExecPlan are revised first.
- Preserve Structure's contract: symbolic, typed, backend-capability checked, explainable, testable, and readable
  generated PySpark.
- Keep unsupported PySpark escape hatches unsupported: raw SQL strings, raw `WindowSpec`, arbitrary Python callbacks,
  UDF/UDTF helpers, and custom streaming side-effect sinks.
- Run every admitted feature through online/generated parity, backend capability checks, public docs, compatibility
  tables, and explain/traceability evidence.
- Keep compiler commands Spark-free.

## Release Milestones

### M8A: DSL and Function Gap Closure

Status: complete.

Users can express common scalar Column operations and SQL functions without hooks. Membership, range, string,
indexing, field helper, cast, ordering, string function, date/time, numeric, and predicate helper behavior is covered
by docs and tests.

### M8B: Join Gap Closure

Status: complete.

Users can use using-key joins, receive sharper right/full diagnostics, request explicit Cartesian joins safely, request
supported join strategies, and express forward as-of joins.

### M8C: Aggregation Gap Closure

Status: complete.

Users can express explicit grouping sets and post-aggregate `having(...)` predicates with typed aggregate-output
scope.

### M8D: Window Gap Closure

Status: complete.

Users can specify null ordering, use multiple order keys consistently, and calculate aggregate windows through admitted
aggregate helpers.

### M8E: Collection Helper Gap Closure

Status: complete.

Users can express collection size, array and map membership, array construction/repeat/union/except, element lookup,
safe element lookup, and map concatenation with typed nullability and deterministic diagnostics.

### M8F: Streaming Transformation Hardening

Status: complete.

Users can rely on explicit watermark, state, and output-mode guidance for admitted streaming transformations, while
callers retain source, sink, trigger, checkpoint, and query-lifecycle ownership.

## Exit Criteria

- Every completed v3 ExecPlan is archived with current `Progress`, `Decision Log`, `Surprises & Discoveries`, and
  `Outcomes & Retrospective` entries.
- `docs/dev/Gaps.md` marks implemented v3 planned gaps accurately or records explicit deferrals.
- Public compatibility tables and references describe the v3 support surface.
- Generated examples cover all admitted feature families.
- `make build` passes at the end of each sprint.
- Opt-in Spark integration lanes or release-blocking manual scripts prove target-specific behavior that cannot run in
  the default build.
- The v3 orders testing model demonstrates the completed release surface without requiring a live Spark runtime.

## Deferred Beyond Beginning v3

- Cost-based join reordering and nearest as-of joins.
- Row-expanding generator helpers such as `explode(...)`.
- Raw SQL string expressions, raw PySpark `WindowSpec`, and UDF/UDTF symbolic helpers.
- Arbitrary Python control flow in higher-order callbacks.
- Custom streaming side-effect sinks such as `foreachBatch`.
- Streaming source, sink, trigger, checkpoint, and query-lifecycle ownership.
- Incremental compile and cache diagnostics, which remain future work with no assigned version.
