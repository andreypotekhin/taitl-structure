# V10: API Catalog and Streaming Contract Expansion

V10 follows the V9 Sprints 45–48 design-gate closeout. It adopts the actionable core API and streaming slices from
`docs/dev/future/API.future.md` and `docs/dev/future/Streaming.future.md` while preserving Structure’s caller-owned
streaming lifecycle boundary.

## Goal

Make schema evolution, provider-neutral Geometry, streaming state composition, additional stream-stream join shapes,
and side-effect safety explicit, typed, testable, and honestly classified in the API Catalog.

## Scope

- Geometry, sampling, missing-column union defaults, nested struct evolution, aliases, and streaming schema-evolution
  rules.
- Explicit APICatalog dispositions for XML, Variant mutation profiles, and opt-in join reordering.
- Compiler-visible streaming state stages, bounded stream-stream join candidates, and finite selected-row alternatives.
- Caller-owned idempotence and recovery guidance for side effects and a typed arbitrary-state programming model.
- Capability ledgers, diagnostics, explain output, references, examples, generated-artifact freshness, and live evidence.
- Collision-safe generated identities across backend modules, schema symbols, schema documentation, plugin file maps,
  and generated-file writing boundaries.

## Non-Goals

V10 does not make Structure own `readStream`, `writeStream`, triggers, checkpoints, output modes, query names,
start/stop, deployment, recovery, `foreach`, `foreachBatch`, custom sinks, or external side effects. Search, Store,
Stocks, Streams, and School application futures remain outside this release.

## Exit Criteria

Every V10 row has a precise status, owner boundary, specification, diagnostic, test, and evidence path. Supported
streaming claims have PySpark 3.5/4.0 online/generated parity and restart evidence. Caller-owned recipes are executable;
generated transforms contain no lifecycle or side-effect calls; generated artifacts are fresh; and `make build` passes
in Sprint 54.
