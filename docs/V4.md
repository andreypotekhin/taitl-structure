# Version 4

Version 4 expands Structure's compiler-visible PySpark transformation coverage. Its purpose is simple: when a developer
knows a PySpark transformation API, Structure should offer a clear typed equivalent or an immediate, documented answer
about why that operation remains outside the DSL.

## What V4 Covers

- Column methods and SQL functions that can remain typed and symbolic.
- Nested struct, array, and map transformations with exact result types.
- DataFrame transformations, joins, aggregates, and windows whose schema and row-cardinality behavior is explicit.
- Caller-owned streaming transformations: watermarks, bounded dedupe, static-gap session aggregation, bounded
  stream-stream outer/semi joins, and stream-static semi filtering.

## What Stays Outside

V4 does not own data loading, storage or writes, table/catalog management, actions such as `collect()`, streaming
sources or sinks, triggers, checkpoints, output-mode application, or query lifecycle. Those are caller-owned PySpark concerns.
Raw SQL strings, raw Spark windows, UDTFs, and arbitrary callback bodies remain explicit hook boundaries rather than
compiler-visible Structure APIs. Scalar `@special(type="udf")` is supported as a row-local ordinary-PySpark batch and
streaming transformation, while Spark Connect remains excluded.

JSON/CSV parsing, row-expanding generators, set operations, and relation-level ordering remain deferred because their
schema, cardinality, or reproducibility contracts are not yet represented in the IR.

## Streaming Migration

Keep the normal Structured Streaming shell in application code and pass the caller-created DataFrames to Structure.
Structure returns a streaming DataFrame; it never starts or configures the query. Session aggregates and bounded
stream-stream outer/semi joins require `append` mode, watermarks, and an explicit `event_time_between(...)` bound where
applicable. See the [Streaming API](api/Streaming.api.md) and
[caller-owned migration guide](dev/design/SparkStreaming.md).

## Coverage Promise

The release creates a broad checked transformation coverage catalog for the supported PySpark 3.5.x and 4.0.x range. Each
relevant transformation API is marked supported, scheduled, deferred, or unsupported, with its Structure spelling, compatibility
profile, semantic differences, and evidence. This means an unimplemented PySpark transformation is visible rather than
surprising.

See the checked [API Coverage](APICatalog.md#api-coverage), the
[Streaming API](api/Streaming.api.md), and [API Gaps](dev/Gaps.md) for the current boundary.
